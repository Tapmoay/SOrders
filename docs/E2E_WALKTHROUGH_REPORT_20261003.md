## 一、结论摘要

用户要求的所有业务动作 **全部跑通**：建分类 → 建商品 → 定价 → 建货主账号 → 建司机账号 → 建车并绑司机 → 货主下单 → 派单 → 司机接单 → 司机拍照上传货物照片 → 填地点照片 → 送达 → 货主申请退货 → 派单员办理退货。

- 业务闭环、库存与账本的**落库**是正确的：派单自动出库 -3、退货自动回库 +3、账本一正一冲两行、送达照片真实落盘 66KB/68KB。
- 但**页面呈现层**存在 1 个高危缺陷与一批中低危缺陷，共 **32 条编号发现**（P14–P17、P21–P22、P24 为编号空缺，测试过程中未成条，不虚构）。
- 高危 3 条：P31（整单退货账本凭空亏损）、P1（停用账号手机号乱码，两页可见）、P7/P23（空表单提交零反馈，两处）。
- 另有 1 条**机制性**问题（Hint 说明系统首次登录后自动关闭），它直接造成了 P25 的误解。

## 三、问题清单（按严重度）

### 🔴 高

**P31 整单退货后，账本凭空出现亏损**
- 页面：账本管理 → 订单账（货主账、批发商账同样）
- 操作：完成一单 ¥85.5 的送达，然后整单退货
- 期望：+85.5 与 -85.5 两行相抵，合计 ¥0
- 实际：**只显示 -85.5 那一行**，「订单账合计（今天）¥-85.5 · 共 1 笔流水」。同一页切到「全部」也不出现 +85.5 那一行；而**部分退货**的单（订单 548，退 2 留 3）两行都在，合计正确。
- 根因（已定位）：backend/app/services/ledger_scope.py:58 的 visible_ledger_clause() —— source=ORDER 的自动行只在订单状态为「已送达」时可见；整单退货后订单变 RETURNED，原始行被过滤掉，但 RETURN 红冲行只要求「订单没进回收站」，于是红冲行留下、被冲的原行消失。
- 影响：对账时凭空多出一笔亏损；今天的营业口径跟着错。
- 证据：_tmp/L4.png、_tmp/w556_ledger3.png
- 修复方向：RETURN 行可见时，其配对的 ORDER 行必须同样可见（一句话原则：红冲要能看见被冲的那一笔）。

## 六、机制性发现：说明（Hint）系统让关键解释句凭空消失

- 新装默认**关闭**说明；首次登录那一轮显示，**下一次冷启动自动关掉**（core/HintRound.kt:33-61）。
- 开关在 我的 → 提示，措辞是否定式：「不显示说明」。三台设备实测都停在这一状态。
- 后果：App 里大量用来澄清口径的解释句**根本不渲染**。已实测确认的一条：ui/shipper/ShipperLedgerScreen.kt:470-475 那句区分「我该付的 / 我该收的」的话，滚动前后 dump 都没有 → 直接造成 P25。
- 建议：把「区分两个数」这类关键文案改成常驻正文；或把开关改成肯定式「显示说明」并默认打开。
