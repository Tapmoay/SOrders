# R4 Canary 观察窗口（**预注册**）

> ⛔ 这份文档是在**观察之前**写的。它只有一个作用：让「看多少算够、什么算通过」
>   在**看到数据之前**定下来。
>
> ⛔ 数字的**唯一来源**是 `_tools/ops/_canary_status.py` 文件头那几个常量，
>   本文只写**口径与理由**，⛔ 不抄数字 —— 抄了就会有两份真相，其中一份迟早过期。

## 为什么必须预注册（用户 §8 的原话）

> 「我建议第一轮不要直接拿"全生产订单数量"当观察窗口，而是做一个**明确的最小观察窗口**……」
> 「达到预先定义的最小样本量 → 检查」

道理和判据一样：**事后挑阈值 = 没有阈值**。
「Canary 很稳定」这句话在事后是永远说得出来的 —— 只要把「多少算稳定」往后挪一点。

## 观察对象

**发布之后新产生的**运费决策：`orders.freight_rule_snapshot` 里 `pricing.kind` 有值的单，
且快照的 `pricing.at` ≥ 发布日（跑的时候给 `--since <发布日>`）。

⛔ **不给 `--since` 跑出来的数字是历史累计**（工具自己会写明这一点），那种数字不许当窗口结论。

## 四分类（口径按 `pricing.reason` 判，⛔ 不是按人猜）

| 类 | 怎么认 | 含义 |
| --- | --- | --- |
| **contract** | `kind = freight_template` | 契约真的算出来了 |
| **fell_back** | `kind = legacy_client` 且 `reason` 不是 `ok`、也不是缺失 | 被 canary 抽中了，但契约算不出来，**如实退回** |
| **not_in_bucket** | `kind = legacy_client` 且 `reason = ok` | 这一单没被抽中（或者这次调用根本没有金额） |
| **stale** | `reason` 缺失 | R4-22 之前的旧式快照 |

⭐ 能这么分类，靠的是 R4-22 那条**原因码**。没有它，「退回」与「没抽中」就混在一起，
而那两件事的修法完全不同：一个是"去配置"，另一个"什么都不用做"。
另外三条（`no_match` / `ambiguous` / `error`）各自还带一句人话，⛔ 不需要去解析 note。

## 门槛（常量在脚本里，这里只列名字）

| 常量 | 管什么 |
| --- | --- |
| `WINDOW_MIN_IN_BUCKET` | 桶内决策（真的被抽中的）至少要多少笔 |
| `WINDOW_MIN_TOTAL` | 决策总数至少要多少笔 |
| `WINDOW_MAX_FALLBACK_RATIO` | 桶内退回比例的上限 |
| `WINDOW_FORBIDDEN_REASONS` | 观察期内**一个都不许出现**的原因码 |

五条判据（任一不满足 ⇒ 观察窗口 = **还没通过**，⛔ 不许「再看看」）：

1. **样本量够**（桶内 + 总数两条都够）；
2. **契约真的被用上了**（`contract ≥ 1`）—— ⛔ 这一条专门防「配着却一次没用上」那种假稳定；
3. **一个 `WINDOW_FORBIDDEN_REASONS` 里的原因码都不许有**（`error` / `ambiguous` 都有具体故障含义）；
4. **桶内退回比例不超上限**；
5. **观察期内不许新增无原因的旧式快照**（那等于退回没被记下来）。

## ⚠️ 一条必须知道的口径偏差（R4-26 撞出来的，不是 bug）

`price-freight`（**派单前**手动定价）会**提前把这一单的来源冻在 legacy** ——
那一刻**还没有司机**，契约看到的候选集是**全部价目**，多半算不出来。

⇒ **实际走契约的比例会低于配置的比例。**
看窗口时⛔ 不要拿「配了 30% 就该有 30% 走契约」当判据；
要按下面这个口径读：`contract / (contract + fell_back)` 才是"桶内真的走通了"的比例。

## 跑法

    python _tools/ops/_canary_status.py                    # 状态 + 历史累计四分类
    python _tools/ops/_canary_status.py --since <发布日>     # 观察窗口 + 五条判据
