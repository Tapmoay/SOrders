① 货主「下单」页与派单员「代理下单」页，什么都不填、直接点底部「提交订单 ¥0」时，屏幕上**没有任何变化** ——
不弹提示、不标红、不滚动、不跳页。E2E 报告里同一页连点两次/三次的截图**字节完全相同**

② 现在的样子：两个入口其实是**同一个页面** `ui/shipper/OrderCreateScreen.kt`（`proxyMode` 决定顶栏标题「代理下单」/「下单」），
只不过 `ui/nav/NavGraph.kt:177` 走 `Routes.ORDER_CREATE`（货主）、`ui/nav/NavGraph.kt:191` 走
`Routes.DISPATCH_ORDER_CREATE` 并带 `proxyMode = true`（派单员）。校验逻辑 `OrderCreateViewModel.kt::submit()` 一句话都不缺：
`lines.isEmpty()` / 商品名空 / 没有价格 / 电话位数 / 货主没选，都会写中文话术进 `vm.error`；
但界面上**唯一的渲染点是 LazyColumn 的最后一项**（原来在 `OrderCreateScreen.kt:645-649`）——
表单要往下滚过商品、地址、联系信息才看得到，底栏那个按钮点下去，视线里什么都没有。
③ 变化：只改「那句话画在哪」与「什么时候说」—— `vm.error` 从滚动区末尾搬到常驻底栏（提交按钮正上方）；
另外给代理下单补一道**同步**闸门：没选货主时点下去立刻说「请选择货主或填写临时货主姓名」，不用等一圈网络。
④ 不能变：校验规则本身（哪几件事必填、电话仍可选、单价仍然只有一个来源）；提交成功后的链路

⛔ 不许改成静默 disabled）；`submit()` 里既有的报价闸门与协程里那道货主闸门。
⑤ 结论：**Presentation** —— 只改「一段已经存在的文字画在哪个容器里」，外加一道 ViewModel 里闸门的同步性；
没有新事实、没有新契约、没有数据写入。
⑥ 证据：`_tools/qa/_check_order_submit_feedback.py` 静态判据 30 项全绿 + `_tools/qa/_reverse_verify_order_submit_feedback.py`
12 条注入全红 + `_check_all.py` 无新增红 + APK 重建通过 + 模拟器 5554 / 5556 两个入口各复验一次（同一屏看得见那行红字）。

## ④ Behavior Contract

```text
Input          货主「下单」页 / 派单员「代理下单」页，表单未填完时点底部「提交订单 ¥…」
Output         同一屏、提交按钮正上方出现一行红字（红色 ErrorOutline 图标 + 红字），说明缺什么；不滚动、不弹窗、不离开这一页
Success        用户在**视线所在的那一屏**就知道为什么提交不了：代理下单没选货主 →「请选择货主或填写临时货主姓名」（同步，立刻）；
               一组商品都没有 →「请至少添加一组商品」；有行没名字 →「商品名称不能为空」；
               某行没有价格 →「「<商品名>」没有价格（这件商品已不在商品库），先删掉这一行再提交」；电话位数不够 → `InputRules.phoneError` 那句中文

               不清空已填内容、不留在「提交中…」、不静默吞掉错误、不把话术塞回滚动区

               ② 电话留空 → 仍然允许提交（可选字段，不许借这次改动把它做成必填）
               ③ 抢在 init 的 sessionFlow.first() 之前点提交 → 同步闸看不见角色，由协程里那道兜底闸接住（两道闸都在）
               ④ 代理下单没有「商品明细」以外的必填项缺失时，仍然报最上面那条（与页面顺序一致：货主在最上面）
```

## ⑤ Data Contract

- **新增/改动哪些字段**：**无**。本事项零字段、零表结构、零迁移、零后端改动。
- **Owner 是谁**：屏幕上那句话的 Owner 是这一页的 ViewModel（`OrderCreateViewModel.error`，语义 = 设计规范里的 `formError`）；
  ⛔ 它**不**承担 `loadError`（页面加载失败仍由页面级 ErrorView 负责），这三格分工见规范 §4.8。
- **什么时候写 / 什么时候不写**：只在动作/校验失败时写（选品超上限、没坐标、地址空、保存地点失败、图片超 9 张、
  提交校验不过、货主没选、价格没拿到、接口异常）；成功提交时先清空再发请求（else 分支 `error = null`）。
- **是否允许 NULL**：允许 —— `null` 的语义是「现在没有话要说」，`FormErrorLine` 收到 null/空白就早返回、不占位。
- **历史数据怎么办**：**什么都不做**。本事项不写库、不读库。
- **迁移怎么做 / Rollback 怎么办**：**无迁移**。Rollback = 把底栏那份 `FormErrorLine` 删掉、把 `vm.error` 的渲染搬回滚动区末尾、
  撤掉同步闸门（协程里那道兜底闸本来就在）。
- **删除本功能后历史数据还能不能解释**：能 —— 订单内容、金额、账目全都不受影响，只是「点了没反应」会回来。

## ⑥ CHG 专章（FEAT / GOV 不适用时写「不适用：<理由>」）

本事项是 **BUG**（修复一条已声明的行为缺陷：「按钮点下去必须有反馈」），不是能力变更；
按规范仍写清 Before / After 对照（对应用户看得见的那一屏）。

### Before

在 5556（货主）打开「下单」页、或在 5554（派单员）「工作台 → 代理下单」打开同一页，什么都不填，
点底部那颗绿色「提交订单 ¥0」：屏幕**一个像素都不动**，连点三次还是不动 —— E2E 报告里两次截图字节完全相同
（183380 B / 179797 B）。校验其实一直在跑，`OrderCreateViewModel.submit()` 里 `lines.isEmpty() -> error = 「请至少添加一组商品」`
写得好好的，只是它画在 LazyColumn 的**最后一项**：表单有商品、地址、联系信息三卡，手机屏上根本滚不到那儿。
代理下单页更绕一层：没选货主时那句「请选择货主…」要等一圈网络（协程里查完 `sessionFlow.first()` 才判角色）。

### After

同一个动作：手指离开按钮的那一瞬间，**底栏**（合计与提交按钮所在的那一条）上方多出一行红字 ——
5554 代理下单页是「请选择货主或填写临时货主姓名」，5556 货主下单页是「请至少添加一组商品」；
不用滚、不用找，它就在你刚点的那颗按钮正上方。表单填全后这行字自己消失（不占位、底栏不跳）。
提交失败时同一位置显示后端那句话。按钮的可点性、颜色、文案一个字没变。

### Blast Radius（L0～L3）

**L1** —— 影响一个页面的**一屏**（底栏那一条）＋ 一个 ViewModel 方法里的校验顺序；不动数据、不动钱、不动权限、不动路由。
之所以不是 L0：这一页是两个入口共用的（货主下单 / 派单员代理下单），改底栏会同时改变两个角色的当面体验。
