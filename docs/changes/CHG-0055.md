① 改的是什么？
   a) 回补那条分支（socket `"sync"`）**补一声语音播报**：断线期间 / 还没登录那段时间被派的单，

## ③ Boundary

- **结论**：**CORE（回补路径的播报判定）＋ INFRASTRUCTURE（通知渠道 id 的一次性语义）**，Blast Radius **L1**
- 逐问依据：
  · **数据 Owner 变了吗**？没有。渠道只是「发送时用哪一条」，业务数据一个字没动；`rung_keys` 是**客户端本地**的一份记录（SharedPreferences 一个键），不是后端的字段。
  · **有没有新的写入**？有，但只在客户端本地：`AlertPrefs.rungKeys`，写入点两处（响过 / 作废），都是 `apply()`（异步）。不碰后端、不碰账本、不碰订单状态。
  · **算法动了吗**？既有判定一个没改；新增的 `ringbackOf` 是**新判定**（回补该不该响），放在纯函数里、有单测（9 个用例）。
  · **权限动了吗**？没有。`VIBRATE` 是安装期普通权限（`AndroidManifest.xml:16`，装上就有）；真正会拦住震动的是**渠道开关**与系统勿扰 —— 这也正是本刀要换渠道 id 的原因。
  · **状态机动了吗**？没有。接单 / 撤回仍然只由既有的 `shouldStop` 与 `forgetOnStop` 那条口径负责，本刀只是把同一口径**也落到盘上**。
- **核心改动声明**：这一刀只改「**什么时候响一声、用哪条渠道发**」，不改「谁能收到、什么时候发通知」。

## ④ Behavior Contract

- **Input**：回补整批 `notifications`（每项采信规则仍是 `PushTrust.acceptNotification`）→ 候选 `List<RingItem>`；角色 `role: Role?`（会话就绪时已赋值，早于 connect）；盘上那份 `AlertPrefs.rungKeys`。
- **Output**：`announce(...)` 至多被**多调用一次**（补响那一条）；两条新渠道开始被实际使用。
- **Success**：回补里存在「角色该听的那一类 ＋ 还没被接单 / 撤回 ＋ 没响过」的条目 → 补响其中**最新**的一条；随后它也被记进盘上的「已响过」。
- **Failure**：记录读不出来 / 写不进去 → **静默**（`runCatching`）—— 读失败最多多响一声、写失败最多下次重连多响一声；⛔ 绝不让它挡住播报或收单。回补里没有该补的 → 一声不响（正常）。
- **Boundary Cases**：
  · 一次回补 200 条 → 只补 1 条（`take`/`return item` 只返回一条），不会连响十几分钟；
  · 同一批里既有「新派单」又有「已接单 / 已撤回」→ 后者先把 orderId 记进 `stopped`，同单号的候选被跳过；
  · 货主登录 → `voiceKind(role)` 为 null → **一条都不补**（「来单了」对他是错的信息）；
  · 派单员 → 补的是 `PENDING_ORDER` 那一类；司机 → 补 `NEW_ORDER`；
  · 记录里的坏行（人手改过 / 版本回退写过）→ 丢弃该行，**不许抛**（少一条记录 = 最多多响一声）；
  · 超过 24 小时的记录 → 丢掉（昨天的单不该在今天重连时响）；条数超过 64 → 只留最新的；
  · 用户关掉 App 语音总开关 → 回补同样不响（`NewOrderPlayer.play` 自己看 `prefs.voiceEnabled`）；
  · 通知权限没开 → 系统通知发不出（既有语义），语音那一路不受影响。
- **Side Effects**：一次本地 `SharedPreferences` 读 ＋ 至多一次写（响过 / 作废各一次）；一次 `announce` 内部的播放与去重（既有）。没有网络请求、没有后台任务。
- **Authorization**：无变化（提醒是本地行为，仍按 `role` 分派语音那一类）。
- **Compatibility**：老版本写下的 `rung_keys`（本键**不存在**）→ 读作空串 → 空记录，行为等于「没响过」；两条旧渠道定义保留 ⇒ 老用户机器上旧渠道的历史设置不作废，新渠道是一次**新的**默认（震动开）。

## ⑤ Data Contract

- **改动哪些字段**：没有后端字段改动。新增一个**客户端本地键** `rung_keys`（`SharedPreferences`）。
- **字段 Owner**：客户端（`core/AlertPrefs.kt`）；格式由 `core/NewOrderAlert.kt` 的 `rungEncode` / `rungDecode` 独占解释。
- **什么时候写**：① 每响过一条（`announce` → `markRung`）；② 收到「该闭嘴了」的信号（撤回 / 接单 → `forgetRungOnStop`）。
- **格式**：`key@ts;key@ts;…` —— `key` 是既有的去重键（例如 `assigned:123`），`ts` 是毫秒时间戳；`rungEncode` 按时间**升序**写，`rungDecode` 读完顺手 `rungTrim`（窗口 24 小时、上限 64 条）。
- **是否允许 NULL**：允许（键不存在 / 空串 → 空记录）；坏行丢弃而不是抛。
- **历史数据**：无（新键）。旧版本升上来第一件事就是读不到 → 空记录。
- **迁移与 Rollback**：无迁移（后端零改动）。回滚 = 撤掉这一提交；盘上那份记录留着**无副作用**（没人再读它），界面与行为回到「回补不响」「旧渠道不震」。
- **删除后能否解释**：「响过没有」是**行为口径**，不是业务事实；删掉它只意味着「同一个司机在一次重连里可能多听一声」。
