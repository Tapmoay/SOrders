## ① 六问

① **解决什么问题？** 高德本区域的卫星影像**原生最高只到 z18**；放到最大（z19/z20）时高德返回
**「此区域无卫星图」的灰底占位图**。而「地图选点」恰恰要靠放大来确认「是不是这个门、这条巷子」，
放到最大反而什么都看不见 —— 这是本事项要解决的。

**实测**（`GET https://wprd01.is.autonavi.com/appmaptile?style=6&x=…&z=…`，2026-10-02）：

| 层级 | 返回 | 判定 |
| --- | --- | --- |
| z17 / z18 | JPEG，10,005 / 7,892 字节，灰度 std ≈ 15 | **真实影像** |
| z19 / z20 | PNG，**4,235 字节**，灰度 std **1.46** | **灰底占位** |

② **当前用户 / 业务流程是什么？** 货主 / 派单员在「下单 → 地图选点」或「地址与联系人 → 地图选点」
打开 `AmapPickerDialog`：默认卫星图（`AmapMapHolder.satellite = true`），拖动地图把中心图钉对到
自己门口，确认后回调 `(lat, lng, address)`。司机那一侧走「订单详情 → 导航」，调用方显式传
`startSatellite = false`，**起步就是标准图**。

③ **哪个现有事实或能力会发生变化？**「放大到 z19 / z20 时看到什么」会变：
从高德的灰底占位，变成自备的高清影像。⛔ 选点本身仍是**高德的 GCJ-02 坐标**，确认回调的
语义一个字不变，逆地理仍走高德 —— 变的只是「屏幕上那几张图从哪来」。

④ **哪些东西明确不能变化？** 见下面 ② 节的 Must Not Change。

⑤ **这个变化属于 Core、Extension 还是 Infrastructure？** **INFRASTRUCTURE**（展示层的基础设施）。

规范化五问（规范 §三）：

- ① 是否定义核心事实？**否** —— 它不定义任何业务事实，只决定画在地图上的像素。
- ② 是否改变核心不变量？**否** —— 不涉及钱 / 状态机 / 权限 / 审计 / 时区。
- ③ 是否必须永久存在？**否** —— 它是一个可替换的影像来源。
- ④ 是否可能出现多个实现？**是** —— 高德原生影像、自备瓦片、将来换第三方底图，都只是"一种实现"。
- ⑤ 删除后 Core 是否仍然成立？**是** —— 删掉它，地图退回高德自己的影像，业务一字不变。

⇒ 结论：**独立的基础设施层，不进 Core，也不新造 Extension Point**
（规范 §三「模糊时先不要抽象：先做一个真实实现，等第二个实现出现再判」）。

## ④ Behavior Contract

```text
Input          高德 SDK 逐格调用 getTile(x, y, zoom)
Output         Tile(256, 256, jpegBytes) 或 TileProvider.NO_TILE
Success        z<=18 -> NO_TILE（地图显示高德自己的影像）
               z==19 -> 取 z20 的 (2x,2y)(2x+1,2y)(2x,2y+1)(2x+1,2y+1) 四格合成 512x512 -> 缩到 256
               z>=20 -> 取 z20/zoom/x/y.jpg
Failure        ⛔ 任何一步失败一律返回 NO_TILE（地图透出高德底图），
               **绝不**合成半张灰图、绝不抛异常、绝不返回空 Tile
Boundary Cases · z19 的 4 个子格里只要有 1 格取不到 -> 整块放弃返回 NO_TILE
               · 瓦片不在覆盖范围内（HTTP 404）-> NO_TILE（这是正常情况，不是错误）
               · 磁盘缓存写失败（空间不足 / 无权限）-> 只用内存，下次重新下载，不报错
Authorization  无 —— 瓦片是公开静态资源，不加鉴权（与 /static/uploads/ 不同，那里是业务图片）
Side Effects   写磁盘缓存（externalCacheDir/tiles）；不发任何通知、不写库、不改任何业务状态
Compatibility  Compatible：纯新增图层（AmapPickerDialog 签名不变，三个调用点零改动）
```
