      而且是两个都会去写库的脚本给出的：seed_dev_users.py 写 pass12345，
      reset_dev_passwords.py（本机 2026-10-08 被就地改成硬编码 123321）写 123321。
      谁后跑谁的算 —— 下一次"登录不上、跑一下重置脚本"就会把库改回另一个口令，

② 现在的流程是什么？
   —— 新机器：`python scripts/seed_dev_users.py`（口令 pass12345）。
      登录不上：`cd backend; python scripts/reset_dev_passwords.py`（本机现在是 123321）。
      跑测试：`backend/tests/conftest.py` 自己造用户（pass12345）。
      本机开发库：2026-10-08 用户把三个测试号与王大力改成了 123321，并要我把脚本也改成 123321。

      缺省 pass12345"。**缺省值与 seed / conftest / README 一致**，本机要 123321 就显式给一个环境变量。
      ⛔ 不变的是：本机开发库里那四个号的口令仍然是我 2026-10-08 重置成的 123321（本轮不动库）。

④ Must Change / Must Not Change（见 ② 节）

   —— INFRASTRUCTURE（开发期的账号准备脚本）。

⑥ 什么证据能证明完成？
   —— 同一个脚本在两种环境变量下打印出两个口令；缺省值与 seed/conftest/README 逐字一致；
      `_check_secrets.py` / `_check_dev_spec.py` 全绿。
