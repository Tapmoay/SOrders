① **用户 2026-10-09 的截图**：助手把三个字段（收货人 / 电话 / 终点地址）写成三行「• 标签：值」，紧接着又用同一段文字追问「『城东水果批发』我没往这张卡里放 —— 它是这条线路的起点，还是写进备注？」。数据和要用户回答的问题糊在一起，得一行行读才知道哪句是信息、哪句是要他拿主意。用户口径（ref `m35395`）：「AI 的回答**最好都要用表格的样式**」「上面有文字下面有信息混在一起就很难分辨出来，他具体想表达的核心内容是什么」，而且**不要一个场景一条规则地加**（「不要就是他啊就是搞一个我们来搞一个搞一个我们来搞一个，这样子太麻烦了」），要**让 AI 自主判断**；「其实基本上只要涉及到信息的基本上他都要想啊想办法比如说像表格呀或者是其他的样式把信息给表达出来」。随后一句（ref `m35399`）：「所以说我们可以**内置对应的 skills 和工作流**」。

② 货主与派单员在「AI 助手」里读答复：字段明细、多条记录（商品 / 订单 / 司机 / 流水）、要用户拍板的问题，全都在同一条消息里。既有提示词（`ai/AiAnswerStyle.kt` 第 9 条 ＋ 结尾第 2 条）只写「条目**超过 3 项**才优先用表格或每项一行」—— 截图那条只有 3 个字段 ＋ 一句追问，正好落在规则之外，于是每次即兴发挥、同一问两次形状都不一样。

③ 助手气泡的**排版**（连续的「标签：值」散行 → 无表头两列小表）＋ system prompt 多一段（编号 **12** 的「形状 → 怎么排」技能表）＋ 渲染器多认一种表（**无表头**的表）。

④ 见 ② 节 Must Not Change：模型自己写好的 Markdown 表、上色那一套、确认卡信息区、用户自己发的消息、后端 / 端点 / 权限 / 数据库 / 历史数据。

⑤ **Presentation（呈现层）**：`ui/ai` 渲染层 ＋ `ai` 提示词文案。不新增字段、不写库、不碰权限 —— 所以它不该在代码边界以外解决：这是「同一份数据怎么摆给人看」的问题，摆法由内容形状决定，不由业务场景决定。

⑥ 判据 `_tools/qa/_check_ai_answer_style.py` 新增第 12 节（技能表拼进 system prompt / 兜底复用确认卡那一份判定 / 只吸文本与无序条目 / 值有上限 / 先补形状再上色 / 渲染器认得无表头）＋ 单测 `AiAnswerShapeTest`（10 条）与 `AiAnswerSkillsTest`（8 条）＋ 反向验证 `_tools/qa/_reverse_verify_ai_answer_style.py`（25 条注入，新增 ⑦ 条）＋ 真机同题截图。

## ③ Boundary（Core / Extension / Infrastructure / Presentation）

**结论：Presentation —— 只动「同一份数据怎么摆」，不动数据本身。**

- 为什么不是 Core：没有新的数据事实、没有新的权限判定、没有新的钱算法；回答里的数字还是那些数字。
- 为什么不是 Extension：不是「加一个能力」，是**换一种摆法**（而且优先级最高的那半在提示词里，代码只是兜底）。
- 为什么不是 Infrastructure：不碰网络、存储、构建产物。
- 为什么呈现要分两层：提示词让模型**认形状**（这是它可以自主判断的部分，用户明确要求「不要一个一个加规则」）；渲染层再兜一层，防模型漏排（模型是概率的，兜底要确定性）。
- 为什么兜底复用 `AiCardTable.asPair`：确认卡信息区早有一份「标签：值」判定（用户 2026-09-20 要求「卡片信息尽量都用表格」）；两处各写一份，迟早分叉 —— 判据第 12 节因此专门查「`shape` 里没有第二份冒号切分」。

## ④ Behavior Contract

```
Input      ：助手回答的纯文本（模型输出）＋ toned（是不是助手气泡）
Output     ：渲染块的形状（文本行 / 标题 / 无序 / 编号 / 表格）
Success    ：连续「标签：值」≥2 行 → 一张无表头两列表；模型自己写的表原样
Failure    ：单行、值带句读、值超 24 宽、标题行、编号行 → 原样不动（绝不硬凑）
Boundary   ：中间隔一句叙述 → 分成两张表；
             无表头的表 → 渲染器要画得出来（表头缺失不再整块不画）
Side Effect：无（纯函数；不写库、不发请求、不改全局状态）
Authorization：无（呈现层不看角色）
Compatibility：既有 `AiMarkdown.Block.Table` 的字段没变（`header` 允许为空）；
             既有带表头的表渲染路径不变（`hasHeader` 为真时与改前逐行一致）
```

## ⑥ CHG 专章

**Before**

- 提示词第 9 条只覆盖「条目**超过 3 项**」⇒ 3 个字段 ＋ 一句追问落在规则外，字段和问题糊在同一段（用户截图）。
- 就算模型排出了两列（`| 标签 | 值 |` 带表头也行，可它常写成无表头的裸行），渲染器 `MdTable` 开头是 `if (table.header.isEmpty()) return` —— **无表头的表整块不画**，等于白排。

**After**

- `ai/AiAnswerSkills.kt` 的编号 12 按**内容形状**给 6 条（不是按业务场景），并明确「≥2 行同类信息就该排开」「要用户回答的问题单独一行放最后」。
- `ai/AiAnswerShape.kt` 把漏排的「标签：值」散行补成无表头两列表（值必须短），渲染器跟着学会画无表头的表。

**Must Preserve**

- 上色口径（CHG-0060）、确认卡（AiCardTable 的既有行为）、用户气泡、既有提示词 1~11 条逐字。

**Blast Radius**：**L1 —— AI 回答的排版**。影响面：助手气泡的排版形状与 system prompt 一段文案；不动后端、不动数据、不动权限。
