## ③ Boundary（Core / Extension / Infrastructure / Presentation）

**结论：Extension —— 加的是「一个新工具 ＋ 一层编排」，把既有读能力按固定顺序串起来；不产生新事实、不改任何既有接口。**

- 为什么不是 Core：后端一行未改、没有任何数据模型 / 接口 / 权限判定变化；工作流读到的每一行都是既有读接口本来就能读的。
- 为什么不是 Extension 之外：这不是「同一份内容换一种摆法」（Presentation），也不是「改基础设施」（Infrastructure）—— 它实实在在**多了一条模型能做的事**（判据第 8 节钉着八处注册点，少一处就是「模型根本不知道有这个工具」）。
- 为什么编排必须在**代码**里而不是提示词里：计划文档 §15.6（`docs/AI_ASSISTANT_PLAN_V3.md:622-630`）早就定了 —— 工作流是 agent 循环**之上的一层**。理由很具体：对账要两张表按**同一个窗口**各查一次再对差集，步骤落在提示词里 ＝ 每轮重发一遍、每次还可能漏一步或换个窗口，而**窗口一错，结论就是「这个月少记了三万块」这种看着最像真的假账**。
- 为什么两条都只给派单员：它们要交棒的写动作（`ledger.sync_delivered` / `price_rules.batch`）本身就不在货主的动作清单里 ⇒ `forRole` 认不出角色时**一条都不给**（与工具白名单同一条 fail-closed）。
- 为什么工具说明**从登记表拼**而不是手写：手写的清单在加工作流时一定会漏（设置页那句「可申请：…」就踩过这个坑），症状是「模型根本不知道有这条工作流」——**静默失效、没有报错**。

## ④ Behavior Contract

```
Input      ：workflow（登记表里的 id：ledger.reconcile / price.batch）＋ 可选 from / to（YYYY-MM-DD）
             ＋ 对账可选 shipper（货主名字）；调价可选 product / shipper（多个用「、」隔开）
             ＋ 调价二选一 adjust（涨降百分比，降 15 填 -15）或 price（统一单价）
Output     ：一段 JSON 文本：workflow / workflow_cn / as_of / window 或 scope / conclusion / incomplete
             / steps[]（每步 title ＋ count ＋ truncated）/ 各自的计数与 brief 列表 / next（action ＋ action_cn
             ＋ params ＋ ask ＋ how）/ trace（痕迹带那一行）
Success    ：两步都读到 ⇒ conclusion 是人话结论；对账给「已送达 N 张 / 缺 M 张（合计 X 元）」，
             调价给「要调的是谁、几条专属价会被覆盖」；next.ask 是给用户的那一句
Failure    ：认不出 id / 执行器没接上分支 / 窗口反了 / adjust 与 price 给得不恰好 / 任何一步读失败
             ⇒ 返回 {error: …}，且**一步都不再往下跑**（窗口反了时一个读都不发）
Boundary   ：一次取不完（truncated）⇒ incomplete = true，结论里写明「这次没查全、数字不能当完整的账用」，
             ⛔ 对账不给 missing_amount（不许把半份数据当账报）
Side Effect：无（只读；不发卡、不写库、不改任何全局状态）
Authorization：工具级 fail-closed —— 角色不在 wf.roles 里就报「不在你现在的可用范围内」；两条都只给派单员
Compatibility：既有 8 个工具与它们的 schema 一个字未改；提示词只在末尾追加第 13 条（第 1~12 条编号不动）
```

## ⑥ CHG 专章

**Before**

- 想让 AI 对个账，用户得说一串（「查一下这个月已送达的订单」「再查这个月的账本流水」「看看哪些没进账本」），模型每轮自己拼窗口、自己算差集；换一轮提问，窗口和口径可能就变了。
- 批量调价同前：用户说「菜籽油降 5%」时，**名字里带「菜籽油」的到底有几个商品、有几条专属价会被覆盖**，发卡之前无从得知。

**After**

- 用户说一句「这个月对一下账」⇒ 模型认出该走 `ledger.reconcile`、一次调用跑完两步（同一窗口查订单与流水）⇒ 回话照 `conclusion` 说：「对完了，全部货主、2026-10-01 ~ 2026-10-09：已送达 12 张单，其中 1 张没进账本（货款合计 30 元）…」＋ 问 `next.ask` 那一句。
- 用户说一句「把菜籽油降 5%」⇒ 走 `price.batch` ⇒ 结论先摆清楚（匹配到几个商品、几条专属价会被覆盖、名字对不上的单列），再问要不要发卡 —— **具体改前 → 改后仍在确认卡上**（算法只有那一份）。

**Must Preserve**

- 写能力那条唯一的路（`preview_write`）、读目录 36 条读能力与它们的口径、提示词第 1~12 条、确认卡、后端 / 端点 / 权限 / 数据库、历史数据。

**Blast Radius**：**L1 —— AI 能力面**。影响面：AI 助手多出 `run_workflow` 一个工具与提示词第 13 条；不动后端、不动数据、不动权限、不动写能力，也不改既有 8 个工具的行为。
