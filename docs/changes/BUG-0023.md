### R4-BOUNDARY-JUSTIFICATION：为什么边界解决不了这件事

这件事**不能**靠外围解决，三条理由都是硬的：

1. **写入口不止一个。** 只在 `backend/app/api/v1/expenses.py` 加校验，等于只堵住 HTTP 那一条 ——
   AI 的「记一笔支出」走的是同一个 `POST`（会跟着被堵），但种子脚本 `backend/scripts/seed_demo_data.py:1176` 与
   `backend/scripts/seed_ops_gap.py:439` 是直接调 `create_expense` 的；**闸门放服务层才是一次收口**。
2. **数据库层堵不住。** 给三个列加 `ForeignKey` 看起来最省事，但老库里**已经有** `id=55` 那类孤儿行（三个 999999），
   加约束的迁移在老库上直接失败；而 `expenses` 表连软删列都没有，没有任何"事后清理"的余地。
   所以本单只能**拦新写入的**，把既有的那些**摆到明面上**（第二件事）。
3. **报表这一侧只能在自己的实现里说清。** 孤儿开销之所以"消失"，不是因为被过滤掉了 ——
   是 `_vehicle_expenses` 把查无此车的桶也选了出来、而 `build_vehicle_cost` 只遍历真实 `vehicles`，**那个桶没有任何消费点**。
   要让它可见，就必须在 `vehicle_cost_query` 里把它接住并单列；在利润表那边"减一笔"是把账做错，
   在 Android 那边补一句静态文案则与数据无关（这个窗口有没有孤儿、有几笔，只有后端知道）。

        driver_id=body.driver_id, vehicle_id=body.vehicle_id, order_id=body.order_id,
