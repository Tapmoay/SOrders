> 出处：用户 2026-10-06 交办的缺陷台账 `_tmp/USER_BUG_LEDGER_20261006.md` 的 **L-10**：

## ⑤ Data Contract

- **新增/改动哪些字段**：① 列 —— `shipper_contacts.remark VARCHAR(256) NOT NULL DEFAULT ''`（迁移 023）；② 模型 `ShipperContact.remark`；③ schema `ContactCreate.remark` / `ContactUpdate.remark` / `ContactOut.remark`；④ Kotlin `ContactDto.remark` / `ContactCreateRequest.remark` / `ContactUpdateRequest.remark`。**没有第二个新字段**，也没有改任何既有字段的类型。
- **Owner 是谁**：这一列归**联系人自己**（`shipper_contacts.shipper_id` 那位货主，只有他能读能写）；共享地点库（`places`）**结构上没有它**，也不许有。
- **什么时候写 / 什么时候不写**：只在用户点「保存」时写（POST 新建 / upsert，或 PATCH 编辑）；「带出到地点备注」那一步**不写联系人备注**（它写的是 `shipper_locations.remark`，走地点自己那条路）；打开抽屉、看卡片、选联系人都只读。
- **是否允许 NULL**：**列不允许**（NOT NULL DEFAULT ''）—— `""` = 没写，是「空」的唯一表示；`ContactUpdate.remark` 的可空是**请求语义**（None = 这次不改），不是数据。
- **历史数据怎么办**：**不回填、不推断**（迁移里没有一句 `UPDATE`）—— 老联系人的备注一律是 `""`。用户没写过的话，⛔ 不许我们替他造。
- **迁移怎么做 / Rollback 怎么办**：迁移 `023_shipper_contact_remark`（VERSION = 23；先看表在不在、再看列在不在 ⇒ 可重跑）。回滚 = `git revert` 实现提交；**列可以留着**（多一列不影响老代码读：老代码的 POST 不带 remark、PATCH 不带键 ⇒ 不会碰它）。
- **删除本功能后历史数据还能不能解释**：能 —— 备注是「某位货主给自己的联系人写的一行说明」，删掉功能只是不再显示 / 不再带出，库里那一行仍然是可理解的事实（本来就是用户自己写的字）。
