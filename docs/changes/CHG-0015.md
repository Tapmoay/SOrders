① 三处「信息补齐」与两处「形态补齐」：

1. **联系人卡不画分类**。分类是 FEAT-0007 专门做出来的（左分类右列表、可管理），
   但列表里的联系人卡只看得到姓名与电话 —— 用户刚把十个人分好类，回头看卡片还是一片一样。
2. **地点卡不标「仓库」**。`LocationDto.isWarehouse` 决定这条地点能不能被订单的仓库口径选中，
   卡片上没有任何标记 —— 报单时才发现选错了地点。
3. **线路抽屉没有备注栏**。`AddressDto.remark` 存得下、卡片画得出（`:1108`），**只有抽屉里看不见** ——
   备注只能靠改数据库或者重开一条线路来写。
4. **三个表单抽屉只写 `fillMaxWidth()`**。`skipPartiallyExpanded = true` 的抽屉本来就是「能长多高长多高」，
   这里没写 `fillMaxHeight()`，于是键盘一起、`imePadding()` 把内容顶掉，用户看见的是一条缝。
5. **详细地址从左截断**。`maxLines = 2` 之外没有 `overflow`，默认尾部省略 —— 先被截掉的恰好是
   **门牌号 / 几栋几室**，也就是这条地址里唯一不能猜的部分。

另外一件是用户定的硬规矩（规范 §4.11 / 06:1371「删除一律软删 + **手边**要有撤回」）：这一页的每一行都没有
二次确认，删除直接打后端，而 `AppRepository` 里 `restoreAddress` / `restoreLocation` / `restoreContact`
三个还原接口**早就有了、界面上一个入口都没有**。

② 用户进「地址与联系人」页 → 在联系人档按分类挑人（左栏）→ 右侧看卡片 → 某条记录错了就点铅笔改、
不要了就点垃圾桶删。整条流程里用户要判断「这条是不是我要的」：分类、仓库、备注都是判断依据；
删错了则想知道「我刚才删的是哪一条、能不能救回来」。

③ 界面由「只有身份信息（姓名 / 电话 / 地址）」**变成**「身份信息 + 归属信息（分类 / 仓库）+ 那条备注」，
抽屉由「半截身子」变成「拉满 + 可滚动」，地址由「尾部省略」变成「头部省略」，

## ⑥ CHG 专章

### Before

分类、仓库、备注三个字段在库里都有（`ContactDto.category`、`LocationDto.isWarehouse`、`AddressDto.remark`），
界面上只用了其中两个（联系人左栏的分类、`AddressCard` 的备注），卡片本身一个字都不画；
三个表单抽屉只写 `fillMaxWidth()`；详细地址 `maxLines = 2` 没有 `overflow`（默认尾部省略，先截掉门牌号）；
删除直接打后端、页面上**没有任何还原入口**，而 `AppRepository` 里三个 `restore*` 早就有了。

### After

`AddressScreen.kt` 多一个私有 `CardTag`（一处实现两处调用）：联系人卡电话下面画分类小字、
地点卡名字右边画「仓库」标记；线路抽屉在「设为默认线路」前多一栏「备注」；三个抽屉的 Column 追加
`.fillMaxHeight()`；详细地址改 `TextOverflow.StartEllipsis`。`AddressViewModel` 新增
`RecentlyDeleted(kind, label, id, name)` + `recentlyDeleted` + `undoDelete()`（`when (rd.kind)` 走
`repo.restoreAddress / restoreLocation / restoreContact`），三处删除成功后各记一笔；
`AddressScreen.kt` 在列表容器之前画一行「已删除「X」+ 撤销」。

### Blast Radius（L0～L3）

**L1** —— 动的是「地址与联系人」这一页加它的 ViewModel，但**新增了一条会写库的路径**：
删除之后可以原地还原（调既有 `restore*` 端点）。不动端点 / DTO / 迁移 / 权限 / 审计 / 并发 / 资金。
⚠️ 选 L1 而不是 L0 的理由：L0 是「只有呈现层、连数据写路径都不新增」；
这一批虽然没新接口，但用户的删除动作从此多了一条「可撤回」的可观察行为，
而且撤回要真的把记录还原回来 —— 按「有写路径」评估。
