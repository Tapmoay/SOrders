# CHG-0018 · 账号管理页按设计规范重做（新增 / 编辑账号从 AlertDialog 搬进抽屉表单 —— 白卡分组、选取器改下拉、错画在表单里）

> 司机管理 / 货主管理 / 批发商管理这三池共用同一个「新增 / 编辑账号」表单。它一直是 `AlertDialog` + 一摞裸
> `OutlinedTextField`，而规范 :14 写的是「**弹窗**：选择/确认类用 `AlertDialog`；表单类用 Drawer/ModalBottomSheet」、
> :762-763 写的是「**表单带选择器时用单独一页，不要塞进 `AlertDialog`**」。这一个表单里有车型、计费规则两个选择器
> 再加一张商品可见范围清单，旧代码自己都写着「字段叠起来在小屏会把「保存」顶出屏幕」—— 本批就是把它按规范搬进抽屉，
> 顺带治一个真的会让人以为「点了没反应」的错：校验 / 保存失败原来写的是**页面级** `vm.error`，而那句话画在弹窗**背后**。

① 三件事，前两件是「同一个事两种画法」，第三件是**真的会误事**：

1. **表单还塞在弹窗里**。规范 :762-763 的结论（「全屏选品层套在弹窗里就是两层 modal 窗口叠着，而且字段一多弹窗会顶到屏幕边」）
   在这一屏成立：`AlertDialog` + `Column(verticalScroll)` 硬顶，小屏上「保存」被顶出屏幕 ——
   旧代码 :221-223 的注释自己就承认了。同一屏的三个**选择器 / 清单**（车型、计费规则、商品可见范围）本来就是"单独一页"的形状。
2. **字段没有分组、也没有走共用行**。手机号 / 姓名 / 密码 / 车辆类型 / 计费规则五个裸 `OutlinedTextField` 竖着排，
   `ProductVisibilityBlock` 还自己画一句 `Text("商品可见范围")` —— 规范 §5.0 的卡片形态是白卡、组标题画在**卡外**，
   地址页与车辆页的抽屉早就是白卡 + 共用行，只有这一屏不是。
3. **保存被拦下时用户看到的是"点「保存」没有任何反应"**。`save()` 的三类失败（手机号格式、初始密码不足 6 位、
   服务端拒绝）写的都是**页面级** `error`；而 `UsersManageScreen.kt:124` 把页面级错误渲染成 `ErrorView`（顶掉整页）、
   弹窗里一个字都不显示。规范 :475 要求表单的错画在「**那张抽屉 / 弹窗内部**、提交按钮上方」，:466-467 记的就是这个病
   （「点「保存」**没有任何反应**——那句话画在抽屉**背后**」「关掉抽屉后**三个列表全没了**」）。

② 派单员（或货主 / 批发商自己）进「工作台 → 司机管理 / 货主管理 / 批发商管理」→ 点黄绿 FAB「新增」或点某张卡片上的「编辑」
