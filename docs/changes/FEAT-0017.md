## ④ Behavior Contract

- **Input**：`{"phone": "138…（11 位，以 1 开头）", "password": "6~128 位", "full_name": "可选"}`。
  ⛔ 请求体里带 `role` / `is_member` / `is_active` / `vehicle_type` / `salary` / `billing_mode` /
  `driver_rule_id` **一律忽略**（schema 不声明 + 端点不读，两道都钉着）。
- **Output**：与登录**同一个形状** `Token{access_token, token_type="bearer", role="shipper", user_id}`
  —— 用户注册完直接进 App，不用再登一次。
- **Success**：建号（role=SHIPPER / is_active=True / is_member=False / category="" / username=phone）
  → 写一行 `USER_CREATE` 审计（payload 带 `"source": "self_register"`，⛔ 不记口令连哈希也不记）
  → 提交 → 记一次 IP 注册计数 → 发令牌。
- **Failure**：手机号形状不对 / 密码长度不对 → **422**（中文，App 端 `humanizeValidation` 兜底）；
  号已被占 → **400「该手机号已存在」**（与派单员建号那条逐字一致）；用户名被老号占着 → 400「该用户名已存在」；
  明文通道（有 `X-Forwarded-Proto` 且不是 https）→ **426**（文案里必须给出下载新版的地址）；
  同 IP 注册过多 → **429**（中文，说明"请让派单员建"）。**没有 500 这一档**。
- **Boundary Cases**：全角数字必须被拒（`re.ASCII`）；带前导/尾随空格的手机号必须被拒
  （账号=登录名，登录按精确匹配，静默 strip 会造出"建得出来、登不进去"的号）；注册**不**撤销任何既有会话。
- **Side Effects**：`users` 多一行、`operation_logs` 多一行、限流计数器 +1；**通知/订单/账本零副作用**。
- **Authorization**：**公开**（没有 token 也能调）。它是"进门"端点，所以**不该**有角色门槛 ——
  安全性不来自鉴权，而来自四条边界：明文拒收 / IP 限流 / 属性服务端写死 / 手机号形状。
- **Compatibility**：老客户端不受影响（只是多了一个可选端点）；新客户端对老后端会拿到 404 →
  `ApiClient.httpMessage` 翻成「服务器上还没有这个功能（接口不存在，404）」，不会崩。

## ⑤ Data Contract

- **新增字段**：无。注册只是往 `users` 插一行，用的全是既有列。
- **Owner**：新账号自己（`users.id`）；审计行 `operation_logs.operator_id` = 新账号 id。
- **何时写**：端点被调用且通过四道边界时，**同一个事务**里写 users + operation_logs。
- **是否允许 NULL**：`full_name` 允许空串（可选）；其余字段全部由服务端写死，不允许 NULL。
- **历史数据**：无迁移、无回填。
- **迁移与 Rollback**：零迁移。回滚 = 删掉端点 + 客户端入口（见 §⑨）。
- **删除后能否解释**：能。审计行留着（`source=self_register`），事后能分清"这个号是自助注册的"。
