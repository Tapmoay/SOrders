# BUG-0006 · 登录被踢之后只有一句「登录已失效」：四种原因分不清、403 被说成掉线、事后在库里查不到「谁顶了谁」（2026-10-03 E2E 走查机制性发现）

> 走查原话（`_tmp/E2E测试报告.md:151-156`，逐字）：
>
> **机制性发现：登录被踢后，四种原因共用一句「登录已失效，请重新登录」**（`:151`）
>
> **现象**（`:152`）：5554 在巡检中被弹回登录页，只有一句 toast「登录已失效，请重新登录」；服务端 `GET /api/v1/users/me` → 401；logcat 05:29 之后到 05:41 之间没有任何其它 4xx/5xx。
>
> **机制（读码确认）**（`:153`）：`backend/app/api/v1/auth.py:68-70` 在账号于新设备登录时 `revoke_tokens_and_sockets(..., "账号在另一台设备登录")` —— 后来者顶掉先登的；旧设备下一次请求 401 → `android/.../core/ApiClient.kt:65` `onSessionExpired` → 清会话 → 跳登录页。而 `core/ApiClient.kt:149` 把 **403（纯权限不足）也写成「登录已失效」**。
>
> **问题**（`:154`）：被顶号 / 被停用 / 改了密码 / 令牌过期，在用户眼里**全是同一句话**，不说原因；服务端明明握着 reason 字符串。真人会以为 App 坏了或网络问题。
>
> **附带**（`:155`）：users 表**没有 last_login_at 字段**，事后在库里查不到「谁顶了谁」。
>
> **证据**（`:156`）：`_tmp/w_stock.png`（实为登录页）、`_tmp/w_login.png`
>
> 这条**不在**报告「九、建议修复优先级」的六条里（不是漏排：它写在「三、问题清单」的机制性发现段里），报告「八、未覆盖 / 待确认」第 6 条还单独追了一句（`:232`，逐字）：**「users 表无 last_login_at，无法在库层面审计「谁顶了谁」。」** —— 本轮把它一次做完。

① **四种原因在用户眼里是同一句话，而四种原因要用户做的事完全不同。**

| 原因 | 服务端知道的那句话 | 用户该做什么 |
| --- | --- | --- |
| 被别的设备顶号 | `账号在另一台设备登录`（`backend/app/api/v1/auth.py:77`） | 问一句「是不是你自己在另一台手机上登的」；不是就得改密码 |
| 主动登出 | `登出` | 什么都不用做（他自己按的） |
| 改了密码 | `改密码` | 用新密码登 |
| 账号被停用 | `账号被停用` | 找派单员（重登一百次也没用） |
| 令牌过期 | （没有撤销，时间到了） | 重新登即可，**不该怀疑账号出问题** |

共用一句话等于把「你该做什么」这件事删掉了 —— 被停用的司机反复重登、被顶号的货主以为 App 坏了、改了密码的人以为网络有问题（报告 `:154` 原话）。第二件事：`core/ApiClient.kt` 的兜底句把 **403（纯权限不足）**也写成「登录已失效」，而 403 是「这个号没这个权限」，**不该清会话、更不该提登录失效**。第三件事（报告 §八.6）：一次顶号在库里只留下「版本号 +1」，**事后查不到「谁在什么时候登进来、把谁顶掉了」**。

② **现状（读码）**：服务端**一直握着原因** —— `backend/app/services/auth_service.py:87 def revoke_tokens_and_sockets(db, user, background_tasks, reason)` 的第四个参数就是那句话，四条调用路径都传了；它被用来排推送、写日志，**但从没有落库**。401 有四个来源，在 `backend/app/deps.py` 里各走各的分支：令牌读不出来（`:58 credentials_exc` / `:63` / `:70`）、过期（`:65 except ExpiredSignatureError:` → `:68`）、账号没了（`:76`）、被停用（`:78`）、`tv` 对不上（`:84` → `:88 raise _unauthorized(_session_ended_detail(user))`）。
客户端这边：`core/ApiClient.kt:66` 见 401 就调 `onSessionExpired`（`:73`）→ `core/AppContainer.kt:19 → :65 clearSession` → `ui/nav/NavGraph.kt:109-112` 弹**硬编码**的「登录已失效，请重新登录」→ 跳登录页。**响应体里的 detail 从来没被读过**（`httpMessage` 只负责把异常拼成人话）。长连接那条路同理：`core/SocketManager.kt:110` 被服务端撤销时只推一个「tick」，`core/RealtimeHub.kt:109-112` 也只清会话、不带原因。
第三件事的现状：`users` 表只有 `token_version`（每次撤销 +1），没有任何「什么时候、因为什么」的痕迹，也没有「这个账号最后一次登录成功是什么时候」。

③ **变化：让服务端知道的那句话活到用户眼前 —— 并且只在该说的时候说。** 五处，一个方向：
(a) **落库**：`users` 加 4 列（`backend/app/models/user.py:55-62`）—— `session_revoked_reason` / `session_revoked_at` / `session_revoked_version` / `last_login_at`；撤销的唯一入口在 `bump_token_version`（`auth_service.py:77`，每个撤销路径都会调它）之后把这三样写进**同一个事务**（`auth_service.py:111-115`）；登录成功时记 `last_login_at`（`api/v1/auth.py:74`，写在 `db.commit()` 之前）。
(b) **分句**：`deps.py` 的四个 401 分支各说各的（`:58` 令牌无效 / `:68` 已过期＋24 小时 / `:76` 账号不存在 / `:78` 已被停用），`tv` 对不上那一路交给 `_session_ended_detail(user)`（`deps.py:27-51`）按「这一次的原因」说话；所有 401 由 `deps.py:18 _unauthorized` 统一构造，带 `WWW-Authenticate: Bearer`。
(c) **对账**：原因是一个**状态**，上一次撤销可能已经隔了好几轮登录 ⇒ 只有 `session_revoked_version == token_version` 时那条原因才描述**最近这一次**（`deps.py:46 if not reason or recorded != current:` → 兜底句「登录已失效，请重新登录」）。**宁可说兜底句，也不许拿旧原因解释这一次**（说得斩钉截铁却是错的，比不说更坏）。
(d) **客户端把 detail 取出来**：`ApiClient.kt:139 internal fun unauthorizedDetail(resp)` 用 `resp.peekBody(64L * 1024).string()` 读正文（`peekBody` 不消费 body，**不能**用 `body?.string()`，那会把后面的反序列化喂成空）、只认中文 `detail`；`:73` 把它交给 `clearSession(reason)`；`NavGraph.kt:112` 改成 `reason ?: "登录已失效，请重新登录"`；长连接那条路把报文里的 `reason` 取出来（`SocketManager.kt:143 revokedReason(args)`）一路带到 `RealtimeHub.kt:112`。
(e) **403 与 401 分开**：`ApiClient.kt:171`（401）与 `:172`（403）不再是同一句；403 不清会话、不提「重新登录」。

④ **不能变**：① **豁免判据不许丢** —— `api/v1/auth.py:76 if not is_test_account(user.phone):`：`1380000000X`（X=1～9，`auth_service.py:49-65`）这些自动化共用号段的账号登录**不作废**别的会话，否则跑一遍用例就把真机踢下线。② **登录失败那条路不许撤销**（打错密码不能把人踢下线，`_check_single_session.py` 钉着）。③ **不许在登录路径上清 `session_revoked_reason`** —— 被顶掉那台还要靠这次撤销记下的原因说话。④ 401 的**四种语义不许合并回一句**（判据逐句钉住）。⑤ `tv` 对不上的**升级兼容**不许破坏：老令牌没有 `tv` ⇒ 按 0、老库补列默认也是 0 ⇒ 升级不踢人。⑥ 不影响任何正常请求、不影响 403、不影响权限。

⑤ **Core**（详见 ③ 的核心改动声明）：`deps.py`（401 的唯一出口）、`auth_service.py`（撤销的唯一入口）、`core/ApiClient.kt`（401 的唯一拦截点）、`core/AppContainer.kt` / `core/SocketManager.kt` / `core/RealtimeHub.kt`（清会话的唯一通道）。**Extension / Infrastructure**：`users` 表 4 列 —— **正式搬迁** = `backend/app/migrations/016_session_end_reason.py`（VERSION 16，逐列判存在、可重跑、不回填）；**自愈副本** = `core/schema_bootstrap.py:1387/1400/1408/1422`（四块都是「列不在才补」，重复启动幂等；它只在 `prepare_schema` 那条迁移入口里跑 —— 应用启动只核对不改库，R3-01）。**Presentation**：`ui/nav/NavGraph.kt:109-112` 那一句 toast（唯一一处）。

⑥ **证据**：判据 `_tools/qa/_check_session_end_reason.py`（37 项：四句话逐句钉、对账条件、时间戳兜底、豁免、403 与 401 分开、peekBody、internal 可见性、两端回归用例数、文档与登记表）；反验 `_tools/qa/_reverse_verify_session_end_reason.py`（32 条注入逐条报红）；后端 `backend/tests/test_session_end_reason.py`（10 例，覆盖被顶号 / 登出 / 被停用 / 改密码 / 过期 / 账号没了 / 对账 / 兜底 / 旧原因不许解释这一次 / last_login_at）；Android `SessionExpiryMessageTest.kt`（6 例）；真机顶号实测（见 ⑧）。

## ③ Boundary（Core / Extension / Infrastructure / Presentation）

**核心改动声明**（4 处，逐条给理由）：
- `backend/app/deps.py` —— **为什么必须动核心**：401 的唯一出口就是 `_unauthorized` 与 `get_current_user`，四句话只能在这里分；在客户端分（按状态码猜）是猜的，服务端知道真因。
- `backend/app/services/auth_service.py` —— **为什么必须动核心**：撤销的唯一入口是 `revoke_tokens_and_sockets`，原因是它的入参；不在这里落库就得在四个调用点各写一遍。
- `android/.../core/ApiClient.kt` —— **为什么必须动核心**：401 的唯一拦截点（`:66`）与唯一的错误文案函数（`httpMessage`）在这里；改别处拿不到响应体里的 `detail`。
- `android/.../core/AppContainer.kt` ＋ `SocketManager.kt` ＋ `RealtimeHub.kt` —— **为什么必须动核心**：HTTP 与长连接两条失效路径**共用**一个清会话通道（`clearSession`），原因必须挂在这个通道上，否则两条路各弹各的。

**Extension**：无（没有新增扩展点）。
**Infrastructure**：`users` 表 4 列 ＋ **正式搬迁** `backend/app/migrations/016_session_end_reason.py`（VERSION 16；不含索引、不回填）＋ 自愈副本 `backend/app/core/schema_bootstrap.py:1384-1426` 四个幂等补列块。
**Presentation**：`android/.../ui/nav/NavGraph.kt:109-112`（一句 toast）。

## ④ Behavior Contract

| 项 | 内容 |
| --- | --- |
| Input | 401 响应体里的 `detail`（服务端四种之一），以及 socket 撤销报文里的 `reason`。 |
| Output | 一条 toast：`登录已结束：<原因>（<时间>）` / `登录已过期（令牌 24 小时有效），请重新登录` / `这个账号不存在或已被删除，请联系派单员` / `这个账号已被停用，请联系派单员`；说不清时 `登录已失效，请重新登录`。 |
| Success | 被顶号那台说得出「账号在另一台设备登录」＋时间；登出 / 改密码 / 被停用 / 过期各说各的；403 不提登录失效、不清会话。 |
| Failure | 读不出 `detail`（英文 / 非 JSON / 空正文）⇒ 退回兜底句，**不炸**（`runCatching`）。 |
| Boundary Cases | 原因与版本对不上（`recorded != current`）⇒ 兜底句；`session_revoked_at` 为空 ⇒ 只说原因不带时间（**不许拿「现在」冒充**，那会让人以为刚刚被踢）；原因超 64 字 ⇒ 截断；原因带空白 ⇒ `strip`。 |
| Side Effects | 一次撤销多写 3 列（同一事务）、一次登录多写 1 列；客户端多读一次响应正文（`peekBody`，不消费）。 |
| Authorization | 无变化（不改任何判权路径；403 的行为只改措辞）。 |
| Compatibility | 老令牌 / 老库按 0 处理 ⇒ 升级不踢人；4 列都有默认值 ⇒ 老行可读；客户端老版本忽略多余字段。 |

## ⑤ Data Contract

| 列 | 类型 / 默认 | 谁写 | 含义 |
| --- | --- | --- | --- |
| `session_revoked_reason` | `String`，default `""` | `revoke_tokens_and_sockets`（`auth_service.py:111`，`(reason or "").strip()[:64]`） | 最近一次撤销的原因原话（空 = 没记过） |
| `session_revoked_at` | `DateTime`，nullable | 同上（`auth_service.py:112`，`utc_now_naive()`） | 这次撤销发生在什么时候 |
| `session_revoked_version` | `Integer`，default 0 | 同上（`auth_service.py:113`，写入**撤销后**的 `token_version`） | 「这句话还算不算数」的凭据：等于当前 `token_version` 才算数 |
| `last_login_at` | `DateTime`，nullable | `_login`（`api/v1/auth.py:74`） | 这个账号最后一次登录成功的时间 |

- **老库升级路径（两条，一主一兜底）**：① **正式** = `backend/app/migrations/016_session_end_reason.py`（VERSION 16，`python -m app.migrations upgrade` 跑一次、跑过写 `schema_versions`；逐列判存在、可重跑、⛔ 不回填）；② **兜底** = `backend/app/core/schema_bootstrap.py` 四个幂等块（`:1387` / `:1400` / `:1408` / `:1422`），都在 `prepare_schema` 那条迁移入口里。两处的默认值都是「没有原因 / 没记过」。⛔ 应用启动（`app/main.py:246-269 assert_schema_ready`）**只核对不改库**：光有兜底块、没有迁移，`upgrade` 会说「结构与迁移都已就绪」而库里依旧缺列。
- **没有**新增/修改任何请求体、响应体、DTO 字段、端点。客户端读的是**既有的** 401 响应体 `detail`。

| 原因已经不作数（隔了几轮登录） | 无此概念 | 兜底句「登录已失效，请重新登录」（**不许**拿旧原因解释这一次） |

| 长连接被撤销（前台那台） | 只推一个 tick → 兜底句 | 报文里的 reason 一路带到 toast |
| `users` 表 | 只有 `token_version` | ＋ `session_revoked_reason` / `session_revoked_at` / `session_revoked_version` / `last_login_at` |

### Must Preserve

- `is_test_account` 豁免判据与它的位置（`auth.py:76`）。
- 登录**失败**分支不撤销；`_check_single_session.py` 的既有红线（后来者顶掉先登的、豁免、失败不撤销）全部保留。
- 登录路径不碰 `session_revoked_reason`。
- `tv` 校验的兼容写法（`getattr(user, "token_version", 0) or 0`）。
- `httpMessage` 其它分支（404 / 其它 4xx / 5xx）的措辞与既有单测。

### Blast Radius

**L2**：认证链路（401 语义、清会话通道）＋ 库表加列。没有钱、没有订单状态机、没有新请求/新端点、没有权限判权变化、没有新依赖。
