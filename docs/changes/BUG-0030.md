# BUG-0030 · 账本「合计必须等于 数量×单价」的报错文案把金额印成 `60.00`（与三端显示口径不一致）

- 类型：BUG（缺陷修复）｜Blast Radius：**L0/L1**（只改一条报错文案的金额显示；闸门逻辑与金额值一个字节不动）
- 发现方式：**自查**——并行会话在跑 `_tools/qa/_check_all.py` 时，`_check_money_display.py` 报 `49 项通过 / 1 项失败`，越界点直指 `backend/app/api/v1/ledger.py:144`（`return f"{Decimal(value):.2f}"`），而这行是 **BUG-0025（测试台账 TB-10）那一单引入的**。
- 相关单：`docs/changes/BUG-0025.md`（同一个闸门）；台账条目 **TB-10**。

## 六问

① **解决什么问题？** 用户 2026-09-22 定的显示口径是「印给人看的金额去掉末尾多余的 0」（`56.70 → 56.7`、`87.00 → 87`，但 `56.77` 一位都不能少）。BUG-0025 的 400 报错文案自己拼了一遍两位小数，于是用户看到「这一行是 数量 3 × 单价 20.00 = 60.00，与你给的 合计 288.00 不一致」——同一屏上别的金额都是去尾零的写法。
② **当前流程是什么？** `resolve_line_total()` 发现不一致时拼 `detail`，其中三处金额走本文件私有的 `_money()`；`_money()` 用 `:.2f`。
③ **哪个现有事实会变？** 只有**报错文案里的金额写法**：`60.00 → 60`、`288.00 → 288`、`20.00 → 20`。
④ **哪些明确不能变？** 闸门的判定逻辑与 400/201 的状态码；`quantity`/`unit_price`/`total` 的**值**与落库结果；接口出参（`suppliers.py` 那种两位小数字符串仍按值口径）；`_reject_if_order_closed` 的「已送达」闸。
⑤ **属于 Core/Extension/Infrastructure？** 展示层（报错文案）——不改核心不变量。
⑥ **什么证据能证明完成？** `_tools/qa/_check_money_display.py` 从「49 通过 / 1 失败」变 **50 项全绿**；`_tools/finance/_check_ledger_total_consistency.py` 仍 **52/52**；`_tools/qa/_check_ledger_manual_entry.py` **49/49**；`backend/tests/test_ledger_total_consistency.py` **6 passed**。

## 改法（一处，3 行）

```python
# backend/app/api/v1/ledger.py
from app.services.money_text import money_text

def _money(value) -> str:
    """金额只用来拼**报错文案**（给人看：与三端同一个显示口径，去尾零）。
    `Decimal("20.0000")` → `20`；`Decimal("56.70")` → `56.7`；`Decimal("56.77")` → `56.77`。"""
    return money_text(value)
```

判据跟着改两处（把「文案里必须有 `60.00`/`288.00`」改成 `60`/`288`）：`backend/tests/test_ledger_total_consistency.py:92` 与 `:198`。

## 六格

- **Changed**：`backend/app/api/v1/ledger.py`（`_money` 改走 `money_text`，并加 import；注释说明为什么不再自拼两位小数）、`backend/tests/test_ledger_total_consistency.py`（两处断言）。
- **Preserved**：闸门判定、状态码、金额值、落库结果、接口出参、已送达闸 —— 都有既存判据（52 项 / 49 项 / 6 条单测）继续钉着。

- **Known Limitations**：只覆盖「报错文案里的金额」这一类；其它模块若将来自己拼两位小数，`_check_money_display.py` 会继续报（这是设计，不是漏洞）。
- **Rollback**：`git revert <实现提交>` —— 只影响一行字符串生成与两条断言。
- **Historical Data Impact**：**无**。历史账本行、已发生的 400 拒绝、已落库的金额都不受影响（本条只改「拒绝时印给人看的字」）。
