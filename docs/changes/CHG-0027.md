## ① 六问

### 问 1：用户看到的是什么？期望是什么？

四处的共同形状是**一个字面量在窄地方被切开**，四种切法：

| 走查项 | 实际（走查原话） | 用户期望 |
| --- | --- | --- |
| P30 | 地点卡联系人行显示「刘秋萍（永盛食品仓库） ·」——**号码整段消失，连省略号都没有** | 既看得见人、也看得见电话（这是这一行存在的理由，`ContactFill.kt:78-83`） |
| P18 | 「用在：大车运费…」「含装卸；超 3 吨…」——省略号截在词中间，页面上只有 删除 / 编辑，看不到完整条件 | 条件能看全（至少有入口看全） |
| P28 | 「**固定工资**（月薪未设置，账单里不会出现…」——肯定词在前、否定在后，还被截断 | 一眼看出「我现在没有工资单」，而不是「我有固定工资」 |
| P4 | 「账号：138000012 / 34 密码：123456」「SO2026100365088830 / 54」——数字串从中间断开 | 号码 / 单号读成一个整体的数 |

### 问 2：现状为什么是这样？（四个各自的根因）

- **P30**：`AddressScreen.kt` 联系人行 `maxLines = 1` 且**没有 `overflow` 参数**（Compose 默认 `TextOverflow.Clip`）⇒ 溢出部分被**静默**裁掉。同一张卡的地址行写了 `maxLines = 2 + StartEllipsis`，两行**同一个取舍没有对齐**。
- **P18**：卡片三行小字里，价目名那行连 `overflow` 都没写（同 P30 的静默裁剪）；另两行是 `maxLines = 1 + Ellipsis`（有省略号，但只给一行）。而「看全文的入口」在生产代码里**其实存在** —— `FreightTemplateSheet` 就是这一条价目的全字段抽屉，只是卡片上没有指向它的手势。
- **P28**：文案由后端 `driver_pay.py` 的 `pay_summary_for()` 一处拼（客户端照抄，这是「钱只说一句」的既有约定），那句话的语序是**先肯定后否定**；显示端 `ProfileHeader.kt` 又只给一行。两件事叠起来才是走查看到的那一行。
- **P4**：Compose 按 Unicode 换行机会折行，而 `SO` + 18 位数字**中间处处都是换行点**；弹层标题与 Snackbar 恰恰是最窄的地方。⚠️ 第一版修法（把 U+2060 WORD JOINER 插进数字之间、取消换行机会）在真机上**被证明不够**：Material3 弹层标题是 24sp 大字，20 字符串号一行约 760px 而弹层内宽约 730px ⇒ 换行器仍然必须从中间劈开（U+2060 只取消「可以断」的点，改变不了「放不下」的事实）。最终改成：动作名一行、**单号另起一行并降到 `bodyMedium`**（14sp）+ 一行 + 省略号，20 字符在小一号里整行放得下。

### 问 3：改完用户看到什么？

- 地点卡的联系人：两行 + **保尾部**的省略号 —— 正常长度（`刘秋萍（永盛食品仓库） · 13530753867`，20 字）**整行看得全**；真放不下时省略号出现在**行首**（牺牲名字的前几个字），电话号码始终在。点卡片任意空白处 = 打开这一条的抽屉（看全 + 改）。
- 运费模板卡：三行小字都给两行；点卡片任意空白处 = 打开这一条价目的抽屉（线路 / 名称 / 一车价格 / 分类 / 计费规则 / 备注全在里面）。
- 司机「我的」：那行最多两行；没设月薪的司机读到的是「**月薪未设置，不会生成他的工资单（计费方式：固定工资）**」——否定在前。
- 退货 / 办理退货 / 驳回退货申请 / 核销 / 编辑订单 这些弹层的标题变成两段：动作名一行（原字号）+ **单号单独一行、小一号、完整不劈开**；新建账号后的分享文案变成两行（账号一行、密码一行）。

### 问 4：不改会怎样？

- 用户按看到的字做决定：P30 让「地点卡上绑了谁的电话」这件事**看着像没绑**；P28 让一个**没有工资单**的司机以为自己有固定工资（这是四条里唯一会误导钱的一条）；P4 让要发出去的账号密码在客户眼里变成两个数。
- 这四条都属于「机器判不出来、只有人眼能看出」的那一类：字符串在无障碍树里是完整的（走查原文即如此），所以任何**按数据做断言**的测试都不会红。

### 问 5：怎么证明改对了？

**只有真机截图能证明**（这正是走查发现它们的方式）：
- 判据脚本 `_tools/qa/_check_text_truncation.py` 钉住**源码里的口径**（哪一行给了几行、有没有 `overflow`、哪几处标题走的是 `DialogTitle`、卡片可点指向哪个入口）；
- 反验脚本 `_tools/qa/_reverse_verify_text_truncation.py` 逐条注入「改坏了」的版本（去掉 `overflow`、把两行压回一行、把标题换回裸拼 `Text`、把单号那一行的字号与省略号改回去、把语序改回肯定在前）证明判据确实会红；
- 三台模拟器（5554 派单员 / 5556 货主 / 5558 司机）走真人手法截图复核。

### 问 6：会不会伤到别的地方？

- `noBreak()` 只改**渲染出来的副本**：剪贴板、请求体、库里存的值都还是原文（U+2060 只在 `Text` 的入参里，且全库只剩 `ui/common/DialogTitle.kt` 一处使用点）；`DialogTitle` 只把动作名与单号排成两段，业务逻辑仍在外层弹层里。
- 地点卡 / 运费模板卡的点击是**新增**手势：原来点卡片没有任何反应，两颗动作图标（编辑 / 删除）自己消费点击，不会被外层抢走。
- `driver_pay.py` 那句换了语序，**取值与分支一个没动**：`sal > 0` / `PIECE` / 挂了规则那三支原样。三个消费点（`ProfileHeader.kt` / `AssignDriverDialog.kt:154` / `UsersManageScreen.kt:696`）显示的是同一句新话。
