① 「下单人」那一行的**标签自带 `Modifier.weight(1f)`**（`ui/order/OrderDetailScreen.kt` 的
   `Text("下单人", style = bodyMedium, modifier = Modifier.weight(1f))`），于是它把后面的值
   **顶到整行最右** —— 中间那段空隙 = `整行宽 − 标签宽 − 值宽`：
   **值一长，空隙就没了（贴在一起）；值一短，空隙就很大**。这就是用户说的"有时候有有时候又没有"，
   与数据脏不脏无关。而它上面那一行「收货人」是**标签与值拼成一个 Text、左对齐**，
   于是两行的**值起点不一样**、**字号字重也不一样**（收货人 `titleMedium + Bold`、下单人 `bodyMedium`）
   —— 这就是用户说的"跟上面的又不做一个对齐"。

② 三端（司机 / 派单员 / 货主）共用同一个订单详情页：进「我的订单」→ 点一张单 → 卡片下方
   「收货信息」那一段依次是**收货人**（点一下直接拨）、**下单人**（点一下先弹「确认拨打」）、备注。
   用户就是在这两行之间看到了忽大忽小的空隙。

③ 两个现有事实会变：
   - 「下单人」那一行的**形态**：从"标签 Text（`weight(1f)`）+ 值 Text"变成**一个 Text**（`"下单人 " + 值`），
     字号字重跟「收货人」那一行对齐（`titleMedium + Bold`）；
   - 那一行的**字面**：源码里不再有独立的 `"下单人"`，改由 `"下单人 " + bossText` 拼出来
     （`ContactEditBlock(edit, "下单人", …)` 那一处是**就地编辑**用的，没动）。

④ 不能变：
   - **绿色**：用户 2026-09-22 点名要的（「样式不要变，但是颜色变一下，变成（一）点绿色」）
     ⇒ 有值时仍然是 `0xFF00B578`，没填时仍然是灰；
   - **点击行为**：下单人那一行点一下仍然只弹「确认拨打」`AlertDialog`，**不直接拨**（收货人才直接拨）；
   - `ui/common/OrderCard.kt` 的 `contactWho(...)`（卡片与详情的"名字（电话）"口径，全库唯一一份）；
   - 收货人那一行、备注行、`EditHint` 的就地改、以及"没填也要画这一行"的那道条件。

⑤ **PRESENTATION**（L0）：改的是同一段文字怎么排，不涉及任何事实、契约与权限。

⑥ 见 ⑦⑧：把"两行同形"这条口径**加到既有的红线里**（`_tools/qa/_check_contact_names.py` ④新增 4 条断言），
   并用既有的注入式反验（`_tools/qa/_reverse_verify_contact_names.py` ④新增 3 条）证明它会红；
   外加全量静检与 Kotlin 编译。

### After

```text
📞 收货人 曾庆华（13780347395）
👤 下单人 福满堂客家菜馆（13930359963）
```
