## ① 六问

① **要解决什么问题？** 批量干活时确认卡**一张张弹**（真机实测：40 条批发商专属价压成 40 张卡，用户全都要确认一遍）；而且**点快了点多了**会拿到 ⚠️「没写成：这张确认卡已经失效了（有效期 5 分钟…）」——卡还没点就作废，活儿白干。用户原话（2026-10-11）：「他那个确认卡呀，他**不要一个（角色）一个（角色）的弹**啊……如果是叫他批量干活的话，那个确认卡也是**只弹一个**，只是那个**表格卡是多个、长表格显示多个人**，这样就省事。不然你一弹一堆的确认卡，你全都要确认一遍，这样太麻烦了。」「还有这个确认卡，我**点快了点多了**，就会出现『**没写成**』的这种情况。」

② **当前流程？** 模型一次 `preview_write(action=…, params={items:[…]})` → `BatchWriteHandler.prepare` 逐条调用既有处理器（校验 + 名字→编号 + 算改动），**任何一条不合法整批不发**；把每条压成一行或一节文字 → 一张卡 → 用户点确认 → 逐条 `commit`、逐条 try/catch → `commitNote()` 汇报「成功 N / 失败 M + 失败原因逐条」。

③ **哪个现有事实会变化？** ③a 卡的**形状**：多一张「序号 / 对象 / 改前 → 改后 / 各条自己的字段」的长表格；③b 批量卡的**有效期**：5 分钟 → 30 分钟；③c 连点第二下 / 过期 / 被新卡顶掉这**三种**的回执口气（原来糊成一句「没写成」）。

④ **哪些东西明确不能变？** 写下去的**条数**（表只是渲染，payload 里的 `_batch` 数组一条不少）；**逐行如实汇报**（「成功 N / 失败 M + 失败的是哪一条」，⛔ 不许被「已完成」盖住）；**撤回语义**（批量不挂撤回，卡上最后一行写明）；**风险分级**（批量永远要确认，自动执行档的动作拒绝批量）；后端接口与权限一个字不动。

⑤ **属于 Core、Extension 还是 Infrastructure？** EXTENSION IMPL ＋ PRESENTATION。

⑥ **什么证据能证明它完成？** `_tools/qa/_check_ai_batch_card.py` 25 条断言全过；反验 `_reverse_verify_ai_batch_card.py` 8/8 条注入全部当场变红且逐字节还原；单测 `AiBatchCardTest` 17 例。

## ② Must Change / Must Not Change

```text
Must Change:
- 批量卡带一张长表格：AiCardBatchTable.sheet(items)（表头 = 序号 / 对象 / 改前 → 改后 + 各条出现过的标签），界面 BatchCardTable 渲染；
- 表格超行（>30）超列（>7）**不静默**：表尾说清「共 N 条，表里只列了前 30 条（点确认仍然是这 N 条全部执行）」；
- 批量卡有效期 BATCH_TTL_MS = 30 分钟（单条卡维持 DEFAULT_TTL_MS = 5 分钟），造卡时按 batch 分支取值；
- execute() 把「已经写进去了」/「被新的一张顶掉了」/「过期了」**三句话分开说**，过期那句给一条出路（「重新说一句我就再给你发一张」）；
- 卡片上「点下即锁」（busyToken），连点只执行一次。

Must Not Change:
- payload 里的 _batch 数组（写下去的条数）；
- commitNote() 的逐行汇报（成功 N / 失败 M + 失败原因逐条）；
- AUTO_EXECUTABLE 档拒绝批量（它在 prepare 里就写完了，放进来等于预览阶段写库）；
- 后端接口、权限点、order/ledger 的任何字段。
```

## ④ Behavior Contract

```text
Input          模型的一次 preview_write，params 里带 items=[{…},{…}]（每个元素是该动作的一组参数）
Output         一张确认卡（AiPendingWrite）：summary「批量<动作>：N 条」
               ＋ detailLines（≤20 条逐条展开，更多则每条压成一行）
               ＋ table（AiCardBatchTableSheet：headers / rows / note）
               ＋ payload={"_batch":[…]}
Success        用户点确认 → 逐条 commit → Done 的 message 里带上「这一批 N 条：成功 X 条，全部成功。」
Failure        任何一条不合法 → 整批不发（错误里带「第 i 条」）；执行期某几条失败 → 那几条不写进去，
               回执逐条点名（#i + 原因前 80 字）并说明「失败的那几条没有写进去，要重来就告诉我」。
               失败时**不**发生：不产生半成品事实（每条自己是一个完整请求）、不吞失败行、
               不把「已经写进去了」说成「什么都没写」。
Boundary Cases 0 条（items 为空 → 拒绝）；1 条（照旧走批量，payload 仍是 _batch）；
               31 条（表只画 30 行，note 说清，执行仍是 31 条）；
               8 个字段（表最多 7 列，note 说清漏了哪几个）；
               连点 5 下（只有第一下拿得到卡，其余 4 下说「这张卡已经执行过了」）；
               过期（说「这张卡过期了…重新说一句我就再给你发一张」）；
               被新卡顶掉（说「被新的一张顶掉了」，⛔ 不许往有效期上引）。
Side Effects   暂无（不改后端任何东西）；卡片本身写入本地暂存区，30 分钟后过期。
Authorization  沿用各动作自己的权限（写动作清单 + 角色裁剪）；批量层不新增权限。
Compatibility  Compatible —— 单条动作的 payload 与卡片一字未变（不带 _batch 的 payload 走原路）。
```

## ⑤ Data Contract

- **新增/改动哪些字段**：`AiPendingWrite.table: AiCardBatchTableSheet?`（**内存态**，只给界面渲染，不进任何请求体）；`AiCardBatchTableSheet(headers, rows, note)` 是纯数据。
- **Owner 是谁**：AI 助手（`ai/AiWrite.kt` 的暂存区）。
- **什么时候写 / 什么时候不写**：造卡那一刻写一次；单条卡**永远是 null**（判据钉着）。
- **是否允许 NULL**：允许（= 不是批量卡）。
- **历史数据怎么办**：不适用（暂存区不落盘、不进库；进程结束即消失）。
- **迁移怎么做 / Rollback 怎么办**：无迁移。回滚 = 把 `table` 那一行与 `BatchCardTable` 的渲染分支去掉，卡片退回原来的纯文字形态（有效期与话术可以单独回滚，互不依赖）。
- **删除本功能后历史数据还能不能解释**：能 —— 历史里没有这张表留下的任何痕迹。
```

## ⑥ CHG 专章

### Before

40 条批发商专属价：模型一次 `items` 申请 → 出一张卡，正文是 40 节 × 3 行（`detailLines` 的逐条展开），用户要滚几十屏才能看完；批量卡与单条卡**同一个有效期**（5 分钟），真机实测 14:21 连着 4 条「⚠️ 没写成：这张确认卡已经失效了（有效期 5 分钟…）」；连点第二下与「过期」无法区分，回执把「已经写进去了」和「什么都没写」糊成同一句。

### After

同一批 40 条：**一张卡 + 一张表**（序号 / 对象 / 改前 → 改后 + 各条字段，最多 7 列 × 30 行，超了在表尾说清「仍然是这 40 条全部执行」）；批量卡有效期 **30 分钟**（与「撤回」窗口同口径，用户只需要记一个数）；连点第二下说「**这张卡已经执行过了，没有写第二遍** —— 这一批 40 条：成功 38 条，失败 2 条 —— #7 …；#19 …」（把上一次的逐行结果原样带回来）；过期说「**这张卡过期了，重新说一句我就再给你发一张**」；被新卡顶掉说「**被新的一张顶掉了**」。

### Must Preserve

```text
- 历史订单 / 历史金额 / 已冻结的 Pricing Fact      —— 一个字没动
- 历史 Provenance / Audit / Ledger                  —— 一个字没动（批量仍逐条写 operation_logs）
- 权限                                              —— 沿用各动作自己的权限点
- API compatibility                                 —— 后端零改动
- 本事项特有：payload 里的 _batch 数组（写下去的条数）、commitNote 的逐行汇报、撤回语义
```

### Blast Radius（L0～L3）

**L2** —— 只影响「AI 确认卡」这一条交互链路（卡片形状、有效期、回执文案），
回滚只需还原 `ai/AiCardBatchTable.kt` 的调用点与 `AiWritePreviewStore` 的两个常量；
不涉及领域模型、数据库、权限、对外契约。之所以不是 L1：它同时改了**界面渲染**与**执行期回执**两处，
且 `AiPendingWrite` 是 50 多个处理器共用的类型（加字段需要考虑单条卡的兼容 —— 用默认值 null 做到了）。
