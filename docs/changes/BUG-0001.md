# BUG-0001 · 整单退货后账本吞掉被冲原行：订单账 / 货主账 / 批发商账凭空少一笔营收

> 来源：2026-10-03 三端真机 E2E（订单 #SO202610036508883054，速冻水饺 ×3 袋 ¥85.5，送达 05:38 → 整单退货 05:56）。
> 现象是**看账的人会以为这一天倒亏了 85.5 元**，而库里两行俱在、金额分毫不差 —— 错的只有**读口径**。

① **整单退货之后，账本页面凭空少一笔营收。** 本该「+85.5 与 −85.5 相抵为 0」，页面上只剩 −85.5：合计变成负数、笔数也少一笔。三张账（订单账 / 货主账 / 批发商账）同时错，因为它们共用同一份可见性判据。

② 业务流程：货主下单 → 派单员派单（自动出库）→ 司机送达（`services/ledger_sync.py` 写一行 `source=ORDER` 的自动账 +85.5）→ 货主申请退货 → 派单员办理退货（`services/order_return.py::return_order` 按行写一行负金额 `source=RETURN` 红冲行 −85.5，**整单退完**把订单状态转 `RETURNED`）。用户随后去「账本管理 → 订单账 / 货主账 / 批发商账」核对这一天的钱。

③ 变化的是**账本读口径**（`backend/app/services/ledger_scope.py::visible_ledger_clause()`）：`source=ORDER` 的自动账原先只在订单「已送达」时可见，现在**整单退货（`RETURNED`）也可见** —— 因为它的配对红冲行本来就可见，**两者必须同时出现才能相抵**。

④ 明确不能变化（详见 ② Must Not Change 一节）：已送达未退货的单、部分退货的单（订单仍是「已送达」）金额与笔数一分不动；回收站（软删）里的单的账继续不算；`CANCELLED` / `ACCEPTED` 上那批历史漂移自动行继续排除；**一行账本都不许删**（软删可恢复是用户 2026-09-20 定的硬规矩）。

⑤ Infrastructure —— 这是既有读口径的**实现修正**，不定义新事实、不新增字段、不改表结构、不新增权限点。判定依据见 ③。

⑥ 证据（见 ⑦⑧）：整单退货后 `GET /ledger/entries` 与 `GET /ledger/accounts?kind=shipper|member` 返回**两行 / 合计 0**；部分退货仍返回两行且金额不变；账本净额与「营业纵览」营业额逐位一致；反向验证脚本注入「退货后原行被吞」必须报红。

### Before

订单 #SO202610036508883054 送达后整单退货。用户在 5554 打开「账本管理 → 订单账」，时间选「今天」，看到：
**合计 ¥-85.5 · 共 1 笔流水**，唯一一行是「永盛食品 / 速冻水饺 ×-3 · 2026-10-03 / 订单退货红冲（自动）/ ¥-85.5」。
切到「全部」（862 笔流水）那一行依旧是孤零零的 −85.5，「订单送达自动记账 +85.5」**从来没有出现过**。
「货主账」「批发商账」同样各显示 永盛食品 ¥-85.5（1 笔）。

### After

同样的动作之后，「订单账（今天）」变成：**合计 ¥0 · 共 2 笔流水** ——
「永盛食品 / 速冻水饺 ×3 · 2026-10-03 / 订单送达自动记账 / ¥+85.5」与「永盛食品 / 速冻水饺 ×-3 / 订单退货红冲（自动）/ ¥-85.5」两行并列、相抵为 0。
「货主账」「批发商账」各显示 永盛食品 ¥0（2 笔）。部分退货的订单（#SO202609262768928606：+104.4 与 −69.6）与改前逐位一致。
