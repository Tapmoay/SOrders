# CHG-0024 · 顶栏分类胶囊落在哪一边 + 地址页三档搜索框对齐（2026-10-05 用户两条要求）

> 用户 2026-10-05 原话（看着车辆管理页顶栏那颗「全部」，红箭头从屏幕右缘指过来）：
> 「呃你这个**全部**按钮啊，与下面的**卡片做一个右侧对齐**啊啊，就是**往左移一点**，然后，
> **其他的所有的按钮也是按照这样子的形式放在右边**啊，不要贴着那个名字的后面。」
>
> 紧接着的一句澄清就是判据：「如果**右边有东西**的话，则就**保持原样**。如果右边是**空**的话，则就**放在右边**。」
>
> 第二条（两张截图：联系人档的描边圆角搜索框 vs 路线档的浅灰实心框）：「还有**路线和地点的搜索框怎么跟联系人的
> 搜索框不一样**，将他们以**联系人的搜索框的形式**给**对齐**啊」
>
> 这一批就做这两件事，都是**版式**层面的对齐，没有一条业务规则被改：
> **① 顶栏那颗分类胶囊的落位** —— 右边有东西的页面（司机管理有「车辆」、批发商管理有「批量调价」、
> 地址与联系人三处都有「新增…」）**保持原样**仍贴着标题；右边空着的页面（车辆管理、账户管理、货主管理）
> 把它贴到右侧、`actions` 自带的 4dp 再补 `Modifier.padding(end = 12.dp)`，右缘正好落在卡片的 **16dp** 内边距上
> （1080×2400 密度 3 上量过：卡片白色平台到 x=1030 ⇒ 16dp，胶囊原先右缘 x=1068 ⇒ 4.0dp）。
> **② 地址与联系人页三档（路线 / 联系人 / 地址）的搜索框** —— 一律换成全 App 唯一那份 `SearchField`
> （放大镜 + 入框即出 ✕ 一键清空 + 圆角描边），**只有占位语按档不同**；那一档原来自己画的 `SoTextField` 与
> 它旁边那枚自绘清空按钮一起删掉。
>
> ⛔ 地址页那三颗胶囊一颗都没动（它们右边都有「新增」，正合用户「右边有东西就保持原样」那句）。
> **后端、DTO、仓库层、权限、审计、迁移一行不改**。

① **我要解决什么问题？** 两个「看起来不像一套」的问题。一是顶栏那颗分类胶囊的**落位**：同样一颗「全部」，
在车辆 / 账户 / 货主三页孤零零挂在标题右边，在司机 / 批发商两页又因为右边有按钮而显得正常——用户要的是
「右边空就贴到右边、并且和下面的卡片右缘对齐；右边有东西就保持原样」，一句话把落位说清楚。
二是**同一个页面上三个搜索框长得不一样**：联系人档是描边圆角 + 放大镜 + ✕ 的 `SearchField`，
路线 / 地点两档是浅灰实心、没有放大镜、清空还得自己画一枚文字按钮 —— 用户要按联系人那档对齐。

② **当前用户 / 业务流程是什么？** 派单员在「工作台 → 车辆管理 / 账户管理 / 司机管理（货主 / 批发商）」里挑分类、
在「地址与联系人」里按线路 / 联系人 / 地址三档查东西。这两件事都是**高频、反复做**的动作：
顶栏那一颗是进页面后第一眼要找的东西，搜索框是每换一档就要再看一眼的东西 —— 形状不一致会让人先愣一下再动手。

③ **哪个现有事实或能力会发生变化？** 只有**画在哪、画成什么样**：胶囊在三个页面从 `title` 移到 `actions`
（并补 12dp），另外两页一字不动；地址页三档搜索框从「一档 `SearchField` + 两档 `SoTextField` + 一枚自绘清空」
变成**同一个 `SearchField` 调用**（占位语按档不同）。搜索的匹配规则、过滤的数据、跳转的目标**一样都没变**。

④ **哪些东西明确不能变化？** ① 占位语文案：`搜线路：收货人 / 电话 / 地址` 这句被 `_tools/ai/_check_ai_guardrails.py:4085`、
`_tools/qa/_check_address_palette.py:37`、`_tools/qa/_check_input_rules.py` 三处钉着，一个字都没改；
② 地址页三处（地点 / 线路 / 联系人）的胶囊**一个像素都没动**；③ 联系人档的默认提示语仍来自共用件 `core/UserSearch.HINT`（不许各页各写一句）；
④ 搜索仍然是**本地过滤**（数据本来就在手上），没有变成一次网络往返；⑤ 三个选人抽屉（运费结算 / 派单账本 / 货主账本）与分类抽屉的宽度不受影响。

⑤ **这个变化属于 Core、Extension 还是 Infrastructure？** **Presentation**。改的全是 Compose 版式与组件选择：
调 `Modifier.padding`、把一段 UI 从 `title` 挪到 `actions`、把三种写法收敛成一个共用件调用。
既没有定义或修改任何核心事实（订单 / 账本 / 车辆 / 账号一个字没动），也没有新增接口、表、权限或审计。

⑥ **什么证据能够证明它完成？** ① 判据 `_tools/qa/_check_roster_cards.py`（**59 项**，新增第 3 节「顶栏分类胶囊的落位」六条）
与 `_tools/qa/_check_address_tabs.py`（**42 项**，第 3/4 节按新形态重写 + §4.4 规范断言）全绿；
② 反向验证 `_tools/qa/_reverse_verify_roster_cards.py`（**52 条**）与 `_tools/qa/_reverse_verify_address_tabs.py`（**26 条**）
把每一处改动逐条破坏一遍、都必须让对应判据翻红，且源码按字节还原；③ 模拟器 5554 上的六张截图（车辆页 / 账户页 / 货主池 / 地址页三档各一张）
亲眼看到胶囊右缘与卡片对齐、三档搜索框同一个形状；④ 全仓 `_check_all.py`（151 个检查）与 `backend/scripts/check_reachability.py` 全绿。
