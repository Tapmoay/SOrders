① **上传的商品照片今天一个字节都不处理**：相册里选什么就传什么（连"竖拍照片的 EXIF 方向"都不摆正、超 4MB 的原图直接吃后端一句拒绝）。用户 m01280：「上传的商品照片是可以**自定义裁切**的啊，这个要注意一点。」—— 拍商品时背景里总有案板、秤、别人的货，而商品卡 / 选品行 / 订单行上的图位全是 `ContentScale.Crop`（只按控件形状硬裁显示），构图中心不可控：同一张照片在 168dp 方框里和在 56dp 圆角里"看到的"根本不是一回事。

② 今天的链路（逐行核过）：`ProductFormScreen.kt:94-106` 用 `ActivityResultContracts.GetContent()` 选图 → 把相册原图**原样**拷进 `context.cacheDir/product_img_<System.currentTimeMillis()>.jpg`（⚠️ 后缀写死 `.jpg`，HEIC / PNG 进来也叫 .jpg）→ `vm.pickImage(path)`（`ProductFormViewModel.kt:167-170` 只存路径）→ 保存时 `uploadIfPicked` → `POST /api/v1/products/{id}/image`（`backend/app/api/v1/products.py:296-346`）**只做两件事**：`read_limited(file, MAX_IMAGE_BYTES, detail="图片过大（最大 4MB）")` ＋ 前 32 字节嗅探类型（JPG/PNG/WebP/BMP），然后按扩展名落盘 `uploads/products/<id>/<uuid>.<ext>` ⇒ **服务端零图像处理**。全库唯一一条位图流水线是 `util/Watermark.kt`（EXIF 摆正 → 缩到长边 ≤2560 → 画水印 → JPEG 85），它只服务送达照与地点照片，商品图这条路上一次都没用过。

③ 变化：商品表单**选完图多一步「自由框选裁切」**（＝手机相册那种：拖四角 / 四边改大小、拖框内移动），确认后交出去的是**裁出来的那一张**；表单上还能对**当前这张图**再来一次「裁切」（对已经裁过的再裁一遍）。连带两件事：① **上传前按 EXIF 摆正**（竖拍照片不再横着传上去）；② **压缩由 App 自动做**（长边 ≤2560、JPEG 85 —— 用户 m01347 明确：压缩不给用户选项）。⛔ 老图**不批量重裁、不迁移、不回填**。

④ 不能变：后端与端点（仍是 `POST /products/{id}/image`、仍限 4MB、**仍然零图像处理**）；上传时机与上传路径（仍是"保存时才传"、仍是 `uploadIfPicked(id, path)`，一个字不改）；商品编辑页那颗 168dp 图**点下去仍是「重新选图」**（m01532：「商品的编辑页面是重新选图的，它不是查看图片的」）；`ui/common/ImagePreview.kt` 那份唯一预览弹层；`ProductThumb` 零件的画法；`ProductFormViewModel.changed()` 的"只发改动的键"差集（裁切只是**换掉 `imageLocal` 指的那个文件**，不新增任何可比较字段）。

⑤ **PRESENTATION**（客户端呈现层）＋ 一个**共用零件**（`util/ImageOps.kt`：摆正 / 缩放 / 裁切 / 输出）。它不定义任何核心事实（上传的仍是一张 JPEG、仍落在同一列 `products.image_url`）、不改任何不变量、删掉后 Core 照旧成立。

⑥ 证据：判据 `python _tools/qa/_check_image_crop.py`（新建：位图流水线只有一份 / 摆正在裁之前 / 自由框选几何是纯函数 / 老图不迁移 / 编辑页点图仍是重新选图）＋ 反向验证 `python _tools/qa/_reverse_verify_image_crop.py`（新建：去掉裁切 / 拿未摆正的位图去裁 / 让"不裁切"绕过压缩 / 给老图加批量入口 ……每条都必须红）＋ 纯函数单测 `ImageCropGeometryTest` ＋ `gradle :app:compileEmuDebugKotlin :app:testEmuDebugUnitTest` ＋ 全量 `python _tools/qa/_check_all.py` ＋ `python backend/scripts/check_reachability.py` ＋ **真机 emulator-5554 截图**（选一张竖拍照 → 裁 → 保存 → 商品列表 / 详情看到的正是裁后构图）。

## ④ Behavior Contract

```text
Input          ① 商品表单里从相册选一张图（GetContent）；
               ② 已有图（本地新选的 / 服务端那张）时，点表单上那颗「裁切」。
Output         全屏裁切层：图先按 EXIF 摆正、按 fit 铺满视口；自由裁切框（拖四角 / 四边改大小、拖框内移动、
               框外拖动改图片位置）＋ 框外压暗；底部三颗（选图那档）「取消 / 不裁切 / 完成」，
               重裁那档两颗「不裁切 / 完成」。
               完成 → 把框换算成原图的像素矩形 → 在「已摆正 + 长边 ≤2560」的位图上裁下来 →
               存成一张新 JPEG（quality 85）到 cacheDir → 交给 VM（保存时才上传）。
Success        上传出去的就是用户在框里看到的那块构图；文件从"原图可能好几 MB"变成"长边 ≤2560 的 JPEG"。
Failure        读图失败 → 表单上「图片读取失败，请重试」，**不改变**原来那张图（不产生半成品事实）；
               裁切层取消 → 什么都不改（原来那张图还在）；写盘失败 → 同上，不留半个文件。
Boundary Cases 框拖到极小 → 不小于 48dp（原图侧至少 1 像素）；框拖出图片范围 → 夹回图内；
               不裁切（allowNoCrop）→ 仍走一次「摆正 + 缩放 + JPEG 85」再交出去（m01347：摆正与压缩恒做）；
               重裁一张已经裁好的图 → 与新图同一条路（可反复裁）；
               竖拍照片（EXIF ROTATE_90/270）→ 看到的与裁出来的都是摆正后的方向。
Side Effects   只写 cacheDir 里的临时文件（product_src_*.jpg 源 / product_img_*.jpg 结果）；
               裁切与保存之间**不发任何网络请求**（上传仍只发生在点「保存」时）。
Authorization  不适用：图片上传仍走既有端点与既有权限（进这一页的权限就是商品管理那条），本次不新建权限点。
Compatibility  Compatible（后端 / API / DTO / 表结构一个字不动；未升级的旧 APK 照旧"原图直传"）。
```

## ⑥ CHG 专章

### Before

商品表单里点那张 168dp 的图 → 相册 → 选一张 → **App 把原图一个字节不改地拷进 `cacheDir/product_img_<millis>.jpg`**（连 EXIF 方向都不摆正，竖拍照片在表单里就是躺着的）→ 点「保存」→ 原图整个 POST 上去。想要构图好看只有两条路：① 在相册里先裁好再选（App 管不着，用户也不一定会）；② 换一张重拍。若是 6MB 的原图，还会被后端一句「图片过大（最大 4MB）」挡回来 —— 而**压缩这件事 App 本来就会做**（`util/Watermark.kt` 给送达照做的就是摆正 → 缩到长边 2560 → JPEG 85），只是商品图这条路上一次都没走过。

### After

同一个动作：**选完图先摆正，再让用户自由框选**（拖四角 / 四边改大小、拖框内移动、框外拖动挪图；框外压暗，看到的即为所得）→ 点「完成」→ App 在**已摆正、长边 ≤2560** 的那张位图上裁下框里那一块，存成一张新 JPEG → 表单上显示的就是裁后这张 → 保存时才上传。不想裁就点「不裁切」：**仍然摆正 + 压缩**（用户 m01347 ②：「可以加一个上传前的摆正；压缩就不需要了 —— 压缩是我们自动给它压缩的」）。已经上传过的图：点表单上那颗「裁切」就能**对当前这张（含裁过的）再裁一遍**（m01347 ④：「它可以重新裁切、也可以选择不裁切」）；⛔ 列表层没有批量重裁入口，老图也不会被自动动一下。

```text
- 历史图片文件与 products.image_url（本次不做迁移、不回填、不重写任何已上传的图）
- 后端 / 端点 / DTO / 表结构（仍是 POST /products/{id}/image，仍限 4MB，仍零图像处理）

- 位图流水线只有一份（摆正 / 缩放 / 输出在 util/ImageOps.kt，Watermark 调它）
- ProductFormViewModel.changed() 的差集语义（裁切不新增可比较字段）
```
