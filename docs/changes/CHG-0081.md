## ④ Behavior Contract

**动作：司机在「任务列表」的订单卡片最底下点「确认接单」**
- Input：`order`（`status in OrderStatusModel.ACKABLE`，今天 = `DISPATCHED`）＋ 当前在「待处理」档（`vm.ordersTab == 0`）＋ `!order.isNewForDriver`（后端 `is_new_for_driver` 派生的"新任务"标为假 —— 刚推来还没被看过的单先不摆按钮，避免"手指正落在它上面"时被点掉）。
- Output：成功 = 本地把列表里那一条**换成响应里那条完整订单**（`OrderDto`，`POST /orders/{id}/driver-ack` 返回 `OrderOut`）⇒ 卡片就地变「已接单」、「新任务」标与那颗按钮一起消失（`is_new_for_driver` 变假）、提醒音**当场停**、再喊一次 `realtimeHub.notifyOrdersChanged()`。
- Success：一步接单；页面不跳走（司机留在列表上，接着看下一张）。
- Failure：`ackError` 记下后端那句中文（`ValueError` → **400**：撞上已被撤销/撤回/别人接过 ⇒「这张单刚刚被改过（可能已被撤销/撤回/别人接过），请刷新后看看当前状态」；非司机 ⇒ 403「无权操作」）＋ `ackErrorOrderId` 记住是哪一张 ＋ **再拉一次列表**（那句话说的就是"现状已经变了"）。⛔ **不发生**的事：不改任何本地状态到"已接单"（失败时列表由 `load()` 重新说了算）、不产生半成品事实、**不把整张列表顶掉**（错画在那一张卡上）。
- Boundary Cases：① 同一张卡连点两下——第一下之后 `ackingOrderId != null` ⇒ **所有**卡都置灰（第二下根本点不到），后端那侧还有 CAS 兜底（重复点必然 400）；② 两个不同的司机同时接同一张单——后到的那个收 400，卡片上出现那句中文、列表刷新后那张单不再是"可接"（`is_new_for_driver` / `status` 由后端说了算）；③ 单刚被撤回/撤销——同上（400 ＋ 刷新）；④ 网断了——`ackError` 只写那句网络错，**不 `load()`**（列表还准，重连重试即可）；⑤ 提醒音正在响时接单——**立刻停**。
- Side Effects：一次 `POST /orders/{id}/driver-ack`；后端自己 `outbox.enqueue("orders.driver_acked")` ⇒ 推给**货主**与**派单员**（本单不改这一层，司机这一端只负责本地替换那一条）；本地停播报 ＋ 喊一次刷新。
- Authorization：不变（沿用既有端点与既有鉴权：`require_driver` ⇒ 非司机 403；司机只能接**派给自己**的单 —— `accept_order` 的条件 UPDATE 带 `Order.driver_id == driver.id`）。
- Compatibility：**Compatible**（没有接口、没有存储格式、没有老对话；详情页那颗按钮与整条链路一行未改）。

## ⑥ CHG 专章

### Before

司机在「任务列表」看到一张派给自己的单：卡片上**只有**「点进详情」这一个动作。要接单得 点卡 → 进订单详情 → 滑到页面底部 → 点那颗绿底「确认接单」→ 再返回列表。一屏三四张单的时候，这件事每张单都要走一遍完整来回。

### After

同一张卡：**最底下多了一整行绿色「确认接单」**（整宽 56dp、`Icons.Default.CheckCircle`、白字 `titleSmall` —— 与详情页那颗同一套颜色与图标），点一下就地接单：
- 卡片那一条换成响应里的完整订单 ⇒ 卡片显示「已接单」、「新任务」标消失、**那颗按钮自己消失**（闸门 `!order.isNewForDriver` 变假）；
- 提醒音当场停（`container.newOrderPlayer.stop()`）；
- 页面**不跳走**，司机接着看下一张；
- 点卡片本身**仍然**进详情页（老入口一个字未动）。

条件只有三条，全在调用点上：`vm.ordersTab == 0`（只在「待处理」档）、`order.status in OrderStatusModel.ACKABLE`、`!order.isNewForDriver`。⛔ **其它三张列表一个像素都没变**：`bottomAction` 默认是空 lambda，`OrderCard` 自己不判角色、不判状态 —— 谁能用这个槽由**调用方**决定。

**为什么另开一个槽、不塞进 `extra`**：`extra` 是 §4.2c 那种「卡片动作」——**并列的多个小图标**（右上角、圈底），管的是"这张单还能拿它怎么办"；用户要的是"**现在就该做的那一件事**"，要求整宽、一眼看到、整只手按得着。塞进 `extra` 会变成右上角一颗小图标，与"方便"正好相反。这一条已写进 `ui/common/OrderCard.kt` 的 KDoc 与设计系统 **§4.2d**（新增小节）。

**失败为什么画在卡上、不画在页面级 `error`**：`DriverOrdersViewModel.error` 被渲染门 `vm.error != null -> ErrorView(...)` 拿去**顶掉整个列表**（设计系统 §4.8「错误的落点」：页面级的错只管"这一页没加载出来"）。接单失败是**这一张单**的事 —— 一句话 ＋ `ackErrorOrderId` 过滤，就画在那一张卡上，别的单照旧能看、能接。

**⚠️ 顺带修掉一条既有判据的误报**：`_tools/qa/_check_driver_tab_highlight.py` 里那条 `highlight = vm\.ordersTab == 0\)` 盯的是**右括号** —— 调用点从单行改成多行具名参数之后，`0)` 变成了 `0,` ⇒ 判据**误报**（实测真的红了）。改成 `highlight = vm\.ordersTab == 0\b`（并加注释说明原因），17/17 复绿。**教训**：正则钉到括号上，等于把"排版"也钉进了判据。
