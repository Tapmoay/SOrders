① 这一页有四个毛病，**都是画法**，功能上却都能用 —— 所以只有对照规范才看得出来：

1. **表单是居中弹窗**。`AlertDialog` + 三个自己摆的 `SoTextField`（名称 / 电话 / 备注）。规范 :1266-1269 的原话是
   「他**不要使用弹窗**啊，**使用底部抽屉**，并且**底部抽屉是拉到最上面**」—— 字段一多，居中弹窗就变成"小框里滚"，
   键盘一弹起来更只剩一条缝。同类的账号编辑（CHG-0018）、车辆编辑（CHG-0017）都已经搬进抽屉了，只有这一页还留着。
2. **卡片动作是两把裸图标**。`IconButton(onClick = onEdit) { Icon(Icons.Default.Edit, …, Modifier.size(18.dp)) }`
   与它旁边那个裸垃圾桶 —— 正是 §4.2c 与用户原话一起否掉的那种画法（「他就是一个**笔**啊，**这个不行**啊，
   他要一个图标啊，**稍微圈一下**」）。而且位置是"编辑在左、删除在右"：规范要求**编辑一定在最右**（惯用手是右手）、
   **相反 / 警示类在最左**。
3. **删了就没法回头**。这一页的删除是真软删（后端把 `is_deleted` 置真、名字改成 `xxx_del{id}` 把唯一名释放出来），
   而且**后端早就有 `restore` 端点**（`backend/app/api/v1/arrears.py:221`，还能把名字改回去）—— 但界面上没有入口：
   删错了只能去数据库里救。规范 :1328 / :1371 那条「**删除一律软删 + 手边要有撤回**」是需求方定的硬规矩，
   这一页是几个管理页里唯一没做到的。
4. **卡头用的是"这个 App 的主色"而不是"这一块的颜色"**。`MaterialTheme.colorScheme.primaryContainer` 蓝；
   这一页的模块色是橙红 `ArrearsTangerine`（工作台「挂账单位」那一格也是它，规范 §2 模块色表）。
   顺带一个对比度问题：白字压在 `#FF6B2C` 上只有 **2.84:1**（不过 AA），所以保存键要用深棕字 ——
   跟 CHG-0016 给黄绿配 `OnDriverLime`（白字 1.4:1 → 深橄榄 ≈8:1）是同一个路子。

② 派单员进「工作台 → 挂账单位」→ 这一页回答的是"哪些单位的账挂在我这儿"（名字 / 电话 / 备注）→
需要时**新增一个、改一个、删掉一个**。这一页用得不多，但每次用都是"要立刻做完"（结算前补一个单位、
发现名字写错了改一下），所以三件事都必须在一屏内做完，别让人再跳一层页面。

③ 变化的只有**画法与错误归属**：表单画在哪、动作长什么样、错画在页面级还是表单级。
新增的能力是"删除之后手边有一行「已删除「X」+ 撤销」"，而它调的是**本来就在**的后端能力
（`POST /api/v1/arrears/units/{unit_id}/restore`）。

④ 接口、DTO、权限（`LEDGER_EDIT`）、审计（`ARREARS_UNIT_DELETE` / `ARREARS_UNIT_RESTORE`）、迁移、
三条删除拦截话术、列表顺序、空状态的主意、页面入口 —— 一样都不动（见 ② 的 Must Not Change）。

⑤ **Presentation**。没有领域语义变化：账还是那些账，单位还是那些单位，只换画法。
唯一落到别处的是一个色 token（`ui/theme/Color.kt`），它是"这一页的配色"的一部分，不是共享语义。

⑥ 新判据 `_tools/qa/_check_arrears_units.py`（67 项）+ 反向验证 `_tools/qa/_reverse_verify_arrears_units.py`（28 条注入）

## ③ Boundary（Core / Extension / Infrastructure / Presentation）

**PRESENTATION**。判断依据：本批改的四件事 —— 表单画在弹窗里还是抽屉里、卡片动作长什么样、
删除之后那一行画在哪、校验的错挂在页面级还是表单级 —— 全都**只发生在渲染层**：
后端不知道界面把表单画在哪，DTO 里没有"抽屉"这个概念，权限模型也不关心"撤销"这一行在不在屏幕第一屏。
反向说：把这些规矩下沉到任何一层边界都是无处安放的（那一层根本不参与渲染），所以只能留在 Presentation，
由对照规范的设计判据来守。

唯一一处"离开页面"的改动是 `ui/theme/Color.kt` 里新增一个色 token —— 它属于 UI 主题层（不是领域语义色，
是"这一页橙红底上该用什么字色"），与既有 `OnDriverLime`（CHG-0016）同一层级、同一路子。

## ⑤ Data Contract

**没有数据变化。** 请求体 / 响应体 / 表结构 / 迁移 / 权限位 / 审计动作一行未动：

- 新增走 `POST /api/v1/arrears/units`（`ArrearsUnitCreateRequest(name, phone, remark)`）；
- 编辑走 `PATCH /api/v1/arrears/units/{id}`（`ArrearsUnitUpdateRequest`）；
- 删除走 `DELETE /api/v1/arrears/units/{id}`（软删 + 写 `ARREARS_UNIT_DELETE`）；
- 撤销走 `POST /api/v1/arrears/units/{id}/restore`（把名字从 `xxx_del{id}` 改回去 + 写 `ARREARS_UNIT_RESTORE`）；
- 客户端唯一新增的"数据"是一个颜色常量 `OnArrearsTangerine = 0xFF2B1200L`，它不进任何请求。

前端那次"删空之后还要留住撤回行"的判断，靠的是 VM 里的 `recentlyDeleted`（内存态，页面一关就没了）——
这是有意的：**撤回的意思是"我手滑了"，不是"最近删除文件夹"**，所以只记**一条**。
