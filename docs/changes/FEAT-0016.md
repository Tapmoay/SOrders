## ① 六问

```text
① 解决什么问题？  用户原话（ref m00879 paraphrase 之后的追问）：「还有 ai 那边也要有这样子的作用，
                  不仅开了一个批量操作吗？他可以直接接管这个操作」。也就是：AI 必须能设「固价」。
② 当前流程是什么？ AI 的商品动作有 建/改/上下架/删/恢复/按表格批量建 —— **唯独没有**折扣口径那一条；
                  `products.update` 的可改字段白名单里也没有 no_discount。
③ 哪个现有事实会变？只有「AI 能做的事」多一件；数据语义、折扣算法、接口都没变。
④ 哪些明确不能变？ ① 不新增端点、不改后端；② ⛔ 卡片文案不许写成「价格锁死/不能改价」
                  （语义只有一条：算折扣时跳过它）；③ 已打过的折不回溯；④ 走既有的确认卡与撤回机制。
⑤ 属于哪一层？    Extension（AI 动作表 + 一个 crud 规格），核心零改动。
⑥ 什么证据能证明完成？`AiWriteTest` 两条新单测 + 动作数棘轮 175→176（留日期与编号）+
                  判据 28 项与反验 7 条（与 CHG-0109 共用一份判据：两个入口一起钉）。
```

## ③ Boundary（Core / Extension / Infrastructure / Presentation）

走**扩展点**：AI 动作是声明式的（`crud(...)` 一个块 + 资源表一行 + 常量一行），
执行仍然落到既有写端点 `PATCH /products/{id}`。核心（钱 / 状态机 / 权限）零改动。

## ④ Behavior Contract

- 用户说「把红富士苹果设成固价」/「这几个商品不参与打折」→ AI 出**确认卡**（风险 MEDIUM，和「设批发商专属价」同档）；
- 卡片必须写清：整单折扣会**自动跳过**它 / 只打勾选几行时它**不能被勾**（后端会拒并点名）/
  ⛔ **价格照旧可以改** / **已经打过的折不回溯**；
- 确认后调既有 `PATCH /products/{id}`，body 只带 `no_discount`；
- 撤回：走既有的商品撤回机制（资源表里登记为 `update`，payload 键就是后端字段名）；
- 「恢复打折」= `no_discount=false`，卡片写明「和别的商品一样照常参与」。

## ⑤ Data Contract

- 请求体：`{"no_discount": true|false}`；出参沿用 `ProductOut.no_discount`；
- ⛔ 不写成本价、不动价格字段；不新增审计码（走既有的商品更新留痕）。
