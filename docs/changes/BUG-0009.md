## ① 六问

**1. 现象是什么？**
- 货主端的「地点」列表里有一张卡，名字和地址都是 `??????`（六个半角问号）。
- 同一张表相邻两行（id=93「惠州市惠阳区验证路 1 号」、id=95「仲恺区惠风东三路40号 8栋1366室」）都是正常中文 ⇒ **不是全局编码问题，也不是这一列坏了**。
- 同名脏数据只在两处：`shipper_locations` id=94 与 `orders` id=426（`address_detail` 六个问号 / `delivery_description` 七个 / `contact_dongjia_name` 五个）。全库再无第三处。

**2. 根因在哪？**
- 同一单里**从库里挑的**东西完好（`order_products` id=915 的 `product_name_snapshot` 是 `赣南脐橙`、`unit_snapshot` 是 `袋`），**手输的自由文本**才是问号；`contact_dongjia_phone=13800001111` 这种 ASCII 也完好。
- 问号恰好是「用装不下汉字的编码去编码」时的**默认替换字符**。三串长度各不相同（6 / 7 / 5 个字符），是**逐字符**被替换掉的 ⇒ 损坏发生在**数据离开客户端之前 / 输入环节**，不是存储、不是传输、不是显示。
- 客户端与服务端全仓**没有任何「把汉字换成问号」的实现**：`android/app/src/main` 里字符字面量 `?` 零命中、`US-ASCII` / `Charsets.ISO` / `replace(..., "?")` 零命中；后端唯一的 ASCII 替换在 `backend/app/services/ledger_export.py:127-130 _ascii_cell`（`s.encode("ascii", "replace").decode("ascii")`），只用于导出 Excel（`:137` 自注「所有中文换成 `?`」）。
- **当年是人工填的还是 AI 助手代填的，已经分辨不出来了**：`operation_logs.origin` 列 2026-09-25 才随迁移 004 落地（`backend/app/core/client_origin.py` / `android/.../core/ClientOrigin.kt`），而 order 426 建于 2026-09-21 ⇒ 那一年的审计行一律 `human`；设备上的 AI 会话记录（`context.filesDir/ai_conversations.json`）已随 BUG-0008 取证时的 `pm clear` 消失。用户提示的 AI 路径**确实能写出这三个字段**（`android/.../ai/AiWriteOrderHandlers.kt:542-560` 取 `address` / `phoneDongjia` / `nameDongjia`，`:619/:624/:625/:626` 写进 payload），但人工建单那条路写的是**同一批字段**。
- ⇒ 收口点不是"哪条路"，而是**这些字段本身**：写进来之前先问一句「这串字是人看得见的字吗」。

**3. 为什么以前没修？**
- `docs/RECTIFICATION_REPORT_E2E.md:118-123` §5.1 的 P6 判词是「库里存的就是六个问号本身，写入端把编码丢成 `?`，显示端无责」，建议并记为**不修**（只提议"将来在写入端加校验并清掉 id=94"，且声明删数据要用户确认）。
- 这一轮把它从"记着"变成"拦住"：历史行仍不动，新写入一律拦。

**4. 这次改到什么程度？**
- 新增**唯一**判据 `backend/app/core/text_guard.py`：不可显示字符（`U+FFFD`、孤立代理项、除制表/换行外的 C0/C1）与**整串只有问号**（半角 `?` / 全角 `？`）一律拒收，`raise ValueError(中文句子)`。
- 6 个入参模型挂名单（Order / Address / Location / Contact 的 Create 与 Update，共 ≥20 个字段），`identify_error` 也过同一道闸 —— 建地点与改共享地址说**同一句话**。
- **不碰历史数据**：id=94 与 order 426 一行不改（要清得用户确认）。

**5. 怎么证明改对了？**
- 判据 `_tools/qa/_check_unshowable_text_guard.py`（四节 **67 项**）＋ 反验注入脚本（**17 条**）逐条证明"判据能判红"；13 例回归钉住行为；全量后端套件、全量静检与 AI 红线都不新增红。

**6. 不许动什么？**
- **正常文字里夹着的问号**（`幸福路 1 号？`、`门牌???`）必须照旧放行 —— 收紧成"含连续问号就拒"会误伤真实表达。
- **长度与空白**仍归 `place_service._clean` 与各 schema 的 `max_length`（`schemas/text.py` 是长度上限的唯一来源）；手机号 / 金额 / 日期那些字段有各自的类型规则，**不走这里**。
- **脏行必须还能改**：id=94 这种历史行，用户把名字改成正常内容时要能存进去（闸只拦"整串还是问号"的提交）。

## ② Must Change / Must Not Change

### Must Change
- 判据落一处：`backend/app/core/text_guard.py` 的 `find` / `ensure` 是纯函数（不依赖 FastAPI、不依赖 Pydantic），别处不许再抄第二份。
- 闸挂到入参上：`backend/app/schemas/text.py` 的 `ShowableModel`（`SHOWABLE_FIELDS: ClassVar[tuple[str, ...]]` ＋ `@model_validator(mode="after")`）被 6 个模型继承并声明名单。
- 服务层同闸：`place_service.identify_error` 先 `text_guard.find` 再看 `NO_NAME_TEXT`，建与改走同一条判词。
- 字段中文名：`validation_errors.FIELD_CN` 补 `contact_dongjia_name`（货主姓名）/ `contact_boss_name`（老板姓名）/ `contact_name`（联系人姓名），用户看到的是中文，不是英文 key。
- 文案不许拼在函数里：两句都是模块级常量（`BAD_CHAR_TEXT` / `ONLY_MARKS_TEXT`），带 `{field}` 占位。
- 连带放宽一处既有红线的**正则**（判据意思不变）：`_tools/ai/_check_ai_guardrails.py` §27「地址/订单的 lat/lng 都接上了」原来要求字面量 `(GeoInput)`，而这一层混入让 4 个模型的基类列表变成 `(ShowableModel, GeoInput)` ⇒ 放宽成"基类列表里可以有别的基类、但必须真的继承 `GeoInput`"（`r"\((?:[A-Za-z_]\w*,\s*)*GeoInput(?:\s*,\s*[A-Za-z_]\w*)*\)"`），并在那一行留了注释说明原因。

### Must Not Change
- 历史数据：`shipper_locations` id=94、`orders` id=426 一字不改；本轮不做任何 UPDATE / DELETE。
- 正常文字（含问号、含制表/换行）与空串 / `None` 的既有行为；必填规则仍在各 schema 自己那里。
- 长度上限（`schemas/text.py`）与空白清洗（`place_service._clean`）的职责边界。
- 手机号 / 金额 / 日期 / 坐标等非自由文本字段的既有校验。
- Android 端：**零改动**（错误文案由服务端 422 的 `detail` 原样透传，端上既有错误提示链路不变）。

## ④ Behavior Contract

| 输入 | 行为 |
| --- | --- |
| 自由文本字段（名单内）整串去掉首尾空白后只有 `?` / `？`（中间可夹空白） | **422**，`detail` 为 `「<字段中文名>」里只有问号，这像是占位符或者编码出错留下的，请填写真实内容` |
| 自由文本字段含 `U+FFFD` / 孤立代理项 / 除 `\t` `\n` `\r` 外的 C0·C1 控制字符 | **422**，`detail` 为 `「<字段中文名>」里有看不见的字符（复制、粘贴或编码出错时会带上这种字符），请删掉后重新填写` |
| 正常文字里夹着问号（`门牌???`、`幸福路 1 号？`） | 照旧写入 |
| 常见空白（制表 / 换行）与空串 / `None` | 照旧（"没填"归各 schema 的必填规则） |
| 名单外的字段（手机号 / 金额 / 日期 / 坐标……） | 完全不受影响 |
| 已存在的老脏行（如 id=94） | 仍可**逐字段**改成正常内容；只要新值不是"整串问号"就存得进去 |

字段中文名的兜底：`FIELD_CN` 查不到就用字段名本身（`validation_errors._field_label`），所以漏配一个键不会 500，只会看到英文 key。
