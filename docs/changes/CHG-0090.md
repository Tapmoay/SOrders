① 非派单角色（货主）装好 App、进「设置 → AI 能用的能力」，看到的是「改数据（需你确认）」**关着**；于是他说「把这一单的收货人电话改一下」，助手照实回「写操作现在全部没开」。这**不是**权限问题（他有 `orders.update_contact` 的权限、货主动作白名单里也有），只是默认值替他做了「先别开」的决定 —— 而用户 2026-10-09 的口径是「所有功能的 AI 所有功能默认是开的」。

② 当前流程：默认值这条线走三个地方 —— `AiKeyStore.enabledTools()`（首装读默认值）、`AiKeyStore.resolveEnabledTools(saved, seenAtSave)`（用户存过之后，把「保存之后新出现的工具」补上）、设置页 `AiSettingsViewModel`（显示开关状态）。三条都必须用**同一个判据**，否则会出现「开关显示关着、其实能用」。

③ 会变化的事实：首装默认集（`defaultEnabledTools()` 不再收角色，非派单角色也含 `AiTools.PREVIEW_WRITE`）＋「升级之后新出现的工具」对非派单角色也自动开（`resolveEnabledTools` 不再减 `optInExclusion(role)`）＋ 单测里那两条按角色的断言（合成一条「默认全开、与角色无关」）。

④ 明确不能变的：**成本开关**（`defaultCostVisible(role) = role == AiRole.DISPATCHER`）照旧按角色 —— 那是「数据外发」决定，不在这次口径里；货主 / 司机的**动作白名单**（`AiWrites.SHIPPER_ACTIONS` fail-closed、司机端没有 AI 入口）；确认卡那道闸（`preview_write` 只是**申请**，真写要用户点确认）；「用户主动关掉的开关不许被重新打开」（`resolveEnabledTools` 那条 fail-safe 原样保留）；后端与数据库。

⑤ 这是 **Extension**：扩的是「AI 默认给谁开」这一层，不动 Core（权限点、端点、动作清单、确认卡）。

⑥ 证据：判据 `_tools/ai/_check_ai_guardrails.py`（**1327 项**，2d-8 段已随动：`OPT_IN_TOOLS` / `optInExclusion` 必须**不存在**、三个调用点都不再传角色）＋ 单测 **1361 / 0 failed / 2 skipped**（94 个类；基线 1362 ⇒ **−1**：`AiEndpointRulesTest` 那两条按角色的用例合成一条）＋ 真机：货主设备（`emulator-5556`，`--fresh` 重装）首装进设置页，「改数据（需你确认）」是**开**的（截图 `shots/61_shipper_write_tool_default_on.png`），并且当场说一句话能出确认卡（截图 `shots/62_shipper_write_card_after_default_on.png`）。

## ③ Boundary（边界：为什么这件事不该在代码边界以外解决）

结论：**这是一条默认值的口径变更，只能落在 `AiKeyStore` 的纯函数上**，不能靠「发个通知让大家自己去开」或「让模型自己解释」。

五问依据：

1. **用户侧**：他已经明说了默认值该是什么（「所有功能的 AI 所有功能默认是开的」）；让他一个个去设置页开，等于把系统该做的决定推给人。
2. **代码侧**：默认值本来就收在纯函数里（`defaultEnabledTools()` / `resolveEnabledTools`），改它是一处；三个调用点跟着去参数即可 —— 不需要新字段 / 新端点 / 新开关。
3. **重复侧**：设置页与运行时用的是**同一个** `AiKeyStore`；改完两处仍然同源（判据钉「两个调用点都不再传角色」）。
4. **风险侧**：把「能改数据的工具」默认开，风险由**确认卡**兜着（`preview_write` 只是申请，真写要他点一下），并且货主 / 司机能做的动作仍由白名单限死 —— 开关开着 ≠ 他有那个动作。
5. **能力侧**：首装即用的体验是这条口径的全部目的；留一个「货主先自己去找开关」的尾巴，就不算落地。

**核心改动声明**：**无**。（`_tools/qa/_core_files.txt` 里 AI 只有 `ai/AiWriteService.kt` 一行，本单没碰它；改的是 `ai/AiKeyStore.kt` / `ai/AiContainer.kt` / `ui/ai/AiSettingsViewModel.kt` / `ai/AiTools.kt`（注释）与测试。）

```text
  - 不开任何权限：动作能不能做仍由后端权限点 + SHIPPER_ACTIONS 白名单决定。
Compatibility:
  - 覆盖 2026-09-20「派单员全开、其余角色除写工具外全开」那条旧口径（V3 §20.5 第 2 条已改写并写明"原先它是 OPT_IN_TOOLS 里唯一那个必须自己打开的工具"）；
  - 单测条数 1362 → 1361（两条按角色的用例合成一条），不是"删了覆盖"，新用例断言更强：
    assertEquals(all, AiKeyStore.defaultEnabledTools()) ＋ AiTools.PREVIEW_WRITE in all。
```
