① **系统里一张发票都没有，而「这个月要交多少税」在界面上无处可问**：(a) 结算单上那个 `invoiced` 布尔（`backend/app/models/shipper_receipt.py:25`，`Boolean, default=False`）**没有任何落点** —— 把它勾上既不能反查是哪张票，也不进任何报表；(b) 利润表那一格今天恒为 0（`backend/app/services/reports/profit_query.py:102` 写着 `tax_total = _ZERO`，`:103` 的恒等式里它一直是个 0 项），口径说明里如实写着「税没有数据源」（折旧已由 FEAT-0012 接上，税是最后一块）；(c) 进项这一侧完全没有连线：上一期刚做完的采购单（`purchase_orders`）能回答「这批货进了多少、成本多少、欠供应商多少」，却回答不了**「这批货有没有票」**；(d) 开销表里今天 40 笔、8 个分类（过路 / 其他 / 加油 / 停车 / 保险 / 维修 / 罚款 / 货损），**没有一笔分类名带「税」** —— 「税金及附加」连手工账都没有落点。设计稿早就画出这一期（`docs/ACCOUNTING_V2_DESIGN.md:333-352` 的 `invoices` 表结构与 P3 税汇口径、`:442-443` 的阶段表、`docs/IMPLEMENTATION_PLAN_ACCOUNTING_V2.md:130-131`），一直没人做。
② **当前流程（用户在界面上怎么做）**：想知道「这个月要交多少增值税」→ 翻纸质发票 / 开票系统，手工加总销项再手工减进项；想知道「这张进货单有没有票」→ 看单据外面夹的纸；想记一张票 → 系统里没有任何地方能记（结算单那个「已开票」勾了也只是一行布尔，勾完仍然是孤立事实）。全流程都在系统外面发生，系统里看不到一分钱税。
③ **会变化的事实/能力**：(a) 新增一张凭证级台账 `invoices`（迁移 020，销项 / 进项共用一张表：`direction` 分方向、`amount` 价税合计、`tax_rate` 税率、`tax_amount` 税额，状态 `REGISTERED → ISSUED → VOIDED`）；(b) 新增两张关联表：进项票 ↔ 采购单（多对多，供应商必须一致）、销项票 ↔ 账本条目 `ledgers`（多对多，客户必须一致 —— 票开的是这个客户名下的哪几笔应收）；(c) 利润表新增三个只读字段 `vat_output` / `vat_input` / `vat_payable`（窗口内**算进税汇**的发票的销项税额 − 进项税额：活着 + 没作废 + 税率非空都算，REGISTERED 与 ISSUED 一视同仁，作废与未税不算 —— 与税账页同一个判据 `tax_service.counts_in_tax`），`vat_payable` **单列一行、不进营业利润**（增值税是价外税）；(d) 利润表「− 税」那一格（`tax_total`）改为取**开销里分类名含「税」的合计**（今天 0 笔 ⇒ 仍然是 0，但数据源已经接上），并且这部分**从期间费用里搬到税那一格**（搬家不改总额，`operating_profit` 与旧实现逐分相同）；(e) 报表中心新增第 10 格「税账」：窗口内按税率分组的销项 / 进项 / 应缴 ＋ 「登记中未开具 N 张」提示 ＋ 发票列表入口与导出 kind `tax-summary`。
④ **明确不能变**：利润表既有的六格取值与恒等式（`revenue_total → cost_total → gross_profit → delivery_cost → operating_expense_total → depreciation_total → operating_profit`）逐分不变 —— 本事项只做两件事：把「税」从期间费用里**搬家**、再加一行**不参与**恒等式的应交增值税；成本口径（`backend/app/services/cost_basis.py`）、欠款口径（`supplier_service.py` 的 Σ alive 应付 − Σ alive 付款）、库存不变量（`Σ(inventory_movements.change) == products.stock`）一个字节不改；`cash_flows` / `orders` / `ledgers` / `supplier_payables` / `purchase_orders` 的表结构与既有行为不动；采购单的建单/改单/撤行/撤销/恢复五条路径**结果不变**（只在删单前加一道闸，见 ② 与 ④ 的失败路径）；⛔ 不新建权限点（`backend/app/core/rbac.py` 的 `Permission` / `ROLE_PERMISSIONS` / `SCOPES` 一个字节不动）；⛔ 历史数据不回填：`shipper_receipts.invoiced` 保持原值、既不双写也不拿它当口径，过去没有票的期间不许凭空补票。
⑤ **归属**：EXTENSION IMPL ＋ PRESENTATION。发票是**新增的一类业务事实**（票号、税率、税额），但它不改变任何既有核心不变量 —— 它挂在既有事实上（采购单 / 账本条目），金额口径自成一套且**不回流**到毛利、成本、欠款任何一格（`vat_payable` 不进营业利润，`tax_total` 的搬家不改总额）；删掉发票台账与第 10 格，利润表回到「税那一格没有数据源」，其余照旧成立。
⑥ **证据**：判据 `_tools/qa/_check_tax_invoices.py` ＋ 反验 `_tools/qa/_reverse_verify_tax_invoices.py`（注入破坏必须报红）＋ `backend/tests/test_tax_invoices.py`（登记 / 开具 / 作废·冲红 / 恢复 / 关联校验 / 冻结规则 / 窗口边界）＋ 后端真实库探针 `_tools/qa/_probe_tax_invoices.py`（登记一张进项票挂到采购单上、开具、验税汇与利润表两处数字对得上、逐字节还原）＋ 模拟器 5554 真机截图（发票列表 / 登记表单 / 税账页 / 利润页新行）＋ 全量静检。详见 ⑦⑧。

## ③ Boundary（Core / Extension / Infrastructure / Presentation）

- **结论**：EXTENSION IMPL（发票台账与税汇这条路径）＋ PRESENTATION（报表中心第 10 格、发票页）
- **五问依据**（规范 §三）：
  - ① 是否定义核心事实？**否** —— 核心事实（订单、结算单、采购单、应付、库存流水、开销）都是既有的；发票是新增的一类业务事实，挂在它们上面，不重定义任何既有金额。
  - ② 是否改变核心不变量？**否** —— 毛利 / 欠款 / 库存三条不变量都不动；`tax_total` 只是从期间费用「搬家」（`operating_expense_total + tax_total` 前后相等），`vat_payable` 不进 `operating_profit`。
  - ③ 是否必须永久存在？**否** —— 发票台账是「要交多少税」的便利落点；没有它，老板照旧能手工加总（只是系统里看不见）。
  - ④ 是否可能出现多个实现？**否** —— 税额算法、状态机、税汇聚合只有 `backend/app/services/tax_service.py` 一处实现；报表只读层 `services/reports/tax_query.py` 只汇总、不重算。
  - ⑤ 删除后 Core 是否仍然成立？**是** —— 删掉三张表与第 10 格，发票历史随之消失，但订单 / 结算 / 采购 / 应付 / 利润表的其余六格一个数字都不变。
- **要改 Core 时的三问**：不适用：本事项的结论不含 CORE（不改任何核心不变量）。
- **核心改动声明行**（`docs/AI_WORK_CLAIM.md`「进行中」里已写）：`backend/app/models/enums.py`、`backend/app/models/__init__.py`、`backend/app/api/v1/router.py` —— 为什么必须动核心：发票的四个写动作码必须进领域词表（审计覆盖与 AI 写闸门都是按词表逐值比对的），模型注册与路由挂载是接线文件；只**追加**，⛔ 既有取值一个都不改。

## ④ Behavior Contract

```text
Input          POST /api/v1/invoices {direction(OUTPUT|INPUT), invoice_no?, invoice_date,
               supplier_id?（进项必填：谁开的票）/ customer_id?（销项必填：开给谁）,
               amount(价税合计), tax_rate?（不填=未税、不参与税汇；填 3.00 = 3%）, tax_amount?（票面税额，不填按税率算）,
               purchase_order_ids?[]（进项 ≥1 张）, ledger_ids?[]（销项可选：账本条目）, note?}
Output         InvoiceOut（后端算出的 tax_amount、status、关联单据 id 与摘要、operator_id、created_at）
Success        201：一行票登记成功，状态 REGISTERED；关联表写入；税额由后端算出来（⛔ 界面不做乘法）
               POST /invoices/{id}/issue → ISSUED；POST /invoices/{id}/void → VOIDED（记 voided_from）；
               POST /invoices/{id}/restore → 回到 voided_from（撤销作废/冲红）
Failure        400 且**一个字都不改**：进项没挂任何采购单 / 挂的采购单供应商与票面往来单位不一致 /
               挂到已作废或已删除的采购单 / 销项挂了不属于该客户的账本条目 / 金额 ≤ 0 或超过两位小数 /
               税率为负或超过 100 / 同方向同票号重复（票号为空串不算重复）/
               改一张已开具（ISSUED）的票的金额或税率（要改先作废冲红、再登记一张新的）/
               作废一张已作废的票、恢复一张没作废的票 / 删一张挂着没作废进项票的采购单
Boundary Cases 税率 0.00（有票免税）：tax_amount = 0 且**参与**税汇；税率 null（未税）：tax_amount = null 且**不参与**税汇
               一张进项票挂多张采购单（合计对得上即可，供应商必须同一个）
               金额 0.01 / 极大值 / 恰好 1 分钱的四舍五入（ROUND_HALF_UP，税额 = amount − amount/(1+rate/100)）
               窗口边界：票面日期落在窗口首日 / 末日 / 窗口外一天；跨月两天各登记一张
               REGISTERED 与 ISSUED **都计入**税汇（算数与否只看「活着 + 没作废 + 税率非空」，状态不参与判断；报表另单列「登记中 N 张」只是提示，不是排除），VOIDED 与未税（`tax_rate = null`）不计入
Side Effects   写 operation_logs（登记 / 开具 / 作废 / 恢复各一条）；⛔ 不写 cash_flows、不写账本、不动结算单金额
Authorization  写：Permission.LEDGER_EDIT（与应付 / 付款同级）；只读：Permission.ORDER_DISPATCH（与利润表 / 成本覆盖同级）—— ⛔ 不新建权限点
Compatibility  Compatible：新增端点与新增只读字段；利润表 tax_total 的**数值**在「开销里没有带税分类」时逐分不变
```

## ⑤ Data Contract

- **新增/改动哪些字段**：三张新表（`invoices`：`direction` / `invoice_no` / `invoice_date` / `supplier_id` / `customer_id` / `amount` / `tax_rate` / `tax_amount` / `status` / `voided_from` / `void_reason` / `note` / `operator_id` ＋ 时间戳；`invoice_purchase_orders(invoice_id, purchase_order_id)`；`invoice_ledgers(invoice_id, ledger_id)`）。利润表输出加三个**只读、非持久化**字段 `vat_output` / `vat_input` / `vat_payable`。
- **Owner 是谁**：发票台账归账务/财务域（`docs/DOMAIN_BOUNDARIES.md` 里登记为「发票」这一族事实），对采购单与账本条目只做**只读引用**（不反向改写它们的任何列）。
- **什么时候写 / 什么时候不写**：只在登记 / 开具 / 作废·冲红 / 恢复这四个动作写；⛔ 不在下单、收款、进货、删除等路径上偷偷写票。
- **是否允许 NULL**：`tax_rate` 允许 NULL（=未税）；`tax_amount` 与 `tax_rate` 同为 NULL（⛔ 未税不许写成 0）；`invoice_no` 允许空串（还没拿到票号的登记）；`voided_from` / `void_reason` 只在作废时才有值。
- **历史数据怎么办**：**不回填**。`shipper_receipts.invoiced` 保持原值、不双写、不当口径；过去没有票的期间在税汇里就是 0（⛔ 不按现在的税率猜过去的税）。
- **迁移怎么做 / Rollback 怎么办**：`backend/app/migrations/020_invoices.py` 只建三张表 + 索引（含一条部分唯一索引：同方向同票号唯一、票号空串除外），⛔ 不回填、不改既有表；Rollback = drop 三张表，利润表回到 `tax_total` 恒 0、`vat_*` 字段消失，其余不动。
- **删除本功能后历史数据还能不能解释**：能 —— 发票行自带票号 / 日期 / 金额 / 税额与状态，删掉页面后它仍是一本自洽的台账（与本事项一起消失的只是「票 ↔ 单据」的连线）。

## ⑥ CHG 专章

### Before

利润表「− 税」那一格**恒为 0**（`backend/app/services/reports/profit_query.py:102`），口径说明里写「税没有数据源」；结算单上有个「已开票」布尔，勾了之后既不能反查票号、也不进任何报表；想知道「这批货有没有票」只能看纸；想知道「这个月要交多少增值税」只能手工加总——系统里一分钱税都看不见。

### After

发票列表页能登记一张票（选方向、选往来单位、填价税合计与税率，税额由后端算），进项票挂到采购单上（供应商必须一致）、销项票可挂账本条目（`ledgers`）；「开具 / 作废·冲红 / 恢复」三个动作各留一条日志；报表中心第 10 格「税账」按窗口给出**按税率分组**的销项 / 进项 / 应缴，并提示「登记中未开具 N 张」；利润表多一行**应交增值税（销项 − 进项）**（⛔ 不进营业利润），而「− 税」那一格改取开销里分类名含「税」的合计（今天 0 笔 ⇒ 仍是 0，但数据源已接上，且这笔钱是从期间费用搬过来的、不双扣）。
