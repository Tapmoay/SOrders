### 边界就够了吗：为什么这三条都在展示层解决得掉

- TA-08 不需要动库、不需要改算法：库里 `0.005` 是对的，弹窗预填 `0.005` 是对的，**只有卡片这一行**选了"到分"的口径。把这一行换成既有函数 [trimMoneyZeros]（去尾零、保四位精度）就三处一致——**改的是显示，不是数**。
- TA-09 的负号是**在客户端被丢掉的**（`InputRules.moneyInput` 的 `mapNotNull`），请求根本没发出去；后端拿到的永远是非负数，所以"拒绝"只能在输入框这一层做（后端 400 无从谈起）。

## ④ Behavior Contract

```text
B1  售价口径三处一致：库里 0.005 的商品 → 商品卡 ¥0.005/箱、改价弹窗预填 0.005、库仍是 0.005（Numeric(14,4) 一位不改）。
B2  金额口径不动：订单合计、收款判据、接口出参仍是"到分 + 去尾零"（formatMoney），一位不差。
B3  改价弹窗里凡是"会把输入变成别的数"的输入（负号、字母/汉字、第二个小数点、超 4 位小数、超 8 位整数）当场**拒绝**：框里保留用户打的原样、框下红字说明、确定键变灰 ⇒ 能保存下去的值永远等于用户看到的字。
B4  合法的归一**不算改写**、不弹红字：全角数字、`.5` → `0.5`、`1.` 停在点上（值没变）。
B5  联系人电话栏里被丢掉的字符（`abc`、汉字、标点）当场说出来（红字），并且**保存被拦下**；真正留空（一个字都没打）不受影响（CHG-0010）。
B6  没有电话的联系人看得见：联系人卡第二行印 `无电话`；新建/编辑抽屉的 placeholder 写明"留空＝无电话"。
B7  红字不残留：保存成功、重新打开抽屉、编辑另一条记录时都清空。
B8  后端与库一行未改：`POST/PATCH /api/v1/contacts` 契约、`phone` 的 NULL 语义、`uq_shipper_contact_phone`、单价精度全部原地。
B9  同一个货主仍可有**两条"无电话"联系人**（这是 CHG-0010 ＋ NULL 唯一约束共同定下的既有事实，见 §⑥"选择的代价"），但现在两条都写得明明白白。
```

## ⑤ Data Contract

- **新增/改动哪些字段**：**无**。没有新列、新表、新索引、新端点；`phone` / `display_name` / `category` / `remark` / `default_unit_price` 的写入格式一字未变。
- **Owner 是谁**：不变（单价仍归商品表、电话仍归 `shipper_contacts`）；本单没有新增字段，`docs/R4_CORE_EXTENSION_MAP.md` 的归属表不需要改。
- **什么时候写 / 什么时候不写**：不变——只不过"该写什么"多了一道前端闸门（被改写的输入不许提交，B3/B5）；`phone` 仍在"用户真的没填"时写 `NULL`，仍不在"用户填了被打字法丢掉字符"时写 `NULL`（那种情况现在根本到不了提交）。
- **是否允许 NULL**：允许，不变（`backend/app/models/shipper.py:53-56`：没填存 `NULL` 而不是空串——空串是**真值**，两条"没填号"的联系人会撞 `uq_shipper_contact_phone`）。
- **历史数据怎么办**：不改、不回填。历史行照旧解释得通（`phone = NULL` 的语义没变，只是现在卡上印 `无电话`）；子分价历史行（如 product 76）在卡上**变得与库里一致**。
- **迁移怎么做 / Rollback 怎么办**：**无迁移**。回滚 = 回滚这一个提交（纯展示/输入层，没有任何数据写入格式的变化，历史行不受影响）。
- **删除本功能后历史数据还能不能解释**：能——删掉本单的改动，库里的数与行一个不变，只是界面重新变得"到分"且会静默改输入。

## ⑥ CHG 专章

### 病灶一：卡上是"四舍五入到分"，弹窗里是库里的真值（TA-08）

```kotlin
// android/app/src/main/java/com/tapmoay/sorders/ui/common/ProductCardKit.kt:174（改前）
value = "¥" + formatMoney(price) + "/" + unitOrDefault(unit),
//            ↑ util/Money.kt:27-33：Double + "%.2f" —— 到分四舍五入再去尾零
//              0.005 → "0.01"：卡片上是**真值的两倍**

// android/app/src/main/java/com/tapmoay/sorders/ui/dispatcher/ProductsScreen.kt（改价弹窗的预填，改前=改后）
var price by remember { mutableStateOf(trimMoneyZeros(p.defaultUnitPrice)) }
//                                       ↑ util/Money.kt:52-56：去尾零、**保四位精度** → "0.005"
```

同一个数两处两个答案，而且卡片那个是错的。`Money.kt:47-48` 当时写的是"显示口径就是到分为止"——
那条规矩是给**金额**定的（订单合计 / 收款判据），被顺手套到了**单价**上，于是 4 位小数的单价在卡上被四舍五入。

### 这次怎么做的

1. **TA-08**：售价行改用 [trimMoneyZeros]（`ProductCardKit.kt`），并把 `Money.kt` 那条 ⛔ 收窄成"**金额**显示不许用本函数 / **单价**必须用本函数"，理由（子分价被印成两倍）写在 KDoc 里。没动库精度、没动 `formatMoney` 的进位、没动金额侧任何一个调用点。
2. **TA-09**：`core/InputRules.kt` 新增 `data class InputRewrite(val value: String, val note: String?)` 与 `priceRewrite(raw)`——**过滤仍然只有一份实现**（它内部就是 `priceInput`），新的只是"这次过滤把什么改掉了"的说明；`QuickPriceDialog` 里 note 非空 → 保留原样输入 ＋ 红字 ＋ 确定键禁用（拒绝），note 为空 → 落过滤值并允许保存。
3. **TA-10**：同形的 `contactPhoneRewrite(raw)`（`-`、空格、括号当分隔符放行；其余被丢掉的字符要说出来）＋ `AddressViewModel.onContactPhoneInput(raw)` / `contactPhoneNote`；`saveContact()` 在原有的两条校验**之前**先看 note（非空 → `formError = note` 并 return）；红字出口改成 `FormErrorLine(vm.contactPhoneNote ?: vm.formError)`；联系人卡第二行空电话印 `无电话`；placeholder 改成"选填；留空＝无电话"。

### 选择的代价（TA-10 为什么选"标注无电话"而不选"唯一性对 NULL 生效"）

台账给的二选一里，本单选**前者**（建的时候/看的时候说清"这条没有电话"，同时拒绝静默丢字）。代价与理由：

- **同一个货主仍能建出第二条"无电话"联系人**。这是**既有设计**，不是本单放的水：`backend/app/models/shipper.py:53-56` 写着"没填存 NULL 而不是空串：这张表有 `(shipper_id, phone)` 唯一约束，空串是**真值**，两条'没填号'的联系人在 MySQL 与 SQLite 上都会撞唯一键；NULL 才允许多行共存"。
- 选"唯一性对 NULL 也生效"要动**核心区**的建表/迁移（`_tools/qa/_core_files.txt` 收录的 `backend/app/core/schema_bootstrap.py`）：要么把 `phone` 的空值改存空串（那么"两个只写了称呼的老客户"从此**建不出来**——CHG-0010 只说了可以没有电话，没说过只能有一个），要么加一个 `COALESCE(phone,'')` 的部分唯一索引（SQLite 与 MySQL 语法不一致，且要回填历史行）。
- 代价的收敛方式：**看不见的重复**变成**看得见的两个"无电话"**——卡片上写 `无电话`，抽屉里说清留空是什么意思；用户想区分就自己填号或写备注。这个代价写在 §⑨ 的 Known Limitations 里。
