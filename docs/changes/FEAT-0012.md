① **利润表里「车的钱」是空的，而且是上期唯一只能写「没算进去」的地方。**
第一期那张表的 notes 第 2 条原文：「折旧没有算进去：车辆台账里没有购置价与折旧字段，也没有月度计提。
所以这张表的营业利润偏高（少了折旧那一块），第二期补车辆台账时接进来。」
另外，「**一台车这个月到底花了我多少钱**」今天要靠人肉翻开销单 —— 开销单能挂到车（`expenses.vehicle_id`），
但没有人把它们按车加起来，也没有「车自己会老」这一块。

② 派单员在「车辆管理」页给每辆车填**车型**（`vehicle_type`，计费口径）、**车身型式**（`body_type`）、
**分类**（`category`）与**计量属性**（高度 / 载重 / 容积 / 货箱尺寸 / 轴数），并绑一个**挂靠司机**；
花钱时开一张开销单，可以挂到车（燃油 / 维修 / 过路 / 停车 / 保险这些分类的 `link_kind` 就是 `vehicle`）。
财务这一侧**没有任何「车的钱」的入口**：库里没有购置价、没有购置日期、没有年限、没有残值率，也没有按月的折旧。

③ 四件事会变：
1. `vehicles` 多**四个可空的台账字段**：`purchase_price` / `purchase_date` / `useful_life_years` / `residual_rate`；
2. 「折旧」第一次成为一个**能被算出来、能被复算的派生量**（纯函数唯一实现：按月直线法，按天摊进窗口）；
3. 经营利润表在「− 期间费用」这一层**多一行「− 车辆折旧」**，恒等式从
   `gross − delivery − expense − tax` 变成 `gross − delivery − expense − depreciation − tax`；
4. 报表中心多一格「**车辆成本**」：按车给出**折旧 / 该车开销 / 该车挂靠司机的配送成本**三项与合计，
   并如实说明「这一单是哪辆车拉的今天不是事实」。

④ **不能变**（逐条）：
- `vehicle_type` 仍是**计费口径**（挂车 → 按单计费，其余 → 固定工资），⛔ 取值不许扩（`resolve_billing_mode` 靠它）；
- 车身型式与属性表（`services/vehicle_attrs.py`、判据 `_tools/qa/_check_vehicle_attrs.py`）一个字节不改：
  ⛔ 折旧四列**不进** `ATTR_KEYS`、不进「哪种车身能填哪些」的规则 —— 折旧跟车身型式无关；
- 订单 / 金额 / 账本 / 资金流水 / 结算单**一行不写**：本事项是**只读报表 ＋ 台账补充**，不产生任何新凭证；
- 第一期那六条恒等式里**前五条不变**（只多折旧那一项）：⛔ 不为了让报表好看去动商品成本 / 司机应得 / 开销任何一处口径；
- 车辆管理页的三个搜索框、卡片动作（圈底图标、左反向右编辑）与计费口径显示照旧（`_check_vehicle_ui.py` 46 项盯着）。

⑤ 见 ③ —— **EXTENSION IMPL ＋ INFRASTRUCTURE ＋ PRESENTATION**（不适用：CORE，理由在 ③ 的五问依据）。

⑥ 判据（静态 ＋ 口径）全绿**且能判红**（配 `_reverse_verify_*.py` 逐条注入）；后端单测覆盖纯函数的
购置当月 / 提足之后 / 跨月窗口 / 残值率留空 / 四个数缺一；利润表恒等式在**真实窗口**上成立（含折旧项）；

## ③ Boundary（Core / Extension / Infrastructure / Presentation）

- **结论**：**EXTENSION IMPL ＋ INFRASTRUCTURE ＋ PRESENTATION**（不适用：CORE —— 本事项给台账补四个**输入数字**、把一个**派生量**算出来并放进报表，不定义新的核心事实）
- **五问依据**（规范 §三）：
  - ① 是否定义核心事实？**否** —— 购置价 / 购置日期 / 使用年限 / 残值率是一台车的**属性**（与已有的 `height_m` / `load_tons` 同一类，已有先例）；折旧是它们按一条公开放出来的**派生量**，不是独立事实，也不参与计费 / 匹配 / 权限。
  - ② 是否改变核心不变量？**否** —— 计费口径（`vehicle_type`）、属性表、「订单带司机不带车」、账本与资金口径全部不动；利润表变的只是「多减一项」，前五条恒等式逐字不变。
  - ③ 是否必须永久存在？**否** —— 折旧口径本身是可换的（年数总和法 / 双倍余额递减法都能替），所以它必须是 Extension。
  - ④ 是否可能出现多个实现？**是** —— 折旧算法天然多种；本事项把「直线法按月、按天摊进窗口」做成唯一实现并要求可复算。
  - ⑤ 删除后 Core 是否仍然成立？**是** —— 删掉本事项，系统回到今天的样子（订单、钱、权限一切照旧），四列留 NULL 即可解释历史。
- **要改 Core 时的三问**：不适用（结论不含 CORE）。
- **核心改动声明行**：**不需要** —— `_tools/qa/_core_files.txt`（核心区清单）里没有本事项要改的文件（`backend/app/models/vehicle.py`、`backend/app/services/reports/profit_query.py` 均不在清单内）。实现期若发现非动某个核心区文件不可，**先**在 `docs/AI_WORK_CLAIM.md`「进行中」补 `核心改动：<路径> —— 为什么必须动核心：<一句话>`，再动。

## ⑤ Data Contract

- **新增/改动哪些字段**：`vehicles` 加四列 —— `purchase_price Numeric(12,2) NULL`（元）、`purchase_date Date NULL`、`useful_life_years Numeric(4,1) NULL`（年）、`residual_rate Numeric(5,4) NULL`（0–0.5）。⛔ 列宽与类型必须与迁移 `018_vehicle_depreciation.py` **逐列一致**（新库 `create_all` 与老库 `ALTER` 不能长得不一样）。
- **Owner 是谁**：`vehicles` 表 —— `docs/R4_CORE_EXTENSION_MAP.md` 里的 `freight.vehicle_registry`（车辆档案，owns `vehicles, vehicle_categories`）。折旧口径的 Owner 是新文件 `backend/app/services/vehicle_depreciation.py`（纯函数，唯一实现）。
- **什么时候写 / 什么时候不写**：派单员在车辆管理页显式保存时写（与其它字段同一条 PATCH 路径）；⛔ 折旧**永远不写库**（派生量，每次按窗口现算）；⛔ 报表、导出、AI 读取都不写任何表。
- **是否允许 NULL**：允许，且 **NULL 有明确含义 = 「没录」**，不等于 0：购置价 NULL ≠ 0 元车；年限 NULL ≠ 当年提完。四格里 **残值率留空按 0% 参与计算**（界面写明），其余三格缺任何一格 → 该车**折旧未覆盖**（单列，不猜）。
- **历史数据怎么办**：
  · 老车的四列全部 NULL ⇒ 折旧未覆盖、单列并说明，⛔ **不按车型猜购置价**（需求方 2026-10-04 明确选「不回溯」）；
  · 有购置价的历史车：**过去月份的报表会多出折旧这一项**（营业利润随之变化）—— 这是**补齐一直存在的事实**，不是改历史金额：历史订单 / 账本 / 资金流水 / 结算单一个字节不动，且 notes 说明「这一格从本期起才有值」。
  · ⛔ 过去没有 provenance 就写 NULL / unknown，不许按现在的规则猜过去。
- **迁移怎么做 / Rollback 怎么办**：`backend/app/migrations/018_vehicle_depreciation.py` 用 `ALTER TABLE vehicles ADD COLUMN` 四列（幂等、可重复跑），与 `schema_bootstrap` 的自愈兜底同批；Rollback = 回滚本提交（四列留 NULL，报表少一行，历史事实不受影响）。
- **删除本功能后历史数据还能不能解释**：能 —— 四列 NULL 表示「没录过购置信息」，报表回到「不含折旧」的旧样子，已录入的数字仍在库里（只是不再展示），不会出现无法解释的历史。

## ⑥ CHG 专章

### Before

派单员打开「车辆管理」，看得见车型 / 车身型式 / 分类 / 属性与挂靠司机，**看不见这台车花了多少钱买的、什么时候买的**。
老板打开「报表中心 → 经营利润」，利润构成是：营业收入(应收) → 算不出成本的收入 → 参与毛利的收入 → 商品成本 → 商品毛利 →
配送成本(司机应得) → 期间费用 → 税金及附加 → 营业利润；口径说明第二条写着「**折旧没有算进去**
（车辆台账里没有购置价与折旧字段）……所以这张表的营业利润偏高」。

### After

同一台车的编辑抽屉里多四格：**购置价 / 购置日期 / 使用年限 / 残值率**（残值率那格写明「留空 = 0%」），
保存后这辆车就「会老」了：系统按**直线法按月**给它计提折旧，并按天摊进你选的窗口。
「经营利润」的利润构成在「− 期间费用」下面多一行「**− 车辆折旧**」，恒等式变成
`商品毛利 − 配送成本 − 期间费用 − 车辆折旧 − 税金及附加 = 营业利润`；
购置信息没填全的车**不猜**，单独在「未覆盖折旧」卡里列出来（车牌 ＋ 缺哪一项），口径说明同步改写。
报表中心多一格「**车辆成本**」：点进去按车看到 **折旧 / 该车开销 / 该车司机的配送成本 / 合计**，
并写明「订单不带车，所以成本按『车 → 挂靠司机 → 那些单』与『挂到这台车的开销单』归集；**收入不按车拆**」。

### Blast Radius（L0～L3）

**L3（钱）** —— 经营利润表的「营业利润」这一格会变：接入折旧后，**所有窗口**（含回看的历史月份）的营业利润都会少一块折旧。
它不是「改历史金额」（订单 / 账本 / 流水一行不动），而是把一直存在的事实补进报表；为了让这件事可核查：
折旧逐车可复算、未覆盖的车单列、notes 明说口径。
