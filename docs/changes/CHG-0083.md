### 判断依据：为什么这道门当初是错的，而「重复点」不需要它

- 需求是「**新来的、还没接的单**在卡片上一点就接」；`isNewForDriver` 标记的正是这批单 ⇒ 把它做成前置条件，等于把需求**取反**。
- 「手滑点两下 / 同时从详情页点」本来就**不需要界面来防**：① `ACKABLE` 在成功那一瞬间就变假（`orders.map` 换上响应里的完整订单，`status` 已是 `ACCEPTED`）⇒ 按钮同时消失；② `ackingOrderId` 是**单值锁**，一次只有一张能飞，别的卡一起置灰；③ 真撞上并发，后端 `accept_order` 的条件 UPDATE（CAS）会回滚并给一句中文错，界面把它画在**出错那一张卡**上。
- 所以这道门的正确形态是：**两条**（在哪一档 ＋ 可不可接），剩下的交给状态本身。
