# CHG-0128 · 选人改成「左分类 + 右列表 + 可搜」：代理下单选货主直接拉起已建的账号

> 变更单（CHG）：只改**表现**（选人弹层的版式）与**复用**（把已有的分组算法接到选人上），
> 不改数据库结构、不改接口、不加权限点、不新增写端点。
> 由来：用户 2026-10-15 口述 —— 「像**选地点库那样**（左分类、右对应项）」，动机是「联系人**一多起来**…找起来**非常麻烦**」。
> 他还特别交代「我们好像**已经有了对应的代码**啊，具体是哪些功能实现了这个我忘记了」
> ⇒ 本单**不新造一套**：分组算法照用商品 / 库存 / 预设单 / 选商品弹层在用的 `ui/common/ProductPicker.kt::categoryTabsOf`，
> 版式照抄同一页的 `ui/shipper/OrderCreateScreen.kt::AddressPickerSheet`（用户点名的「选地点库」那一份）。
> 口径（用户授权父会话定下）：左分类 ＋ 右列表 ＋ 可搜；**没分类的人归「未分类」，不许藏起来**；一屏内能选到人（减少使用摩擦）。

## ⑥ CHG 专章

### Before

用户点代理商下单页的「为谁下单 → 选择」：弹出来的是一个只有**标题 + 搜索框 + 一条平铺名单**的底部抽屉（`ShipperPickerSheet.kt`），货主名册里的账号从头到尾排下来；同页「收货人」与地址页三处入口的 `ContactPickerSheet.kt` 也是这样一条**没有分类**的名单。名单一长，用户只能靠搜索框输名字或手机号后 4 位 —— 而「联系人一多起来…找起来非常麻烦」正是他 2026-10-15 说的原话。仓库里其实早就有分类：联系人分类（FEAT-0007）与账号分类名册都建好了，只是**选人的时候用不上**。

### After

同样点「为谁下单 → 选择」：抽屉里多了一列**常驻左分类栏**（112.dp，色用该模块自己的语义色）——「全部」/ 各分类 / 「未分类」，键就是分类名本身；右边只显示选中那一类的人，搜索框仍在**上面一行**横跨整页，与分类**交叉筛**（先按类、再按词）。切分类**不清空**搜索词；选中项在名册变化时自愈回「全部」；选中那一类没人时给专门文案而不是空白。**没分类的人归「未分类」那一格，排在最后，一条都不许少**；名册里没有的老分类也照样出一格（后端分类是自由文本，按名册过滤会让这些人整批消失而他们一条都没被删）。版式与「选地点库」一致（用户点名的参照物），分组算法与商品 / 库存 / 预设单**是同一份**（`categoryTabsOf`），⛔ 没有第二套挑联系人的实现。
