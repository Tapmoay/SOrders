# CHG-0030 · 消息提醒按角色统一：所有角色后台都能接收（语音仍是司机与派单员的活）

> 用户口径（2026-10-04 五件事清单第 ③ 件，逐字）：
>
> 「消息提醒按角色统一：所有角色后台都能接收、语音只有派单员与司机（货主、批发商没有），修掉货主端默认「仅前台接收」」

- **ID**：`CHG-0030`
- **类型**：CHG（消息提醒的角色口径 ＋ 后台接收默认值）
- **状态**：🚧 进行中（2026-10-04 认领）
- **Owner**：DSH 会话 `session-e94394d5-4f36-49dd-9ee1-446fcb7dee30`（与 BUG-0001 ～ BUG-0009 / CHG-0024 ～ CHG-0029 同一会话）
- **开工日期**：2026-10-04 ｜ **关闭日期**：⏳（归档那一笔回填）
- **Blast Radius**：**L0** —— 五个 Android 源码文件（`core/NewOrderAlert.kt` / `core/AlertPrefs.kt` / `core/AlertService.kt` / `core/NotifyCenter.kt` / `ui/profile/AlertSettingsScreen.kt`）＋ 一个现有测试文件（`core/NewOrderAlertTest.kt`）＋ 新建一对判据/反验脚本。
    - ⛔ **后端一行未动**：这是「端上怎么提醒」的口径，服务端只管把消息发出去（它本来就对所有角色一视同仁）。

## ① 六问

### 问 1：用户看到的是什么？期望是什么？

货主（批发商同理）在「我的 → 消息提醒」里看到的那一档写着**「仅前台接收」**，开关是**关**的。
这句话的意思是：**关掉 App 之后，他一条通知都收不到**。而他要收的消息是「司机接单了」「货送到了」「退货申请有回应了」——
这些消息**没有一条是给他"顺便看看"的**，都是要他动手的事。

同一页上还有一句「已确认：锁屏 / 关掉 App 后仍会接收并播报」—— 货主看到的是**自相矛盾的两句话**。

### 问 2：为什么现在不对？

因为那一档的**缺省值是按角色算的**：`NewOrderAlert.defaultBackground(role)` 从前返回 `hasVoice(role)`。
`hasVoice` 说的是「这个角色有没有语音播报」（司机与派单员有，货主与批发商没有），
可「后台接收」与「语音」是**两件事**：

- 「后台接收」= 关掉 App 之后还能不能收到消息（要不要挂前台服务 ＋ 常驻通知）；
- 「语音」= 收到之后念不念出来（TTS）。

把前者绑在后者上，等于说「你不配听语音，所以你也不配收消息」—— 这就是那个 bug。

### 问 3：谁受影响？

**货主与批发商**（`Role.SHIPPER` / `Role.WHOLESALER`，以及认不出角色时的 `null`）。
司机与派单员不受影响（他们本来就默认开着，行为一个字没变）。

### 问 4：不改会怎样？

货主关掉 App 之后收不到「司机接单了」这类消息 —— 他只会觉得「这个 App 不好使」，
而这条路的**默认值**是错的，绝大多数用户**永远不会**去改那一档（他们不知道它关着）。

### 问 5：改哪一层？

Android 展示层 ＋ 端上通知口径（`core/` 与 `ui/profile/`）。**不碰后端、不碰请求/响应、不碰库表、不碰权限模型**。

### 问 6：怎么证明改对了？

- 新建判据 `_tools/qa/_check_alert_background_all_roles.py`：**57 项**，逐条钉住「缺省恒真 + 四句按角色说的话 + 那三支分派」；
- 新建反验 `_tools/qa/_reverse_verify_alert_background_all_roles.py`：**16 条注入**，把修复逐条撤回，证明上面那 57 项与 Android 单测真的会红；
- Android 单测（`testEmuDebugUnitTest`）：**1160 项 0 失败**（其中 3 条是本轮新增的角色口径用例）；
- 真机（emulator-5556 货主 / 5554 司机）逐屏看一眼那几句话说的是谁的事。

## ② Must Change / Must Not Change

### Must Change

1. `NewOrderAlert.defaultBackground(role)` **对所有角色都返回 true**（不再跟 `hasVoice` 绑）；那个参数留着（三个调用点都在按角色问"我该怎么算"）。
2. `AlertPrefs.backgroundEnabled(role)`：**用户没表过态**（`!sp.contains(Keys.BACKGROUND)`）时走上面那条缺省 ⇒ 所有角色都开；用户表过态就**以他的选择为准**（他手动关掉就是关掉，不许"帮他打开"）。
3. `NewOrderAlert.serviceNotice(role)`（常驻通知那两句）与 `backgroundRowText(role)`（设置页那一档的标题与副标题）**按角色说要收的是什么**：
   - 司机：`SOrders 正在后台接收派单` / `有新派单会立刻提醒你`、`关掉 App 也收单` / `关闭后只有打开 App 时才收得到新派单`（**逐字不动**）；
   - 派单员：`…新订单` / `有新订单待派单会立刻提醒你`、`关掉 App 也收单` / `…新订单`；
   - 其余角色（货主 / 批发商 / 认不出）：`SOrders 正在后台接收消息` / `有新消息会立刻提醒你`、`关掉 App 也收消息` / `关闭后只有打开 App 时才收得到新消息`。
4. `NotifyCenter` 的**常驻通知渠道**（整机共享的那条）：名字 `后台接收派单` → `后台接收消息`，描述 → `关闭 App 后仍在接收消息的常驻提示`；`serviceNotification(title, text)` 的**标题由调用方给**（从前这里写死「正在后台接收派单」）。
5. `AlertService.goForeground()` 把**当前角色**从会话缓存读出来再递进去（`Role.fromKey(container.tokenStore.cachedRole() ?: "")`）。
6. `AlertService` 的类注释改成角色中性（「后台接收消息的常驻服务」）—— 代码改对了、注释还在说"派单"，下一个人会照着注释改回去。
7. `NewOrderAlert.summary(...)`：**每个角色**都要把「后台接收 / 仅前台接收」这半句说出来（从前只有货主那一支写「仅前台接收」，司机把「关掉 App 也收单」关掉之后那一行还是「语音 3 次」）。

### Must Not Change

1. **语音那一半一个字都不许动**：`hasVoice` / `voiceKind` / `speaks` / `repeatLabel` 的语义与取值（司机与派单员有语音，货主与批发商没有）。
2. 司机与派单员**看到的那几句话逐字不变**（判据里逐字钉着）。
3. 用户**手动关掉**后台接收之后，不许有任何代码"帮他打开"（`contains` 那一下问的就是他表过态没有）。
4. 通知权限没开时那句话不变（`通知权限没开，现在只会在 App 里显示`），「正在后台接收（通知栏有一条常驻提示，随时可关）」这句运行时文案也不变。
5. 不新增权限、不新增依赖、不碰后端与库表。

## ④ Behavior Contract

1. **没表过态**时：`backgroundEnabled(role)` 对**任何**角色都是 `true`（`Role.DRIVER` / `DISPATCHER` / `SHIPPER` / `WHOLESALER` / `null`）。
2. **表过态**时：返回他存的值（`sp.contains(Keys.BACKGROUND)` 为真就只认那个值）。
3. 常驻通知的文案由 `NewOrderAlert.serviceNotice(role)` 决定，`AlertService` 只负责把当前角色递进去；标题与正文都**由调用方传入**（`NotifyCenter.serviceNotification(title, text)`）。
4. 渠道（`NotifyChannels.SERVICE`）名字与描述**不含**「派单」二字（它是整机共享的一条，货主也看得见）。
5. 设置页那一档：标题 `关掉 App 也收{单|消息}`、副标题 `关闭后只有打开 App 时才收得到新{派单|订单|消息}` —— 由 `backgroundRowText(role)` 给，页面不写死。
6. 状态那一行为**任何**角色都包含「语音 …」与「·后台接收 / ·仅前台接收」两件事（权限没开时先说权限；语音关掉时说「语音已关」）。
7. 司机那一句 `SOrders 正在后台接收派单` 在整个 `NewOrderAlert.kt` 的**代码**里只出现一次（司机那一支）。

## ⑤ Data Contract

- **服务端**：不适用 —— 本次不新增/修改任何请求、响应、DTO、库表或状态机（后端一行未动）。
- **端上（唯一的"数据"是本地设置）**：`AlertPrefs` 的 `SharedPreferences` 里那个 `background` 布尔键，语义变成：
  - **键不存在**（用户从没动过那一档）= 所有角色都开（`defaultBackground` 那条缺省）；

    他若真的手动关过，键就存在 ⇒ 尊重他的选择（不"帮他打开"）。
- **不迁移**：不加新键、不改键名、不写 `migration`（读取路径本身就是兼容的）。
