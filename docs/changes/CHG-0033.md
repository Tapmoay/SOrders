## ① 六问

### 问 1：用户看到的是什么？期望是什么？

- 看到：自己明明是批发商（在派单员的名册上挂着一枚琥珀色「批发商」小标、货主端账本里多一段
  「我的货主欠我多少」、能替货主核销），工作台右上角那颗胶囊却一直写着「货主」。
- 期望：那颗胶囊上的字**按这个人的实际身份**说 —— 普通货主写「货主」，批发商写「批发商」。
- 注意用户说的分寸：**只有一个字要变**（胶囊上的文字）。左边那句「工作台 · 订单与账本」、
  胶囊的形状/位置/颜色族、头部高度，用户一个字都没要求改。

### 问 2：为什么现在不对？

批发商在我们库里**不是第三种角色**。实测（2026-10-04，`users` 表）：

| 角色 | `is_member` | 人数 |
| --- | --- | --- |
| `SHIPPER` | 0 | 35 |
| `SHIPPER` | 1 | **14** |
| `DISPATCHER` | 0 | 2 |
| `DRIVER` | 0 | 71 |

也就是说：49 个货主里有 **14 个**是批发商（永盛食品 `13800000002`，`id = 2`，就是其中一个）；
`role` 这一列对他们**仍然写着 `SHIPPER`**。而头部那行代码是这么来的：

```kotlin
RoleBadge(role.key)          // role.key 只有 shipper / driver / dispatcher
```

`rolePaletteOf(role)` 也只认这三种键 —— 于是「看角色画胶囊」这条老规矩**看起来完全正确**，
那 14 个人却一直被告知自己是「货主」。**这不是漏了一个分支，是把一个二维事实压成了一维。**

### 问 3：最小的改动是什么？

四件事，都在画胶囊这条线上（不动布局、不动颜色族、不动头部文案）：

1. 色源里多一支：`rolePaletteOf` 增加 `"shipper_member" -> RolePalette("批发商", Color(0xFF005A78), Color(0xFF8FDCF0))`
   —— **有意与货主同族色**：他本来就是货主那一族，变的只是标签上那个字。
2. 唯一那份映射：新增纯函数 `internal fun roleBadgeKey(roleKey: String, memberShipper: Boolean): String =
   if (roleKey == "shipper" && memberShipper) "shipper_member" else roleKey`
   —— `memberShipper` **只对货主生效**（派单员/司机就算被标了 `is_member` 也不改标签，与 `AiActor.of` 同一条纪律）。
3. 胶囊收下身份：`fun RoleBadge(role: String, memberShipper: Boolean = false)`，体内
   `val p = rolePaletteOf(roleBadgeKey(role, memberShipper))` —— 默认 `false` 是 **fail-closed**；
4. 工作台**问一次**再交给头部：`var memberShipper by remember(role.key) { mutableStateOf(false) }` +
   `LaunchedEffect(role.key) { memberShipper = runCatching { container.repo.me().isMember }.getOrDefault(false) }`，
   头部改为 `WelcomeBar(role, memberShipper)` —— ⛔ 头部自己不取数（那一行里只能有一个网络调用点）。

### 问 4：不改会怎样？

- 那 14 个批发商（以及以后新加的）永远在头部看到「货主」——**错的身份比没有身份更难发现**：
  没人会来报「我不是货主」，他们只会觉得这 App 不懂自己。
- 「批发商」这个概念在端上已经有四处（名册小标、货主账本多一段、`AiActor.memberShipper`、
  `canDialDriver`），头部是**唯一还按角色走**的一处 —— 留着它，这一维就有了两套口径。

### 问 5：怎么知道改好了？

- 纯函数级：`roleBadgeKey("shipper", true) == "shipper_member"`、`roleBadgeKey("shipper", false) == "shipper"`、
  `roleBadgeKey("driver", true) == "driver"`、`roleBadgeKey("dispatcher", true) == "dispatcher"`；
- 色源级：`rolePaletteOf("shipper_member").label == "批发商"`，且亮/暗两档色**与货主逐字相同**；
- 界面级：模拟器 5556（永盛食品 `13800000002` = 批发商）头部胶囊写「批发商」；
  换成普通货主账号（同角色、`is_member = 0`）写「货主」；
- 机器级：`python _tools/qa/_check_workbench_member_badge.py`（本事项的新红线）；
- 反向验证：`python _tools/qa/_reverse_verify_workbench_member_badge.py`（18 条注入全红才说明判据真的钉住了）。

## ② Must Change / Must Not Change

### Must Change

1. 一个批发商（`role = "SHIPPER"` ＋ `is_member = 1`）进工作台，右上角胶囊写「批发商」；
   一个普通货主（`is_member = 0`）写「货主」——**同一份代码，靠数据分岔**。
2. 「我是不是批发商」这个事实**只问一次**，由工作台问、交给头部显示；头部自己不取数。
3. 问不到（网络失败 / 老后端不返回这个字段）时**按普通货主画**（fail-closed），
   宁可漏报一个批发商，不可把全体货主写成批发商。
4. 批发商那一支的亮/暗两档色**与货主逐字相同**，色源里仍然只按「角色族」给色。
5. 这一维在端上**只有一份**判断（`roleBadgeKey`），全树不许有第二份。

### Must Not Change

- ⛔ 左边那句「工作台 · 订单与账本」／「工作台 · 全量管理」一个字不改（`workbenchHeaderText` 仍是唯一出处）；
  ⛔ 也不给批发商另写一套头部文案。
- ⛔ 不动胶囊的形状（细描边 + 透明底 + 同色字、两端半圆、不带三角）、位置（右边）、两档色的机制。
- ⛔ **不借名册那枚琥珀小标**（`0xFFFFF1C6` / `0xFF7A5900`）：那会把「角色 → 色」这条对应劈成两套。
- ⛔ `memberShipper` **不溢出到派单员与司机**：他们即使 `is_member = 1` 也不改标签。
- ⛔ `ProfileHeader`（深色头部）**故意不用** `RoleBadge`，这次也不许顺手改它。
- ⛔ AI 那一侧（`AiActor.memberShipper` / `AiContainer.refreshMembership`）已经是对的，不动。
- ⛔ 不新增取数通道：还是 `repo.me()`，只是多了一个调用点，且**不在头部**。
- ⛔ 不动 `_tools/qa/_install_all.py` 的 `STRONG_MARK`：装包脚本认角色靠**头部文案**，
  接下来胶囊上的字**因人而异**，拿它当强标志会让 5556 的核验随机红。

## ④ Behavior Contract

给定 `RoleBadge(role, memberShipper)`：

```
p     = rolePaletteOf(roleBadgeKey(role, memberShipper))
label = p.label          // 货主 / 批发商 / 司机 / 派单员 / 未知键原样
color = ThemeMode.isDark ? p.dark : p.light
```

- `roleBadgeKey` 是**纯函数**：同一个入参永远同一个出参；不取数、不读 Compose 状态、不读时间/环境。
- `roleBadgeKey` 的两条规则：① `roleKey == "shipper" && memberShipper` → `"shipper_member"`；
  ② 其余一切情况 → **原样返回 `roleKey`**（含未知键，不吞身份）。
- 工作台生命周期：进入（或 `role.key` 变化）时问一次 `GET /users/me`；
  - 成功且 `isMember` 为真且当前角色是货主 → 胶囊写「批发商」；
  - 失败 / 未返回该字段 / 非货主 / 非成员 → 胶囊写原来的字（**与改造前逐字节一致**）；
  - 请求未回来之前先按普通货主画（默认 `false`），回来后若有变化只重画那一颗胶囊。
- `WelcomeBar` 自己**不发请求**：它拿到的 `memberShipper` 全部来自 `WorkbenchScreen`。
- 换角色（同一个账号在别处切到派单员/司机）→ `role.key` 变 → 重新问一次，绝不串味。

## ⑤ Data Contract

**读**（唯一的读）：

```
GET /api/v1/users/me
→ { "id": 2, "role": "SHIPPER", "is_member": true, ... }
```

- 字段 `is_member`（Dart 侧 `UserDto`：`@SerialName("is_member") val isMember: Boolean = false`）——
  **缺省 false**：老后端不返回它时端上按普通货主处理，不会因为字段缺失把谁标成批发商。
- 端上**不缓存**这个事实：每次进工作台问一次（与 `OrderDetailViewModel:137`、
  `ShipperLedgerViewModel:200-209`、`AiContainer.refreshMembership()` 同一条口径 ——
  名册上刚被标成批发商的人，回到工作台就能看到新字）。

**写**：无。

- 本次不改任何表、不迁移任何列、不写任何字段。`users.is_member` 是**既有的**服务端事实
  （`is_member` 的写入端在派单员的用户管理里，不归本事项管）。
- 端上不产生任何本地持久化（不写 `SharedPreferences`，不进 `WorkbenchOrderStore`）。
