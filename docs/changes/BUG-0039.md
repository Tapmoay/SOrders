# BUG-0039 · 地图选点「拿不到定位」时静默停在高德默认视图（北京），而且那个从没选过的中心还能直接确认

> 缺陷修复（BUG）：**不是新增能力**，是把「已经声明过的行为」修回它该有的样子 ——
> 全仓的口径是「**拿不到就如实说一句中文**」（见 `docs/HINT_STYLE.md` 与 CHG-0122/CHG-0133 那两处同形实现），
> 而地图选点这一处**违反了它**：拿不到定位时一句话都不说。
> 由来：用户 2026-10-15 逐字：「我在测试的时候出现了一个bug，就是我在**代理下单选择地图选点**的时候
> 呃**没有弹出正确的显示**啊，看一下是什么原因包括**还有一些其他的地方**呃主要是涉及到**地图选点**
> 呃看一下是哪些原因，然后修复一下」。
> ⚠️ 用户报的"其他地方"＝**同一个共用件**的另外三个调用点（下单 / 地址与联系人 / 订单详情导航）——
> `ui/common/AmapPicker.kt` 是全库唯一那一份选点弹层（判据 `_check_map_picker.py` 钉着"调用方恰好 3 个、
> 定义恰好 1 处"），所以**这一处修好，四个入口一起好**。

① 在**代理下单**点「地图选点」：弹层正常打开，但**地图停在「北京」**（高德 SDK 的默认视图）、
底部只有一句 `拖动地图或点击地图选择位置`、**没有任何提示**；点「定位到当前位置」也毫无反馈
（按钮文字不变、没有报错）。用户的原话就是"没有弹出正确的显示"。
更要紧的是**第二半**：那个从没被选过的中心**能直接确认出去** —— 屏上唯一那道闸
（`SunLocation.isPlausible`）只知道 `(0,0)` 不可信，**挡不住北京**（`39.9,116.4` 是可信坐标），
于是一个用户在电话里根本没看过的点会被写进订单、写进**全库共享的地点库**（那个库没有删除接口）。

② 派单员（或货主）点「地图选点」⇒ 弹层打开 ⇒ 三种正常用法：**拖动地图**（中心图钉即选点）/
**点地图** / **搜索地点** / **定位到当前位置** ⇒ 底部出现逆地理地址 ⇒ 点「确认」把
`(lat, lng, address)` 交给调用方。**没有定位信号**时（模拟器、室内、高德 Key 没开定位服务、
权限被拒、冷启动 GPS 没锁星）这套流程里"定位"那两条路会失败。

③ 两件事：① 拿不到定位时弹层**会说话**（一? 句中文，与全仓同形）；② **没有出处的中心不许确认**
（`centered` 为假时「确认」不出坐标，并告诉用户下一步怎么做）。行为面的其余部分**一个字不动**。

④ 不能变的六条：① **`(0,0)` 哨兵的语义**（`core/AmapLocationManager.kt` 失败时照常回调它，
`_check_ai_guardrails.py:3214-3218` 钉着 `else` 分支不许碰坐标）；② **取点链路全 App 只有一条**
（`container.locationManager`），⛔ 不许退到 `DeviceLocation`（WGS-84，国内偏几百米 —— 会把坐标带偏）；
③ 弹层的**签名与三个调用方的参数**（`initialLat/initialLng/onPicked/onDismiss/startSatellite`）不许动；
④ 「坐标不可信不许确认」那道**既有**闸（P1-13）与它的文案不许动；⑤ 图层、瓦片 https、单例不销毁

⑤ **PRESENTATION**（`ui/common/AmapPicker.kt` 内部的三个状态与两句中文）。Core 不碰：

## ⑥ 修复专章（BUG）

### Before

代理下单 → 「地图选点」：弹层打开，**地图停在「北京」**（高德默认视图）、底部只有
`拖动地图或点击地图选择位置`、**一句话都不说**；点「定位到当前位置」毫无反馈。
根因两条：

1. `core/AmapLocationManager.kt` 定位失败时**照常回调哨兵 `(0,0)`**（不是 null，这是高德的行为），
   而弹层的 collector 只做 `locating = false` 然后 `if (pt.lat != 0.0 || pt.lng != 0.0)` 跳过 ——
   **哨兵被悄悄吞掉**，界面既不说话也不动。
2. 「确认」只校验`SunLocation.isPlausible(lat, lng)`（挡 `(0,0)` 那种），而**默认视图的中心是可信坐标**，
   于是"没看过、没选过"的点照样能确认出去。

### After

同一路径三态（设备实测，emulator-5554 派单员 `13800000001`）：

| 场景 | 现在屏上是什么 |
| --- | --- |
| 打开（无定位、无初始坐标） | 地图仍停在高德默认视图，但底部多一句 `没拿到当前位置：请点「定位到当前位置」重试，或直接在图上拖动 / 点一下选点。` |
| 直接点「确认」 | 就地多一句 `请先在地图上选一个点：拖动地图，或在图上点一下 —— 中心图钉指向的就是要选的位置。`，**弹层不关、不出坐标** |
| 拖动地图后点「确认」 | 地址自动填好（`北京市昌平区崔村镇天桥路…`），确认成功、回到代理下单页并把地址写进表单 |

### Must Preserve

```text
- 历史订单 / 历史金额 / 共享地点库里的历史点
- 取点链路全 App 唯一一条（container.locationManager）＋ (0,0) 哨兵语义
- 「坐标不可信不许确认」那道既有闸与它的文案（P1-13）
- 弹层签名 / 三个调用方参数 / startSatellite 口径 / 图层与瓦片契约 / 单例不销毁
- API compatibility（不涉及后端）
```

### Blast Radius（L0～L3）

**L1** —— 只影响选点弹层在"拿不到定位"与"没选过就确认"两种情形下的表现；
四个入口（下单 / 代理下单 / 地址与联系人 / 订单详情导航）**一起**受益（同一份共用件），
但它们传参与回调语义一个字没变；后端、权限、账本、状态机全不涉及。
