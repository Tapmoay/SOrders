**① 我要解决什么问题？** 核销要弹窗确认这件事**不撤**（用户自己说了「还是用弹窗吧」），要换的是**样子**：
现在那颗弹窗的底色是 `#DDE1EA` 的灰蓝，用户的原话是「太丑了」「不要那种灰蓝灰蓝的……像那种卡片的弹窗样式一样」。

**② 当前用户 / 业务流程是什么？** 核销（把一张已送达订单的司机运费结算掉）在两个角色的账本页各有一套弹窗：
**货主账本** `ShipperLedgerScreen.kt` 有 3 处（`:176` 恢复这笔核销的确认、`:782` `SettleOrderDialog` 核销订单、
`:896` `OrderSettlementsDialog` 订单核销记录）；**派单员账本** `LedgerPersonScreen.kt` 有 2 处
（`:385` `SettleOrderDialog`、`:471` `SettleAllDialog` 核销全部）。这 5 处都是裸 `AlertDialog`。

**③ 哪个现有事实或能力会发生变化？** 只有**外观**：这 5 处弹层的容器色从 `surfaceContainerHigh`（`#DDE1EA` 灰蓝）
变成 `colorScheme.surface`（白底），圆角从默认换成弹层档 `shapes.extraLarge`，`tonalElevation` 归零
（不再自带那一层灰蓝罩）。**标题、正文、输入框、两颗按钮的槽位与文案逐字未变**，参数表与 `AlertDialog` 逐字对齐
（`onDismissRequest / confirmButton / modifier / dismissButton / icon / title / text / properties` 八个）。

**④ 哪些东西明确不能变化？** 核销的**行为**（哪颗按钮核销哪一单、`SettleOrderDialog` / `SettleAllDialog` 的
提交与防连点、批量核销的目标集合、恢复核销的确认流程）；主题 token（`Color.kt` / `Theme.kt` 一个字不改 —— 台账的
C 案被否掉就是因为会波及 AI 聊天与消息页那 6 处消费者）；全 App 其余 **63 处**裸 `AlertDialog`（含订单详情页 8 处、
派单员订单列表 5 处）与共用件 `DangerConfirmDialog`（它是危险确认，属待拍板的「弹窗语言」）。

**⑤ 有没有更小的改法？** 有两条都被否掉：① 只给核销这一颗加 `containerColor`（台账 A 案）—— 同一个功能在
货主 / 派单员两本账上会有两种长相，而用户抱怨的是「弹窗难看」这件事本身；② 改主题 token（台账 C 案）——
一改就顺手改了 AI 聊天与消息页 6 处，超出用户说的范围。本事项按台账**推荐的 B 案**做，并且把**迁移范围**钉死在
「核销这一族」（5 处），⛔ 不做全 App 收敛。

**⑥ 如果什么都不做，会发生什么？** 用户每次核销都要看见那颗灰蓝弹窗（他一天要核销很多单）；而 L-16 与 L-20
（退货弹窗样式）是同一个决定 —— 不做，这两个条目会一直挂着，且「弹窗语言」永远没有落点。
