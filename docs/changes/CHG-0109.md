## ① 六问

```text
① 解决什么问题？  用户在商品管理的「批量操作」里找不到「批量设成不参与打折（固价）」——
                  一百个商品要一个个进编辑页勾。
② 当前流程是什么？ 批量操作页只有三格：改分组 / 沽清·上架 / 删除。折扣口径只能单个商品改。
③ 哪个现有事实会变？**没有事实变**：改的是「同一件事多一个入口」。`products.no_discount`、
                  折扣算法（order_discount.py）、接口契约、已有订单金额都不变。
④ 哪些明确不能变？ ① 不新增端点（走既有 PATCH）；② 不碰任何价格字段；③ 语义只许一种说法：
                  「订单打折时跳过它」，⛔ 不许写成「价格锁死 / 不能改价」；④ 已打过的折不回溯。
⑤ 属于哪一层？    Presentation（L0）+ 局部行为（L1）：只加一个动作与一次确认。
⑥ 什么证据能证明完成？判据 `_tools/qa/_check_fixed_price_no_discount.py`（28 项）+ 反向验证
                  `_reverse_verify_fixed_price_no_discount.py`（7 条注入全红且逐字节还原）+
                  `:app:compileEmuDebugKotlin` 通过。
```

## ③ Boundary（Core / Extension / Infrastructure / Presentation）

这一单**只碰 Presentation**：批量页多一个动作，复用既有的写端点与既有的 DTO 字段。
后端（core）没有任何改动 —— 能力早就在，缺的只是把入口摆出来。

## ④ Behavior Contract

- 勾选 N 个商品 → 点「固价（不打折）」→ 确认弹层写明「订单打折会跳过这些商品；⛔ 价格照旧可以改；已经打过的折不回溯」→ 确认；
- 逐条调用 `PATCH /api/v1/products/{id}`，body 只带 `no_discount`（PATCH 语义：没说的字段不动）；
- 逐条汇报「成功 X / N；失败……（带商品名与原因）」；失败的那几个**不会被一句"已完成"盖住**；
- 反向动作「恢复打折」＝ `no_discount=false`；
- 一个都没勾时**不弹层**，直接提示「先勾选商品」。

## ⑤ Data Contract

- 请求体：`{"no_discount": true|false}`（既有字段，既有含义）；
- 出参：沿用 `ProductOut.no_discount`；
- ⛔ 不动 `default_unit_price` / `tier_prices` / `is_active` / 成本价；
- 不写新的审计动作码（商品改走既有 `PRODUCT_UPDATE` 那条留痕）。

## ⑥ CHG 专章

### Before

要改折扣口径只能一个商品一个商品进编辑页勾「不参与打折」；批量页没有这一格。

### After

批量页顶部多了两格：「固价（不打折）」「恢复打折」；勾一批 → 确认 → 一次设好，逐条汇报。

### Must Preserve

语义一句话不变：**算折扣时跳过它**。价格照旧可以改（改单价、批发商专属价都不受影响）；
已打过的折不回溯。

### Blast Radius（L0～L3）

**L1**：只影响商品管理 → 批量操作页；不触及接口契约、数据与账。
