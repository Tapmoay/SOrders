# CHG-0059 · 数量框里已经填着 1，直接输「15」就变成「115」（点进去 ＝ 整串选中）（台账 L-25）

> 出处：只读排查台账 `_tmp/USER_BUG_LEDGER_20261006.md`（L-25 第 1048 行；汇总表相应行）。
> **L-25** 正文（ref **m00812**）：「还有一个 bug……比如说我们在**添加商品**的时候，他不是要填一些数量吗？那里**就不要填 1 了，就默认是 0** 啊。」
> 「因为假如我们要填 15，如果他自己已经填好了 1 的话，那就是要填 5 了；但是一般就很反常识，我们一般人就是**直接填 15** 的，

## ② Must Change / Must Not Change

**Must Change**

- 数量框必须走 `TextFieldValue` 受控 —— 只有它能表达"选中了哪几个字"（`value = qty.toString()` 时光标只能落在末尾）。
- 「聚焦即全选」必须挂在**聚焦那一刻**（`onFocusChanged`），⛔ 不是"每次点击"：已经在框里再点一下**不该**再全选（要挪光标仍然挪得动）。
- 外部 `qty` 变化（`−` / `+` / 转单那层 `coerceIn`）必须回填文本，**回填时光标放末尾**（否则下一次打字又被吃）。
- 判据仍然只有 `typedQty` 一份：框里显示的必须是夹好之后的数（不合法就回填，不许出现"框里写着 0、值却是 1"）。
- 两个共用字段件的开关默认**关**（默认开＝全 App 几十个字段一起变）；只有数量类字段打开。
- 三个挂载点共用同一份 `FieldSelection`（谁又抄一份会当场被"只有一份"那条判据逮住）。

**Must Not Change**

- ⛔ `const val QTY_MIN: Int = 1` / `QTY_MAX = 9999` / `QTY_DIGITS = 4` 与 `typedQty` 的行为：一个字没动。
- ⛔ 两个数量框的默认值（账本 `var qty by mutableStateOf("1")`、采购单行 `else "1"`）：一个字没动。
- ⛔ 退货页 `ui/common/Components.kt::OrderReturnLines` 那一行（三个裸控件、下限 0、上限"还能退几件"）：它体内**没有输入框**，不在这一刀里。
- ⛔ 后端 / 接口 / 权限点 / 审计 / 数据模型：一个字没动。
- ⛔ 既有红线 `_check_qty_dialog_style.py` 那 22 项：只随动了第 7 组那一条的表达式（口径反而更强），别的条目一个字没放宽。

## ④ Behavior Contract

- 数量框（选品 / 下单页行编辑 / 转单 / 账本 / 采购单行）点进去 ⇒ 整串选中；直接敲 15 ⇒ 框里是 `15`、值是 `15`。
- 点进去不敲、直接离开 ⇒ 值不变（默认仍是 1；⛔ 不会变成空、不会变成 0）。
- 已经在框里了，再点一下 ⇒ **不再全选**（想挪光标挪得动 —— 这是这次的逃生门）。
- `−` / `+` / 转单外层 `coerceIn` 改了值 ⇒ 文本回填、光标放末尾。
- 敲进去的非数字字符根本进不来、全角数字归一成半角、超四位按前四位截断 —— 全走既有的 `typedQty` / `InputRules`，行为一个字没变。
- 其余几十个普通文本框：行为一个字不变。
