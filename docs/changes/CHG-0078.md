② **现状三步，每一步都把人往外推。** 用户在聊天里问 → `export_sheet` 工具**只把请求打到后端生成一次**、立刻 `val body = repo.exportReport(...)` 之后 `body.close()`（`android/app/src/main/java/com/tapmoay/sorders/ai/AiTools.kt:519`，注释逐字：「不下载：把体积留给报表页自己按需下载」），并把「已生成，请到「报表中心」查看/下载。」当答复（`:523`）→ 用户自己去报表中心**重做一遍**（重选 tab、重选时间、再点导出）。账本那种大导出更远：**手机端零入口**（全 Android grep `export-jobs|ExportJob|createExportJob` = 0 命中），只能等站内信，而站内信那颗下载按钮也不存在（`ui/messages/NoticeRouting.kt:43-49` 只认 `request_id`）。

## ④ Behavior Contract

**动作 1：`export_sheet`（既有工具，改造）**
- 参数：`kind`（必填，turnover/products/drivers/customers/finance/audit）、`mode`（day/week/month，缺省 day）、`date`（锚点日，缺省今天）、`date_from`/`date_to`（区间，成对）。
- 现在做什么：**只校验参数**（本地对着 `EXPORT_KINDS`/`EXPORT_MODES`，与今天同一处判断），**不再打后端、不再 `body.close()`**，直接回一条 `recipe`（`source=report`）＋ 一句给模型看的话（`message`）。
- 文件名：`中文名 + "-" + from + "_" + to + ".xlsx"`（中文名与报表页页签同名：营业纵览/商品经营/司机绩效/客户经营/财务/异常与审计；区间＝参数给的 `date_from`/`date_to`，缺省时由 `mode`+锚点日算，day ⇒ 当天、week ⇒ 周一~周日、month ⇒ 1 号~月末）。
- 界面：这条消息下方出现**文件行**（文件图标 ＋ 文件名 ＋ 「下载」）。点「下载」＝客户端当场 `repo.exportReport(kind, mode, date, dateFrom, dateTo)` 取字节 → `saveExportFile` 落 `Downloads/SOrders报表` → 文件行显示保存路径并**多出一颗「分享」**。
- 失败：后端拒绝（权限/区间/500）时，文件行**原文照转**后端那句话（`humanError`），⛔ 不吞成一句"导出失败"。
- ⛔ 点按钮之前**不发任何请求**：这就是口径 m01850 ②「当场重新生成、服务器不留文件」的落地方式（后端 `reports/export` 本来就是现算现返）。

**动作 2：`export_ledger`（新增，只给派单员）**
- 参数：`shipper`（必填：货主姓名 / 手机号片段 / 临时货主名）、`date_from`（必填）、`date_to`（必填）。
- `prepare`：对着 `GET /ledger/accounts`（`repo.ledgerAccounts`）按名字或手机号找货主 —— 找不到 ⇒ 如实说「账本里没有这个人」；**命中多个** ⇒ 回 `candidates` 让模型问清是哪一个（照写侧既有范式）；命中唯一 ⇒ 回一条 `recipe`（`source=ledger`，内含 `shipper_id`）。
- **工具回合不建任务**：⛔ 不调 `POST /ledger/export-jobs`。理由＝配额（`EXPORT_DAILY_QUOTA = 20/日`）是**用户的**，模型在"先给我看看"这一步不该烧它（口径 m01850 ③「保留每天 20 次配额」）。
- 点「下载」时才：`POST /ledger/export-jobs`（`export_format=excel`）→ 轮询 `GET /ledger/export-jobs/{id}`（每 2 秒，最多 60 次，界面如实显示「正在生成…」）→ `status=done` ⇒ `GET /ledger/export-jobs/{id}/download` 取字节 → 落盘 → 显示路径 ＋ 分享；`status=failed` ⇒ 原文照转 `error_message`。
- `jobId` 写回那条消息的配方：**再点只重新下载**，不再建任务（也就不会再吃配额）。产物被清理（404）⇒ 如实说，并清掉 `jobId`，允许重新生成。
- 失败如实转述：配额用完（429）、上一次还在跑（429）、区间超过 20 000 笔（400）、PDF 关着（400，「服务器没有内嵌中文字体」那句）。临时货主（没有账号）⇒ 如实说「临时货主没有账号，导不了文件，只能在账本页看」。

**动作 3：下载完的分享（两个入口同批，口径 m01865）**
- Android 10（Q）及以上：`Intent(Intent.ACTION_SEND)` ＋ `type` ＝ xlsx 的 MIME ＋ `EXTRA_STREAM` ＝ `content://` Uri ＋ `FLAG_GRANT_READ_URI_PERMISSION` ＋ `Intent.createChooser(intent, "分享到")`。**不加权限、不加 `queries`**（微信/QQ 由系统选择器列，不需要我们声明可见性）。
- Android 9 及以下：**如实说明**「这台手机是 Android 9 或更早，系统不允许把「下载」目录里的文件直接分享出去」，并告诉用户去哪儿找（照 `ui/profile/ProfileViewModel.kt:325-329` 先例）；⛔ 不静默失败、⛔ 不把 `Failed to find configured root` 那类英文异常弹给用户。
- 入口一 ＝ 聊天文件行里那颗「分享」；入口二 ＝ 报表中心导出成功后那颗「分享」。**同一段实现**（`util/ExportUtil.kt` 新函数），⛔ 不写第二份。
- 仅"聊天那颗下载"与"报表中心那颗导出"两个入口；`ui/common/ImagePreview.kt:167-202` 的"保存到相册"⛔ 不在本单范围内。

**Authorization**：沿用既有权限 —— 报表导出走 `STATS_READ`（后端 `reports.py` 那道），账本导出走 `Permission.LEDGER_EDIT`（后端 `ledger.py:577` 那道）；客户端只是**把按钮画出来**，越权时后端照旧 403，前端原文照转。
**Compatibility**：Compatible（老对话照读；后端零改动；报表中心原有导出行为与文件名不变）。

## ⑥ CHG 专章

### Before

用户在聊天里说「把这个月的货主账导成表格」→ 模型调 `export_sheet` → 工具**真的把请求打到后端生成了一份 xlsx**，然后立刻 `body.close()` **把字节扔掉**，回一句「已生成，请到「报表中心」查看/下载。」→ 用户在聊天里得到的信息是**一个地址**，不是**一张表**；要文件就得自己离开聊天、进报表中心、重新选一次 tab 与时间、再点导出。账本那种大导出干脆没有手机端入口。

### After

同一句话 → 模型先用查询工具把数据查出来，**把表直接摆在回答里**（`ai/AiMarkdown.kt` 的表格识别 ＋ `ui/ai/AiRichText.kt` 的真表格早就在了）→ 需要文件时调 `export_sheet`/`export_ledger` → 工具**只回一条配方**（不打后端、不建任务）→ 这条消息下方出现**文件行**：文件名 ＋ 「下载」→ 点一下，客户端当场生成并落到 `Downloads/SOrders报表`，文件行显示路径并长出「分享」→ 点分享，微信/QQ 里就能把这份 xlsx 发出去。**全程不离开聊天框。**

### Must Preserve

```text
- 历史订单 / 历史金额 / 已冻结的 Pricing Fact —— 本单一处不碰
- 历史 Provenance / Audit / Ledger —— 不碰
- 权限：货主端仍然没有导出（工具白名单不动）
- API compatibility：后端零改动
- 账本导出的三道闸与每天 20 次配额：一个字不动
- 报表中心原有的导出路径、文件名规则、提示语：不动（只多一颗分享）
- 本事项特有的：老对话里**不许**凭空出现按钮；点按钮之前**不许**发请求（配额与服务器负载）
```

### 为什么按钮带的是"配方"，不是服务端产物 id

两条路摆在一起：**(a)** 工具回合先把文件生成好、存到服务器，按钮带产物 id —— 用户不点也生成，白烧配额与服务器（账本导出实测单任务 39.77 秒 / 峰值 RSS 469MB，见 `ledger.py:556-570` 那段注释）；**(b)** 工具回合只回"配方"，**点按钮才生成** —— 服务器不留文件、不点不花钱，且按钮重开对话还能用（配方跟着消息落盘）。口径 m01850 ② 定的是 (b)：**选它**。

### 为什么账本导出"点按钮才建任务"

配额是**用户的**（每天 20 次），不是模型的。如果工具回合就建任务，那么"让 AI 看看这个月的账"这句**看一眼**的话就会吃掉一次配额 —— 而用户往往只是想先看表。所以 `export_ledger` 只做"点名册 + 出配方"，`POST /ledger/export-jobs` 推迟到用户**真的点了下载**那一刻；拿到 `jobId` 后写回配方，**再点只重复下载**。这一条同时保住了口径 m01850 ③「保留每天 20 次配额」。

### 为什么编号只进配方、不进给模型看的那段文字

全仓库的口径是「参数里只许出现名字，绝不要传编号；返回值里没有账号编号」（`AiTools.PARAMS_HINT:911-932`）。而账本导出端点**按 `shipper_id` 收口**（`schemas/export_job.py:9 shipper_id: int`）。折中：编号**只**出现在 `recipe` 里，而 `recipe` 由 `AiAgentLoop` 在喂给模型之前**整段摘掉**（模型看到的只有 `ok` / `message` / `file_name`）。这样"模型不许碰编号"与"端点只能按编号导"两件事同时成立，且不需要给后端加一个按名字导出的口子。

### 为什么分享和下载同批做（而不是"以后再说"）

口径 m01865 的收口逐字是「可以可以就按你说的做」：**两个入口同一批一起给分享**。理由很实在 —— 用户下载 xlsx 的下一步动作九成是"发给别人"（微信/QQ），只给下载等于让人再去文件管理器里翻；而两个入口共用同一段实现（`ExportUtil` 的保存已经拿着 Uri，只是今天把它扔了，`util/ExportUtil.kt:29`），分开做反而会出现"聊天里能分享、报表中心不能"这种同一个功能两种命的现象。

### 判据与反验（本单自带的两个脚本）

`_tools/qa/_check_ai_export_files.py`：两个工具的 id / 组 / 角色 / 参数逐字对；`export_sheet` 里**不再**出现 `repo.exportReport` 与 `body.close()`（也就是"不许再打后端"）；`export_ledger` 里**不出现** `createLedgerExportJob`（也就是"工具回合不许建任务"）；配方必须由 `AiAgentLoop` 摘掉后才进模型（`messages += ChatMessage.tool(...)` 那一行喂的是摘过的字符串）；`AiEvent.FileOffered` 在 VM 的 `onAiEvent` 里有分支；文件行只在 `role != USER` 且 `exportRecipe != null` 时画；分享函数只在 `Build.VERSION_CODES.Q` 以上给 Intent、以下给中文原因；报表中心那颗分享与聊天那颗**调同一个函数**；提示词三处口径一致（`AiAnswerStyle` 新条目 ＋ 结尾"三件事" ＋ 工具说明里不再写"去报表中心"）；`_write_coverage.py` 那两条 EXCLUDED 的理由已按新口径改写；空转闸（脚本在文件缺失/正则不匹配时报红，而不是静默 PASS）。

`_tools/qa/_reverse_verify_ai_export_files.py`：逐条注入坏法 —— 把 `export_sheet` 改回"打后端 + `body.close()`"／把 `export_ledger` 改成工具回合就建任务／把配方整段漏给模型／把货主放进 `export_ledger` 的角色集／把 Android 9 那条如实说明改成静默 `return`／把报表中心的分享换成自己写一份 `Intent`／把提示词里的"三件事"改回"两件事"／把 `_write_coverage` 的理由改回"聊天里递不给用户" —— 每一条都必须被上面那份判据抓住。

### 真机验收（台账 L-43 `:2219` 与 `:2244` 两条验收）

① 问一句「把这个月的货主账导成表格」→ 回答里**真有表**（不是「去报表中心」）；② 点表旁边的「下载」→ `adb shell ls /sdcard/Download/SOrders报表/` 里真有那份 xlsx（文件管理器看一眼）；③ 点「分享」→ 系统分享面板出现，能选中微信；④ 账本大导出同理，且点按钮之前 `ledger_export_jobs` 行数不变。

### Blast Radius（L2）

L2：改的是聊天页的一条展示链路与两个 AI 工具的产物形态，**不动后端、不动钱、不动账**；最坏情况（按钮点不动/文件没落盘）只是"还得自己去报表中心"（今天的行为），不会有错数据。之所以不降到 L1：它同时改了提示词口径（模型行为）与"下载→分享"这条新链路，且配方要**落盘**进聊天记录（格式向后兼容必须验）。
