③ 服务端第一次有了「这台设备是谁」的概念（`X-Device-Id: <install_id>:<token>`），并据此决定放不放行；账号与设备之间多了一张**可回查**的绑定表（含解冻后的历史行）。

## ④ Behavior Contract

```text
Input          所有请求可带 X-Device-Id: <install_id>:<token>（App 统一注入）；POST /api/v1/devices/register 公开收 {"install_id": "..."}（8~64 位）
Output         GET /api/v1/users/{id}/devices → 行：id / device_id / bound_at / last_seen_at / source / active / expires_at（含已解冻历史行，active=false）；两个解冻端点 → 204
Success        已含本设备 → 只刷 last_seen_at；active < 3 → 直接绑；= 3 且最旧那台 bound_at + 6 个月 <= now → 那台置 unbound_at=now, unbind_reason="expired"，新设备顶上
Failure        登录超限 → 403，detail 说人话并带最早可替换日期（例：「这个账号已绑 3 台设备，最早那台要到 2027-04-11 才能替换；急用请联系派单员在「账户管理 → 编辑」里解冻。」）；注册超限 → 429
               —— 失败时不发生什么：登录侧 db.rollback()（不留 last_login_at、不留绑定行、**不** revoke 手上那台）；注册侧在建号之前就返回
Boundary Cases 头缺失 / 签名对不上 → 当作「没有设备信息」照旧放行；is_test_account 为真的号三条限制全跳过且**不落行**；同一 (user_id, device_id) 再次绑定**复用**旧行（清 unbound_at、更新 bound_at）
Side Effects   写 account_devices 一行；解冻写 operation_logs(USER_DEVICE_UNBIND)；登录失败计数与注册计数照旧
Authorization  GET/POST /api/v1/users/{id}/devices* 一律**签名级** Depends(require_permission(Permission.USER_MANAGE))（= 派单员，不新开权限点）；POST /api/v1/devices/register **公开**（无 token）
Compatibility  Compatible：老客户端不带 X-Device-Id 时行为与今天**完全一致**（所有闸门都因 device_id 为空而放行）
```

## ⑤ Data Contract

- **新增/改动哪些字段**：新表 `account_devices`（`id` / `user_id` FK→users.id 索引 / `device_id` String(64) 索引 / `bound_at` / `last_seen_at` / `unbound_at` 可空 / `unbind_reason` String(16) 可空 / `source` String(16)）+ `(user_id, device_id)` 唯一约束 `uq_account_devices_user_device`。`users` 表一个字段都没加。
- **Owner 是谁**：`account_devices` 由 `backend/app/models/account_device.py` 拥有（绑定事实本身）；`expires_at` 是**算出来的**（`bound_at + 6 个月`），不落库，避免两个真相。
- **什么时候写 / 什么时候不写**：登录成功、注册成功、派单员解冻时写；**测试号不写**；签名对不上不写；老客户端不带设备头不写。
- **是否允许 NULL**：`unbound_at` / `unbind_reason` 可空（`NULL` = 这台设备**当前有效**）；其余非空。
- **历史数据怎么办**：迁移**不回填** —— 过去没人记过设备，过去就是 `unknown`，⛔ 不许按现在的规则猜。上线后第一次登录才开始记。
- **迁移怎么做 / Rollback 怎么办**：`031_account_devices.py` 走 `AccountDevice.__table__.create(bind=engine, checkfirst=True)`（先判表在不在，可重跑）；回滚 = 删表（解绑记录一起没，但它是风控数据不是账目，删掉不影响任何历史金额）。
- **删除本功能后历史数据还能不能解释**：能 —— 解冻审计行（`USER_DEVICE_UNBIND`）留在 `operation_logs` 里，历史绑定表即使删掉也不改变任何订单/金额的解释。
