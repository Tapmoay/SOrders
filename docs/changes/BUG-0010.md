## ① 六问

**1. 现象是什么？**
上周（2026-09-28 ~ 10-04）报表中心读数：营业额 ¥6724.10、**商品成本 ¥5215.70**、**期间费用 ¥8559.51**（其中「货损」¥24.51）、
商品毛利 ¥1508.40、营业利润 **−¥12053.69**。这一周只有 2 张单报过货损，各坏 1 件：
- `SO202609286822445232`（orders id=564）「黄豆芽」数量 2 / 退货 0 / **货损 1** / 行金额 ¥15.40 / 快照成本 ¥5.91
- `SO202610021216747127`（orders id=590）「速冻水饺」数量 5 / 退货 0 / **货损 1** / 行金额 ¥142.50 / 快照成本 ¥18.60

两件坏货的成本（¥5.91 + ¥18.60 = **¥24.51**）**同时出现在两个地方**：
留在「商品成本」里（按净数量 2 件 / 5 件算的），又单独开了一张「货损」开销单进「期间费用」。
⇒ 同一笔损失被扣两次，**营业利润少了 ¥24.51**（上月同型 ¥43.91、本月窗口 ¥18.60）。

**2. 根因在哪？**
- 成本那一侧：`backend/app/services/reports/turnover_query.py:95`
  `net_qty = int(lp.quantity or 0) - int(lp.returned_quantity or 0)` —— 只减了**退货**，**没减货损**；
  紧接着 `:96` 的早退条件还专门给货损留了一行（`net_qty <= 0 and (lp.damage_quantity or 0) <= 0`），
  `:106` `cost_total += cost * Decimal(max(0, net_qty))` ⇒ 坏掉那几件的成本照算进 COGS。
- 费用那一侧：`backend/app/services/accounting_service.py:284` `cost_amt = (cost * Decimal(qty)).quantize(...)`
  → `:293-301` 建一张 `Expense(category="货损", amount=cost_amt)`（`:310` 同时落一条 `EXPENSE_LOSS` 现金流水）。
- **代码里声明的设计本来不是这样**：`backend/app/services/accounting_service.py:6` 写的是
  「货损（公司自担）：EXPENSE_LOSS（成本口径）+ ledgers 专用红冲行（amount=0、**负成本快照冲回 COGS**）」，
  也就是"坏货不进 COGS，损失只由开销单承担"。`:322-338` 确实每次都写了那条红冲行
  （`source=LedgerSource.REFUND`、`amount=0`、`cost_price_snapshot=-成本`）。
  **但全仓没有任何一处读 `ledgers.cost_price_snapshot`** —— 只有写点
  （`app/services/ledger_sync.py:48`、`:66`；`app/services/order_return.py:187`、`:202`；
  `app/services/accounting_service.py:339`）与模型定义（`app/models/ledger.py:43-44`）。
  ⇒ 红冲是**死代码**，冲回从未发生（开发库里负成本快照行 29 行，全是白写的）。

**3. 为什么以前没发现？**
- `backend/app/services/reports/profit_query.py:22` 与 `:65` 的口径说明写着
  「期间费用已含货损开销（货损是一张开销单），这里**不重复扣 damage_amount**」——
  这句话只管住了 `damage_amount` 这一头（它确实没被再扣一次），**没管 COGS 那一头**。
- 判据里没有任何一条把「COGS 里那几件坏货」与「开销单里那笔货损」并排看。
  独立重算探针（GOV-0005 新增）第九节就是为此加的。

**4. 这次改到什么程度（建议，未实施）？**
- 方案 A（与代码里声明的设计一致，改动最小）：`turnover_query.py:95` 的净数量再减 `damage_quantity`
  —— 坏货不进 COGS，损失只由「货损」开销单承担一次。连带要确认：`:96` 的早退与 `:110`
  `cost_covered_amount += line_receivable(lp)` 在"整行都是货损"时的收入口径（收入按行金额，不按净数量）。
- 方案 B（不动 COGS，改费用侧）：货损不再开开销单，只在成本里体现 —— 但这会动现金流水与既有开销账，
  且与 `accounting_service.py:6` 的声明冲突，**不建议**。
- ⛔ 不论哪个方案，都要先把 `profit_query.py` 那段口径说明改对（现在这句话只说了半件事）。

**5. 怎么证明改对了？**
- 独立重算探针 `_tools/seed/_verify_ledger_math.py` 第九节「口径自相矛盾（真错）」：
  并排打印「COGS 里含的货损件数成本」与「期间费用·货损」，差值必须为 0。
- 注入式反验：把净数量改回"不减货损"（或把期望值改成会重复扣的那一份）时，探针必须报红 ——
  ⛔ 不许出现"改坏了还绿"。

**6. 不许动什么？**
- **营业额与欠款**：客户是全额付款的，`damage_amount` 的注释（`turnover_query.py:118-120`）也说明货损金额故意用下单快照、不追溯改均价 —— 这一条不改。
- **「货损」开销单本身**：它进期间费用、进现金流水，是已入账的历史事实。
- **成本取价的三级口径**（期间均价 / 累计均价 / 下单快照，`app/services/cost_basis.py`）：本次只动"减去哪几个数量"，不动取价。
- **退货**那一侧已经是对的（`turnover_query.py:93-94` 的注释解释了为什么退货要减），不许顺手改坏。
