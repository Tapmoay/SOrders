① 五件事，全是「同一个事两种画法」那一类：

1. **卡片上的编辑是个裸图标**。`VehicleCard` 表头右侧一个裸 `IconButton` 塞着 18dp 铅笔 ——
   规范 §4.2c 记的用户原话「这个不行」指的就是它：信息很满的卡片上它太轻、手指也不好找。
2. **停用 / 解绑是两个文字按钮**。卡片底部一行两个 `TextButton`，而全 App 早已统一的形态是
   **圈底图标**（`ui/common/Components.kt::CardActionIcon`；账户管理页 `AccountManageScreen.kt:292-329` 就是范例），
   规范 §4.2c 还定了位置：**右＝编辑类，左＝反向 / 警示类，警示放最左**（惯用手是右手）。
3. **危险动作的入口写着和做的不一样**。司机行尾部写着「换 / 解绑」，点下去只是开弹层；
   而「解绑司机」是不可逆的一步（那辆车的活就换人了、历史要留痕）。
4. **同一页三个搜索框两种画法**。列表页与两个抽屉里的搜索框都写 `SoTextField`：
   没有 ✕ 一键清空、宽高与提示语各写一句 —— 规范 §4.4 的原始抱怨正是「同一件事两种画法」。
5. **黄绿在三个文件里手写了三遍**。`#C0E100` 在 `VehicleManageScreen.kt` / `UsersManageScreen.kt` /
   `ui/nav/Modules.kt` 各写一遍；规范 §2 模块色表「司机管理」那一格的常量列写的是「-」，
   而同一张表里别的 13 格都有 token —— 下一个人改色时必然漏掉一处。
   顺带：汇总卡里「有 N 辆车还没绑司机」那行提醒借了账本模块的金橙 `MoneyOrange`（同一个色两个含义）。

## ⑥ CHG 专章

### Before

- 编辑 = 表头右侧一个裸 `IconButton` 里的 18dp 铅笔（规范 §4.2c 里被点名「这个不行」的那一种）。
- 停用 / 启用与解绑司机 = 卡片底部两个 `TextButton`（文字按钮，没有语义色、没有圈底）。
- 司机行尾部写着「换 / 解绑」，点下去只是开编辑抽屉。
- 三个搜索框各写各的（`SoTextField`），没有 ✕ 一键清空。
- `#C0E100` 手写在三个文件里；规范 §2 那格的常量列是「-」。
- 提醒文案借账本模块的金橙 `MoneyOrange`。

### After

- 卡片底部一行三枚圈底动作：**左** 解绑（红，仅绑了司机时画）· 停用 / 启用（警示黄 / 成功绿），
  `Spacer(weight(1f))`，**右** 编辑（导航蓝）。三枚都 `label = ...`（圈底图标 + 文字），尺寸 15 / 圈底 30。
- 表头只剩信息标签（车型 / 车身型式 / 停用），不再有动作。
- 司机行尾部「换司机」。
- 三个搜索框全走 `SearchField`（列表那个仍写「搜车牌或司机」，因为要搜的是车牌）。
- `ui/theme/Color.kt` 新增 `DriverLime` / `OnDriverLime`；三个消费方全部引用它；规范 §2 那格填 `DriverLime`。
- 汇总卡提醒与 `PickRow` 警示改用 `WarningAmber`。

### Must Preserve

- 计费口径：`VEHICLE_TYPES` 三个值与它们的文字。
- 属性表按车身型式整表替换（`attrsFor`）与卡片上的 `capacityText`。
- 只停用不删除；解绑必须过确认弹层。
- 司机搜索口径：`UserSearch.filter` + 「后 4 位也行」那一份提示语。
- 后端 / DTO / 迁移 / 权限 / 审计。

### Blast Radius（L0～L3）

**L1** —— 一页的画法，加上一份**全 App 共用的定义**（`ui/theme/Color.kt` 的色 token）。
选 L1 而不是 L0 的理由：本批新增的两个 token 会被四个文件引用（车辆页、司机管理页、工作台模块网格、规范 §2 表），
改错一个值会同时影响三个界面 —— 这正是 L1「共用定义」的定义；但它不新增写库路径、不动端点与权限，所以不是 L2/L3。
