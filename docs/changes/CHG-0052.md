# CHG-0052 · 「我的账本」那一段支出只在选「全部」时画：选中某个货主就只剩「我该收的」，两个方向标签的括号一并省略（推翻 CHG-0026 的 P25 括号修法）

> 出处：用户 2026-10-06 交办的排查台账 `_tmp/USER_BUG_LEDGER_20261006.md` 的 **L-17**（选中固定货主后「我该付的」不见 ＋ 括号一事）：
> - **用户原话**（台账记的 ref 是 **m00354**）：「还有一个 bug：如果我在那个**货主选择**里选了**一个固定的人**，
>   他那个**我欠公司的**是**不会显示**的，只有**别人欠我的** —— 我就说我该收的那个，那个**括号都不应该存在**、
>   括号都要**省略掉**，不要搞括号的内容，就是「我该付的」和「我该收的」；当**选到固定货主**的时候，
>   他**只会显示我该收的**，就没有了，他下面就是那个**订单信息**。这是个 bug。」
> - **口径定稿**（台账记的 ref 是 **m00573**）：选「**全部**」时，「我欠总经销商（我该付的）」**要显示**；
>   选「**某个货主**」时它**直接不显示**，只显示「别人欠我的（我该收的）」，下面接订单信息；
>   「（欠公司）/（下游欠我）」这两处括号**一并去掉**（他早前就说过"括号都要省略掉"）。
> - **与改动前的差异**（台账逐行复核）：改动前支出段是**无条件**渲染的
>   （`ui/shipper/ShipperLedgerScreen.kt:430-449`）—— 所以"选中某人后支出段消失"这件事在改动前**根本不发生**；
>   按 m00573 的口径不是修一个消失，而是**新增"没选人时才画那一段"的闸门**。选人只改后端的过滤参数
>   （`customer_name` / `customer_phone`，`shipper_ledger.py` 里两侧同一处 `_customer_filter`），
>   `is_member` 是"这个账号是不是批发商"，**与选了谁无关** —— 后端一个字都不用动。
> - **括号的出处与这次推翻**：括号来自 **CHG-0026**（2026-10-03 E2E 走查 P25，`docs/changes/CHG-0026.md:88`）：
>   「我的账本：「支出 · 我该付的」→「支出 · 我该付的（欠公司）」；「收入 · 我该收的」→「收入 · 我该收的（下游欠我）」」。
>   加它的起因写在 `docs/E2E_WALKTHROUGH_REPORT_20261003.md:86-88`：批发商替下游货主下单时两个数**本来就会一样大**
>   （同一批货的两头：他欠公司、下游又欠他），只写「我该付的 / 我该收的」用户会以为被收了两遍钱。
>   ⇒ 删括号**等于推翻一条既有裁定**，所以本事项**用别的办法补上那一半**：方向词留在标签里，两段之间那条分隔线
>   与下面两句**常显**口径句（`"同一批货的两头，两边各记各的账，不会重复收钱。"` ／ `"两段互不影响：下面那本账怎么核销"`）
>   一个字没动 —— 认得出的"这是两头、不是被收两遍"仍在，只是不再写在标签的括号里。
>   旧 CHG 文档是**历史快照**，本次**不回去改** `docs/changes/CHG-0026.md`，推翻由本文件声明。
> - 台账是只读排查的产物（HEAD 那时是 `9fb541d`），本文件是它的**立项与收口**。

## ④ Behavior Contract

- **Input**：向下的货主名单里有没有选中某个人 —— 判据是 `ShipperLedgerViewModel.selectedCustomer`
  （抽屉里选人/清人改的就是它；`selectedCustomerKey` 是它的键，两者不许各说各话）。
- **Output**：顶上合计卡上画不画**支出段**（标签 ＋ ¥ 数 ＋ 副行），以及那条分隔线画不画；
  两个方向标签的**文本**（括号省略之后仍是"支出 · 我该付的" / "收入 · 我该收的"）。
- **Success**：选「全部」（`selectedCustomer == null`）→ 支出段与收入段**都在**，中间一条分隔线；
  选中某个货主 → 支出段**不在**，收入段仍在（`is_member` 时），**没有**悬空的分隔线，
  下面直接接这个人／这一段 · 共 N 单 的订单明细。
- **Failure**：闸门读错了判据（例如读 `selectedCustomerKey`，而标题读 `selectedCustomer`）⇒
  会出现"标题上写着某个人的名字、下面却画着全部的支出"或者反过来"写着全部、支出段却不在" ——
  两种都不会报错，只是数字与标题对不上。判据第 ① 组两条就是钉这个（闸门与标题**同一判据**）。
- **Boundary Cases**：
  · `summary == null`（加载中 / 失败）时支出段照旧画 `¥0`、收入段整段消失 —— 这是既有形状，本次不动；
  · 选的人在下拉名单里找不到（`allCustomers` 里没有这个 key）⇒ 两边一起退回"全部"（同一个判据的必然结果）；
  · `UNSET_CUSTOMER`（「未指定货主」）⇒ 仍按"没选人"处理，支出段在；
  · 普通货主（`is_member == false`）⇒ 收入段本来就不画，本次改的是支出段那道闸门与标签文案，与这一支无关。
- **Side Effects**：无。没有请求、没有写库、没有埋点、没有通知 —— 这一刀只改一屏上的一段怎么画。
- **Authorization**：无变化。「我的账本」的可见性由既有的 `ShipperOnly` 依赖与后端权限守，本次没碰。
- **Compatibility**：后端接口与出参**逐字未变**（老版本 APK 拿到的 JSON 与从前一样）；改的只有本 App 这一屏。

### Must Preserve

- 两个方向标签里的**方向词**（「支出 · 我该付的」/「收入 · 我该收的」）—— 删括号不许把方向一起删掉。

  `"两段互不影响：下面那本账怎么核销"`）仍是 `Text(` 起步 —— P25 的防混一半在这里。
