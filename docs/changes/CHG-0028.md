- **P3**：`ui/dispatcher/ProductFormScreen.kt:154-162` 那一行同时写了 `required = true`（画星）与 `placeholder = "初始库存（选填）"`（说不选填）。`FormRows.kt:150-157` 里 `required` **只负责画那颗星**（不参与提交校验）⇒ 这不是「填不填得动」的问题，是**两个信号互相打脸**。后端站在「选填」一边：`backend/app/schemas/product.py:31` `stock: int | None = Field(default=None, ...)
  description="初始库存（选填，仅创建时生效）")`。
- **P11**：`ui/dispatcher/VehicleManageScreen.kt:81-82` 的注释写着「挂车最常见，排第一」，而**真机与库里的数据不是这样**：`vehicles` 表 `small 11 / large 3 / trailer 1`（探针脚本 `_tools/qa/_probe_core_flows.py:235` 建司机时默认写 `"vehicle_type": "trailer"`，`users` 表里那 48 个 trailer 大多是这么来的）。默认值 `:97` `var draftType by mutableStateOf("trailer")`、`:193` `openCreate()` 里 `draftType = "trailer"`、`:209` `openEdit()` 里 `ifBlank { "trailer" }` —— 三处各写一次字面量，谁都没跟数据对过。
- **P5**：同一件事三处各写一遍：`ui/dispatcher/ProductCategoriesScreen.kt:371-375` 写的是对的那版（`if (c.productCount > 0) "${c.productCount} 个商品" else "暂无商品"`），而 `ui/dispatcher/ProductBatchScreen.kt:342` 与 `ui/dispatcher/ProductFormScreen.kt:354` 都用 `CategoryChoice(it.name, "${it.productCount} 个商品")` ⇒ 0 时显示「0 个商品」。共用零件 `ui/common/CategoryPickerSheet.kt:17` 的 `CategoryChoice(name, subtitle)` 本身没规定副标题怎么拼 ⇒ 每个调用方自己拼，于是必然分叉。

### 问 4：不改会怎样？

- P3 / P5 / 残余：都是「一句话说两遍、两遍不一样」——**机器判不出来**（两处都对、都能编译、数据也没错），只有人眼在那一页上同时看到两个信号才会发现。留着就是每来一个新人问一次「到底选填还是必填」。

### 问 6：会不会伤到别处？
