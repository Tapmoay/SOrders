# BUG-0011 · 司机的「待结运费」被历史结算单抵掉：窗口内的应付减掉全时段的已付，还被 max(...,0) 抹平（2026-10-05 造数与对账时发现，未修）

> 现场来源：**GOV-0005**。独立重算探针在"司机绩效"这一节逐位司机比对时发现：
> 页面上的「计件司机待结运费」比窗口内真实未结账单**少了 ¥44**——那 44 元是 2026-06 的账，
> 却在 2026-10-03 才付掉，于是从上周（2026-09-28 ~ 10-04）的应付里被扣走了。

- **ID**：BUG-0011
- **类型**：BUG（统计口径：区间应付 − 全时段已付）
- **状态**：⏸ 待定（已定位、已用真实数据实测；改法要动"结算单归哪一期"的语义，等用户拍板）
- **Owner**：DSH 会话 `session-e94394d5-4f36-49dd-9ee1-446fcb7dee30`
- **开工日期**｜**关闭日期**：2026-10-05 ｜ —
- **Blast Radius**：**预估 L1** —— 只动 `backend/app/services/stats_service.py:304-316` 的减法与它的展示落点

## ① 六问

**1. 现象是什么？**
报表中心 → 老页面「司机绩效」，窗口 = 上周（2026-09-28 ~ 10-04）：
- 页面「计件司机待结运费」= **¥1061**
- 同一窗口 `driver_bills` 里 `bill_type=piece / status=open` 的 29 行合计 = **¥1105.00**
- 差额 ¥44 全在一个人身上：**廖少华（users.id=36）**，页面显示 **¥22**，而他在窗口内有 3 张单
  （orders id=570/574/583，送达 09-29 / 09-29 / 09-30，各 ¥22 = **¥66**，账单全部 open）。

**2. 根因在哪？**
`backend/app/services/stats_service.py:304-316`：
```python
total_freight = sum(pay_for_order(ode).total for ode in os if has_per_order_pay(ode))   # 窗口内该司机的单
settled = db.scalar(select(coalesce(sum(DriverSettlement.amount), 0))
                    .where(DriverSettlement.driver_id == did,
                           DriverSettlement.status == SettlementStatus.PAID))           # ⛔ 全时段，不带窗口
owed = total_freight - settled
freight_owed = str(max(owed, 0))                                                        # ⛔ 少给 / 多付都被抹平
```
抵掉廖少华那 ¥44 的是结算单 **`driver_settlements` #56**：
`driver_id=36`、`month=2026-06`、`amount=44.00`、`status=paid`、`paid_at=2026-10-03 16:00`、
`bill_ids=[5, 11]` —— **它是 6 月的账**（两张 6 月的账单），2026-10-03 才付。

**3. 同型的还有谁？**
探针实测：另有 4 位压测司机（users.id **70 / 83 / 96 / 109**）窗口内各有 ¥675.00 的 open 账单，
页面同样显示 **¥0**（被历史已付结算单抵光）。⇒ 不是个例，是**每一位有历史结算单的司机都会中招**。

**4. 影响是什么？**
- **老板少给司机钱**：页面说"待结 22"，真实应付 66；结算时按页面走就少付 44。
- **多付的那一侧也看不见**：`max(owed, 0)` 把负值抹成 0，于是"这期已经付超了"这种事实**没有任何地方显示**。
- 与司机账单页（`driver_bills` 逐单）**对不上**，且差异随"什么时候结老账"漂移 —— 结一次老账，历史窗口的读数就变一次。

**5. 建议改法（待拍板）**
- 结算单本来就带 `period_from / period_to` 与 `bill_ids`（表列见下），应当**按它自己覆盖的那一期**去抵，
  而不是"全时段已付一律抵本期"；
- 最小改法：`settled` 只算 `bill_ids` 落在窗口内账单集合里的那些结算单（或 `period_from/period_to` 与窗口相交）；
- 同时**不要再静默 clamp**：多付时给一个负数或单独一格（"本期已付超 ¥X"），否则又一个事实被 `max(...,0)` 抹掉。

**6. 不许动什么？**
- 司机应得本身的算法（`backend/app/services/driver_pay.py::pay_for_order`，读订单快照）——探针已证明它与 `driver_bills` 逐月差 0.00。
- `driver_settlements` 的状态机与既有结算单数据（本轮**一行不改**）。
- 工资制司机不走这一格（`freight_owed = None`，导出印空串）——这条口径保留。

## ④ Behavior Contract

```text
Input          统计窗口（本周 / 上周 / 自定义）+ 司机的 driver_bills 与 driver_settlements
Output         司机绩效页「计件司机待结运费」与导出列
Success        每位司机的待结运费 == 该窗口内未结账单合计（探针逐人比对）
Failure        现状：减去全时段已付结算单（廖少华 66 → 22；4 位压测司机 675 → 0）
Boundary Cases 结算单跨期（month=2026-06 却在 10-03 付）；一位司机既有多期账单又有多期结算；
               owed 为负（多付）；工资制司机（不进这一格）
Side Effects   若实施修复：司机绩效页与导出的读数会变（变大），司机账单页不变
Authorization  统计接口既有权限（派单员）
Compatibility  DTO 字段不变；同一窗口的读数会变（要在按语里写清"这一期只抵这一期的账"）
```
