① **系统答不了「谁欠我多少、欠了多久」**：现在只有一份**按挂账单位聚合**的欠款汇总（`backend/app/services/reports/arrears_query.py:22 build_arrears_summary`，集合是「已送达 + `paid=False` + 未软删」，金额取 `order_money.arrears`），它按 `arrears_unit_name` 分组、逐单只报「这一单还欠多少」，于是三件事都答不了：(a) **哪个债务人**欠多少（同一个债务人的欠款散在多张单里，还有预收、退款、红冲要抵消）；(b) **欠了多久**（有没有 0-30 / 31-60 / 61-90 / >90 天这种分桶）；(c) **这个债务人还能不能再赊**（主数据里没有任何额度字段，`backend/app/models/arrears.py` 只有 name/phone/remark 三列，全仓库 `credit` 只有 1 处无关命中）。设计稿早就把这件事写成缺口：「挂账无发生额/结清/账龄 →『谁欠我钱』算不出，无法催收对账」（`docs/ACCOUNTING_V2_DESIGN.md:69` G2），口径也在 §6 钉好了：「客户欠款 = Σ(ledgers 应收行+负向红冲) − Σ(cash_flows IN, party_type=customer) + Σ(cash_flows OUT 且 biz_type=REFUND_CUSTOMER, party_type=customer)；<0=预收」（`:424`）、「**账龄定义**：桶 = 0-30 / 31-60 / 61-90 / >90 天；锚点 = 各应收行 `entry_date` → 今天；红冲行单独不计账龄（冲减发生额）」（`:427`），端点也定了名：`GET /reports/customer-balances`（`:406`）。**这些至今一条都没有实现**（backend 里 `customer-balances` 0 命中）。
② **当前流程（用户在界面上怎么做）**：想知道「郑伟东还欠多少」→ 打开账本 / 客户经营页一单一单看，自己心算；想知道「这笔欠了多久」→ 看单据日期自己减；要催收 → 凭记忆和纸；要决定「这单还赊不赊」→ 没有任何依据，只能凭印象。第 ⑤ 期要的就是把这三个问题变成**一页能读的数**。
③ **会变化的事实/能力**：(a) 新增只读报表 `GET /reports/customer-balances`：**一行一个债务人**的应收余额（预收为负、单列）+ 账龄四桶 + 可选逐单明细 —— ⛔ **只有这一种视图**（不做第二个分组口径：行的身份必须与「这笔钱该向谁要」1:1，换个分组就会出现同一个债务人两个答案）；(b) 挂账单位主数据 `arrears_units` 新增一格 `credit_limit`（迁移 021 只加一列，可空 = 不限额）＋ 一个设/清额度的写端点；(c) 报表中心加第 11 格「客户欠款」页；(d) 生成物与 AI 只读目录各多一条（新读端点）。
④ **明确不能变**：既有的欠款口径一个字节不改 —— `arrears_query.build_arrears_summary`（挂账单位汇总）、`turnover_query` 的「挂账未收」、`money_contract.money_map` 的 `order_money.arrears`、`shipper_settle.py` 的核销口径；`orders` / `ledgers` / `cash_flows` / `shipper_receipts` **一行不写**（本事项是纯只读 + 挂账单位主数据一列）；`rbac.py` 的权限点与角色表不动（⛔ 不新建权限点）；既有九个报表端点与九个导出 kind 的字段与话术不动。
⑤ **归属**：EXTENSION IMPL（报表只读层新增一份查询 + 一个新读端点）＋ PRESENTATION（报表中心第 11 格）＋ INFRASTRUCTURE（迁移 021 给 `arrears_units` 加一列）。**不改任何核心不变量**：新报表的口径必须与既有欠款口径**对得上**（见 ④ Behavior Contract 的恒等式），对不上就是要修的地方，⛔ 不许为了让新页好看去改旧口径。
⑥ **证据**：判据 `_tools/qa/_check_customer_balances.py`（口径 / 账龄桶边界 / 预收 / 债务人四种凭证 / 额度 / 权限 / 只读边界）＋ 反验 `_tools/qa/_reverse_verify_customer_balances.py`（注入破坏必须报红并还原）＋ `backend/tests/test_customer_balances.py`（单测）＋ 真实库探针 `_tools/qa/_probe_customer_balances.py`（真库造数、恒等式、清理）＋ 模拟器 emulator-5554 实测第 11 格 ＋ 全量静检（173 → 174/174）。

## ⑤ Data Contract

- **新增/改动哪些字段**：`arrears_units` 加一列 `credit_limit`（金额，可空 = 不限额）。⛔ 不新增表、不改既有列的类型与含义。
- **Owner 是谁**：挂账单位主数据域（`arrears_units` 这一族事实的拥有者，`backend/app/api/v1/arrears.py` 是它的唯一写入口）；报表只**读**账本 / 流水 / 订单，不反向改写它们的任何列（归属见 `docs/R4_CORE_EXTENSION_MAP.md` §3/§4，落地时同步 `docs/DOMAIN_BOUNDARIES.md`）。
- **为什么额度长在挂账单位上（⛔ 不是 customers）**：报表一行 = 一个债务人，而赊账主体就是挂账单位（`backend/app/api/v1/orders_payment.py:276-285` 写单时就把它记在订单上）；额度必须与报表行 **1:1**，挂在客户档案上会出现「两个客户同一家单位、额度算谁的」。而且挂账单位名册页已经存在（`Routes.kt:139 ARREARS_UNITS = "dispatcher/arrears"`），就地设额度不需要新页面。
- **什么时候写 / 什么时候不写**：只在「设额度 / 清额度」这一个写端点写；⛔ 不在下单、送达、收款、退货任一条路径上偷偷写额度；报表侧一个字节都不写。
- **是否允许 NULL**：`credit_limit` 允许 NULL（= 不限额，报表里显示「不限额」而不是 0）；额度只在**设了额度**的行上参与「已用 / 可用 / 超限」判断（NULL 不参与，⛔ 不把 NULL 当 0 处理）。
- **历史数据怎么办**：**不回填**。加列之后所有既有挂账单位都是 NULL（= 不限额），⛔ 不按现在的欠款去猜一个额度 —— 过去没有过额度这件事，`NULL` 才是诚实的。
- **迁移怎么做 / Rollback 怎么办**：`backend/app/migrations/021_arrears_unit_credit_limit.py` 只加一列（可重复执行：先 `inspect` 看列在不在；SQLite 走既有加列路径，与 009 的写法一致），⛔ 不回填、不动既有表结构；`backend/app/core/schema_bootstrap.py` 里另留一份自愈副本（老库启动即可用）。Rollback = 撤下第 11 格与那一个写端点，`credit_limit` 列留着（drop 列不是必需的，留着的空列不影响任何既有口径）。
- **删除本功能后历史数据还能不能解释**：能 —— 欠款与账龄是**算出来的**（订单 / 账本 / 流水都在），删掉这一页只是少了一个视图；额度那一列是挂账单位档案上的备注，删掉功能后它仍然是一句可读的事实。

## ⑥ CHG 专章

### Before

「谁欠我多少」只有一份按**挂账单位**聚合的汇总（客户经营页那一块与 `kind=customers` 导出共用 `arrears_query.build_arrears_summary`），它答的是「这个挂账单位下所有未付挂账订单还欠多少」，⛔ 不是「这个债务人现在净欠我多少」（预收、退款、退货红冲都不在里面），而且没挂单位的单会被笼统归成一行「未分配」，打电话都找不到人。没有任何地方给欠款分账龄；挂账单位档案里只有 name / phone / remark，赊不赊全靠印象。

### After

报表中心多一格「客户欠款」：**一行一个债务人**（挂账单位 → 单位名快照 → 货主 → 临时货主 → 未填货主，四道凭证按次序认），给出**应收余额**（预收为负、单列，余额 = Σ 四桶 − 预收）与**账龄四桶**（0-30 / 31-60 / 61-90 / >90，锚点=该单最早一笔正向往来行的 `entry_date`、按业务日算），可以展开看**逐单明细**（哪一单、送达日、应收 / 已收 / 还欠、落在哪一桶）。设了额度的挂账单位还会显示「已用 / 可用」与超限标记（超限只是提示，⛔ 不挡下单、不挡发货）。额度在挂账单位名册上设一次、留一条日志。

### Blast Radius（L0～L3）

**L3（钱）** —— 应收余额与账龄是催收与授信的依据，算错会让老板少收钱（漏催）或错赊（超限继续赊）；因此按规范 §八，判据 / 反验 / 探针 / 真机取证 / 全量闸五样都要有，且金额口径必须有恒等式判据。
