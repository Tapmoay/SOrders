## ① 六问

1. **谁遇到**：打开 AI 助手的三种人 —— 派单员、货主、批发商。
2. **什么时候**：第一次装好进来（空状态）、以及之后每次想不起来该怎么问的时候。
3. **遇到什么**：标题一律写「我是货主助手」，批发商看着别扭；推荐问题写死在代码里，**第一次来的人看到的是「我这个月的账结了吗」**（他连一单都没有）；想问点别的只能自己组织句子，打字慢的人每次都要重新想一遍。
4. **现在怎么办**：要么硬着头皮点一条不对味的问题，要么自己敲。
5. **为什么不行**：推荐问题本来就是为了「省得他每次都要那样子搞」，结果它给的是**这个人此刻用不上的问题**，等于没有推荐。
6. **改成什么**：标题按三种身份变；问题清单按「第一次来 / 用过一阵」两档变；常用的自动排前面；自己可以固定、也可以在设置里改首次预设；聊天页右边缘挂一颗半透明的「预设」悬浮球，点开按类别挑一条 —— **点一条先弹一次二次确认**，确认了才替他发出去。

## ④ Behavior Contract

- **身份三档**（`AiSuggests.whoOf(actor)`）：`role == DISPATCHER` ⇒ 派单员；`actor.memberShipper` ⇒ 批发商；否则 ⇒ 货主。`actor` 为空（还没拉到会员标记）⇒ 标题退回「我是你的助手」，不猜。
- **标题**：派单员「我是派单助手」／货主「我是货主助手」／批发商「我是批发商助手」，三句互不重样。
- **两档问题**：`runs <= 0`（这次装好还没跟 AI 聊过一轮）⇒ 首次档 `pack.first.take(4)`；否则 ⇒ 常规档 `rank(pack.flat, pinned, taps).take(4)`。
- **排序**：固定 → 常用（被点过 **≥2** 次，按次数倒序）→ 默认顺序。⛔ 点过一次不算常用（防手滑）；⛔ 不在当前角色问题池里的历史问题**不硬塞**（换过角色之后不该冒出上一位角色的问题）。
- **入口**：聊天页**右边缘**一颗半透明的「预设」悬浮球（`Scaffold(floatingActionButton = { if (suggestPack != null) SuggestFab(onOpen = { showLibrary = true }) }, floatingActionButtonPosition = FabPosition.End)`，`Modifier.alpha(0.55f)`）；空状态底部另有一条路进面板。
- **面板**：左抽屉，顶部「我常问的」区，下面是按类别分的组；**点任意一条只是把这句话挂起**（问题走 `pending = it`、操作走 `pending = op.say`），末尾的 `AlertDialog`（标题「就发这一句？」）弹出来让用户确认一次 —— 点「发出去」才发送，点「再想想」什么都不做。
- **置顶看得见**：每条问题右边是一颗**带字**的小按钮（「置顶」/「已置顶」），不是一颗裸图钉。
- **设置页**：首次预设可编辑（洗完为空的条目丢掉；最多 8 条 × 60 字），「恢复默认」清回出厂档。
- **隔离与清空**：prefs 名 `sorders_ai_suggest` ＋ scope 后缀，切账号重建；`taps` 最多 60 条，满了先丢次数最少的。

## ⑥ CHG 专章

### 为什么批发商不能是第三个 `AiRole`

后端 `AiRole` 只有两个值，批发商是 `users.is_member = 1`。
如果为了标题在枚举里加一个 `MEMBER`，那么：`ai.currentRole` 的每一处 `when` 都要补分支、
后端提示词与写操作闸门也要跟着分叉 —— 而**批发商能做的事和货主是同一套**，只是看的问题不同。
所以新增的 `AiSuggestWho` 是**界面自己的一层**，由 `whoOf(actor)` 从既有的两个输入算出来。

### 为什么首次档不查「有没有订单 / 有没有地址」

空状态第一帧就要画问题清单，而订单数与地址数要等网络。
拿网络结果决定摆哪四条问题，会让清单在首帧和次帧之间跳一次。
所以首次档的判据取**本机就知道**的东西：`AiHabits.runs <= 0`（还没聊过一轮）。
代价：一个老用户换了新手机、登录后第一眼会看到首次档 —— 这是可接受的，
因为他点掉一条之后 `runs` 就 > 0，下一次进来就是常规档。

### 「隐藏入口」最后做成了半透明的悬浮球（两版之间被用户否掉一次）

第一版把入口做成输入框上方一行带边框的胶囊按钮，理由是「隐藏入口要靠用户发现，
而这一颗按钮服务的恰恰是**最不会探索的那批人**」。用户 2026-10-11 直接否掉了这个形态
（逐字）：「**不要做成这样子的按钮形式啊**……就像我们桌面常用的那种**悬浮的按钮**……
不用它的时候，它就是在右边，而且**透明度比较低**，就是那种隐藏的一种」。

于是改成：挂在 `Scaffold` 的 `floatingActionButton` 槽、`FabPosition.End` 贴右边缘、
`Modifier.alpha(0.55f)` 半透明、形状只圆左边两角（`RoundedCornerShape(topStart = 16.dp, bottomStart = 16.dp)`
—— 贴边的那一侧不留圆角，看起来像"从屏幕右边探出来的一条"）。原先那行胶囊（`SuggestEntryRow`）
连同 `bottomBar` 里那行调用一起拆干净：**两套入口会让人以为有两个功能**，判据里钉了一条
`"SuggestEntryRow" not in chat_code`。

### 为什么点一条要弹二次确认（用户：「防止误触」）

用户原话：「每个预设的卡片有一个**二次确认**啊，就是**防止误触**」。
落点是抽屉末尾一个 `AlertDialog`：点卡片**不发送**，只把这句话挂进 `pending`
（问题入口 `{ pending = it }`、操作入口 `{ pending = op.say }`），弹窗把**将要发出的那句话原样显示**
（`text = { Text(ask) }`）＋ 确认键「发出去」调 `onPick(ask)`、取消键「再想想」。
判据用 **and** 而不是 or 钉两条路都要挂住 —— 只挂住一条，另一条点一下就直接发出去了。

### 为什么置顶从裸图钉改成带字按钮

用户原话：「假如想给这个搞成**置顶**该怎么该怎么搞，**这个我并没有看到该如何的去操作**」——
病不在功能缺失（图钉本来就能点），在于**它看不出来能点**（16dp 图标、没有文字）。
改成 `Surface` ＋ 文字「置顶」/「已置顶」的小按钮，并写进三档提示语
（「右边的『置顶』按一下」）。

### 顺手补掉的一处老毛病

`ai/AiContainer.kt` 的 `memberShipper` 是普通 `var`，不是 Compose state ⇒ 它变了**不会触发重组**。
原来 `AiChatScreen` 读 `ai.currentRole` 也有同样的毛病（首次进入若会员标记还没回来，
标题会一直停在「我是货主助手」）。本单在空状态处 `LaunchedEffect(Unit) { ai.refreshMembership(); suggestRev++ }`
—— 手动碰一个 state 强制刷新一次。这是**权宜**：根子上的修法是让 `memberShipper` 变成 `mutableStateOf`，
但那会波及整个 `AiContainer`，留给后续单子。

### 为什么「操作」那半张表要现算，而不是抄一份

用户 2026-10-11 追加的口径（逐字）：「不只有一些问题啊，还有一些操作……也就是说**不只是问问题，还有一些操作**
也就是相当于我们预设好了一些操作啊，**基本上我们先预设好全部操作吧**」。

注册表就在 `android/app/src/main/java/com/tapmoay/sorders/ai/AiWrite.kt` 的 `object AiWrites`
（`forModel` 给的是「这个角色真正叫得动的活」）：派单员 **151** 条、普通货主 **34** 条、批发商 **38** 条。

⛔ 最容易走错的一步是「把清单抄进 `AiSuggest.kt` 或界面文件」——抄一份的那天起，
注册表加了动作而面板不知道、改了名字而面板还是旧的，**而这两件事都不会报错**，
只会让用户点了按钮之后 AI 说「我不太明白」。所以判据专门钉了一条**反抄袭**（第 12 组）：
`AiChatScreen.kt` 与 `AiSuggest.kt` 里不许出现 `"orders.assign"` 这种写死的动作 id。

### 为什么面板从底部弹层改成左抽屉

两百多条摊平了没人翻得到底。用户的口径（逐字）：「**我们点个按钮弹一个左边侧边栏**然后呢，
它就是有做好的分类然后我们直接去按照分类来选就可以了……**那个按钮是一个入口**」。
所以：右边缘那颗半透明的「预设」悬浮球是**入口**，点开是左抽屉 —— 左栏是类别（带条数），
右栏是这一格里的问题与操作，一次只看十几条。

高风险那 60 条**照样摆**（用户逐字：「**对按你推荐的来搞**……他只是预设……就相当于他只是替用户说了一段话而已
具体还是要用户点击确认卡的」）：点一条只是**替用户把这句说出来**，
AI 该问的还是要问，动手前那张确认卡还是要用户点 —— 所以每条右边挂一枚风险签（直接生效 / 要确认 / 高风险）。

### ⚠️ 一个同名类别的坑（单测当场抓出来的）

左栏是按**类别名**排的，而问题分类与操作域的名字必然撞：两边都叫「订单」「账目」「地址与联系人」。
第一版 `shelf()` 直接 `addAll(opsSections(...))`，于是左栏出现两格同名 ——
点进去一个有问、一个有活，用户根本看不出区别。
单测里那句 `assertEquals(shelf.size, shelf.map { it.cn }.distinct().size)` 当场红了（13 格 / 12 个名字）。
改法：同名**并成一格**（`AiSuggestKind.MIXED`，上面列能问的、下面列能让他干的），
于是左栏读作「订单 33」= 3 条问题 ＋ 30 条操作。

### 二次确认卡为什么必须走零件（全量静检抓出来的真缺陷）

第一版的二次确认是**自己画了一层裸 `AlertDialog(`**，看着没问题、装到机器上也弹得出来 ——
是 `python -X utf8 _tools\qa\_check_all.py` 把它顶出来的：
`_tools/qa/_check_dialog_language.py` 报「全库代码里裸 `AlertDialog(` = 2 处」，
实际分布 `{'ui/ai/AiChatScreen.kt': 1, 'ui/common/Components.kt': 1}`。
这条规矩（台账 L-20「弹窗语言」）是：**一张卡只出一个图标，颜色就是这件事的性质** ——
全库只准剩 `CardAlertDialog` **定义体**里那一处裸弹窗，任何页面自己长一层底都不行。

改成零件后（`android/app/src/main/java/com/tapmoay/sorders/ui/ai/AiChatScreen.kt:2336`）：

```kotlin
CardAlertDialog(                       // 零件，见 ui/common/Components.kt
    onDismissRequest = { pending = null },
    title = { Text("就发这一句？") },
    text = { Text(ask) },
    confirmButton = { TextButton(onClick = { pending = null; onPick(ask) }) { Text("发出去") } },
    dismissButton = { TextButton(onClick = { pending = null }) { Text("再想想") } },
)
```

**为什么用默认的 `INFO` 档**（不写 `tone`）：这一句只是「把它说出去」，
不改数字、不删东西、退不回来的是**聊天记录里多一句话**，不是数据 ——
按台账的三档定义（`INFO` 普通确认 / `WARN` 会改数字 / `DANGER` 回不来），它落在 `INFO`。
真机重拍后卡片顶部是那枚提示蓝图标（`shots/chg0114/ai_confirm.png`）。

**判据里补了一遍**：`_check_ai_suggest.py` 除了钉 `CardAlertDialog(` ＋ 「就发这一句？」＋ `onPick(ask)`，
还多钉一条 `"AlertDialog(" not in chat_code.replace("CardAlertDialog(", "")` ——
本单的改动**自己**带上这条约束，改坏了不必等下一次全量静检才发现。
反验同步加了第 21 条注入（`CardAlertDialog(` → `AlertDialog(`）。

### 上一版为什么推迟到现在才跑（留档）

第一版提交时 `:app:testEmuDebugUnitTest` 一次都没跑通，三次失败都不是本单的文件：
`ui/messages/MessageGrading.kt` 的 `Unresolved reference 'contentOrNull'`、

外加两次环境问题（Kotlin 编译器 `OutOfMemoryError: Java heap space`；两个会话同时往 `android/app/build/` 写导致
`Could not copy … app_emuDebug.kotlin_module`）。树干净后本轮补跑，数字见上表 ——
**没有拿 CHG-0108 那轮的 1507 条冒充**。

判据钉的是**形状**（不是把现值抄进判据）：三档标题互不重样、`AiRole` 仍只有两个枚举值、
界面文件里不许再出现那两张写死的问题表与两元标题、入口必须是 `floatingActionButton` 里那颗 `SuggestFab`
（`floatingActionButtonPosition = FabPosition.End`、闲着时 `alpha` 小于 1、第一版那行 `SuggestEntryRow` 不许复活）、
点一条必须把话挂进 `pending` 再走末尾的 `CardAlertDialog`（两个入口都要 —— 只挂一条等于另一条点一下就直接发出去）、
置顶必须是**带字**按钮而不是裸图钉、
`AiContainer` 暴露 `suggests` 且取前 `ensureScoped()`、两个新文件不碰网络、单测覆盖三档身份、
**操作清单必须来自 `AiWrites.forModel`（反抄袭）**、左栏必须是 `ModalNavigationDrawer` 且右栏内容来自 `AiSuggests.shelf`。

反验 21 条注入里踩过四个坑，全是**注入本身写错**、不是判据松：
① 注的是注释（判据先过 `code_only()` 剥注释，本来就该看不见）；
② 入口挪了个位置但没挪出 `bottomBar`（第一版那条已随形态换代删掉，换成 `.alpha(0.55f)` → `.alpha(1.0f)` 等 6 条）；
③ 「换成底部弹层」那条注到了**另一个** `ModalNavigationDrawer(`（这个界面本来就有别的抽屉）——
   判据与注入双双改成只认 `SuggestLibraryDrawer` **自己的身体**之后才红；
④ 锚点写成**多行**（`'CardAlertDialog(\n            onDismissRequest = …'`）—— 这个仓库的 `.kt` 是 **CRLF** 换行
   （`AiChatScreen.kt` 实测 `\r\n` 3004 处），Python 字符串里的 `\n` 匹配不上 `\r\n`，注入恒报「源码里找不到」。
   ⇒ 注入锚点一律取**单行**唯一子串（`CardAlertDialog(` → `AlertDialog(`，该串在文件里恰好一处）。

## 附：这单为什么不是「加个配置项」

如果把三套问题写成一份 JSON、让界面读，那只是把写死从 Kotlin 搬到了 JSON ——
「第一次来的人该看什么」这条判断仍然没有落点。
真正的分界线是**三个输入**：身份（`role` ＋ `memberShipper`）、阶段（`runs`）、习惯（`taps`）。
`AiSuggest.kt` 是纯函数（无 Android 依赖），所以这套判断能被 37 条单测逐格钉死；
`AiSuggestStore.kt` 只负责存，判断一行都不掺。
