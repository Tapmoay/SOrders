## ① 六问

1. **谁遇到**：打开 AI 助手的三种人 —— 派单员、货主、批发商。
2. **什么时候**：第一次装好进来（空状态）、以及之后每次想不起来该怎么问的时候。
3. **遇到什么**：标题一律写「我是货主助手」，批发商看着别扭；推荐问题写死在代码里，**第一次来的人看到的是「我这个月的账结了吗」**（他连一单都没有）；想问点别的只能自己组织句子，打字慢的人每次都要重新想一遍。
4. **现在怎么办**：要么硬着头皮点一条不对味的问题，要么自己敲。
5. **为什么不行**：推荐问题本来就是为了「省得他每次都要那样子搞」，结果它给的是**这个人此刻用不上的问题**，等于没有推荐。
6. **改成什么**：标题按三种身份变；问题清单按「第一次来 / 用过一阵」两档变；常用的自动排前面；自己可以固定、也可以在设置里改首次预设；聊天页随时有一个「典型问题」按钮，按类别挑一条直接发出去。

## ④ Behavior Contract

- **身份三档**（`AiSuggests.whoOf(actor)`）：`role == DISPATCHER` ⇒ 派单员；`actor.memberShipper` ⇒ 批发商；否则 ⇒ 货主。`actor` 为空（还没拉到会员标记）⇒ 标题退回「我是你的助手」，不猜。
- **标题**：派单员「我是派单助手」／货主「我是货主助手」／批发商「我是批发商助手」，三句互不重样。
- **两档问题**：`runs <= 0`（这次装好还没跟 AI 聊过一轮）⇒ 首次档 `pack.first.take(4)`；否则 ⇒ 常规档 `rank(pack.flat, pinned, taps).take(4)`。
- **排序**：固定 → 常用（被点过 **≥2** 次，按次数倒序）→ 默认顺序。⛔ 点过一次不算常用（防手滑）；⛔ 不在当前角色问题池里的历史问题**不硬塞**（换过角色之后不该冒出上一位角色的问题）。
- **入口**：`bottomBar` 里、输入框上方一行「典型问题」；空状态底部也有一条路进面板。面板顶部「我常问的」区，下面是按类别分的组；点任意一条 = 关面板 ＋ 直接发送。
- **设置页**：首次预设可编辑（洗完为空的条目丢掉；最多 8 条 × 60 字），「恢复默认」清回出厂档。
- **隔离与清空**：prefs 名 `sorders_ai_suggest` ＋ scope 后缀，切账号重建；`taps` 最多 60 条，满了先丢次数最少的。

## ⑥ CHG 专章

### 为什么批发商不能是第三个 `AiRole`

后端 `AiRole` 只有两个值，批发商是 `users.is_member = 1`。
如果为了标题在枚举里加一个 `MEMBER`，那么：`ai.currentRole` 的每一处 `when` 都要补分支、
后端提示词与写操作闸门也要跟着分叉 —— 而**批发商能做的事和货主是同一套**，只是看的问题不同。
所以新增的 `AiSuggestWho` 是**界面自己的一层**，由 `whoOf(actor)` 从既有的两个输入算出来。

### 为什么首次档不查「有没有订单 / 有没有地址」

空状态第一帧就要画问题清单，而订单数与地址数要等网络。
拿网络结果决定摆哪四条问题，会让清单在首帧和次帧之间跳一次。
所以首次档的判据取**本机就知道**的东西：`AiHabits.runs <= 0`（还没聊过一轮）。
代价：一个老用户换了新手机、登录后第一眼会看到首次档 —— 这是可接受的，
因为他点掉一条之后 `runs` 就 > 0，下一次进来就是常规档。

### 为什么「隐藏按钮」做成了明面按钮

用户原话是「可能有个隐藏的按钮啊就是啊放在或者说可能也是一个按钮不一定是隐藏的」——
给了口子。做成明面一行「典型问题」的理由：隐藏入口要靠用户发现，
而这一颗按钮服务的恰恰是**最不会探索的那批人**（打字慢、不熟悉功能的货主）。
放输入框上方，一屏之内必看见。

### 顺手补掉的一处老毛病

`ai/AiContainer.kt` 的 `memberShipper` 是普通 `var`，不是 Compose state ⇒ 它变了**不会触发重组**。
原来 `AiChatScreen` 读 `ai.currentRole` 也有同样的毛病（首次进入若会员标记还没回来，
标题会一直停在「我是货主助手」）。本单在空状态处 `LaunchedEffect(Unit) { ai.refreshMembership(); suggestRev++ }`
—— 手动碰一个 state 强制刷新一次。这是**权宜**：根子上的修法是让 `memberShipper` 变成 `mutableStateOf`，
但那会波及整个 `AiContainer`，留给后续单子。

## 附：这单为什么不是「加个配置项」

如果把三套问题写成一份 JSON、让界面读，那只是把写死从 Kotlin 搬到了 JSON ——
「第一次来的人该看什么」这条判断仍然没有落点。
真正的分界线是**三个输入**：身份（`role` ＋ `memberShipper`）、阶段（`runs`）、习惯（`taps`）。
`AiSuggest.kt` 是纯函数（无 Android 依赖），所以这套判断能被 28 条单测逐格钉死；
`AiSuggestStore.kt` 只负责存，判断一行都不掺。
