## ② Must Change / Must Not Change

**Must Change**

- 提示词必须写出「形状」：结果只有一条也要分行、一个对象的明细用**两列**小表（`ai/AiAnswerStyle.kt` 第 9 条）。
- 必须写出「同类信息同一套写法」与「颜色由界面自动上、模型只加粗、最多 3 处」（第 9.1 / 9.2 条）。
- 提示词**开头与结尾都要改**（`ai/AiAgentLoop.kt` 结尾那段同步）—— 只改开头不改结尾，模型会读过去。
- 颜色只能是设计系统既有语义色的**别名**（`ui/theme/Color.kt` 的 `AiToneDanger/Money/Warn/Ok`），一个新色都不许造。
- 判定表**只有一份**（`ai/AiAnswerTone.kt`）：界面各页不许自己再写一份词表。
- 「无异常 / 没有异常 / 无风险 / 已恢复」必须先判成「正常」—— 不许被当成"异常"染红（误导比丑严重）。
- 三条上限必须真的被用上：最多 12 处、最多 2 种颜色、只有 ≤16 字且不带句读的短片段才上色。
- 英文键 → 中文标签只做一层薄表（`ai/AiFieldLabels.kt`）：认不出来原样返回，一个中文标签只能对应一个英文键。

**Must Not Change**

- ⛔ 表格：`AiMarkdown.Block.Table` 分支、`ui/ai/AiRichText.kt` 的 `MdTable`、表格「中性白卡、不跟随气泡」的配色：一个字没动。
- ⛔ 用户自己发的消息（蓝底白字）不上色：调用点是 `toned = !isUser`，全文件只有这一处传开关。
- ⛔ `ai/AiAnswerStyle.kt` 既有 9 条、第 10 条「缺信息就问，不要自己编」、结尾那句【最后再确认两件事】：一个字没动。
- ⛔ 后端 / 接口 / 权限点 / 审计 / 数据模型 / 迁移：零改动。
- ⛔ `AiCardTable` 那条卡片式表格的路：一个字没动。

## ③ Boundary

- **结论**：**PRESENTATION（AI 回答气泡的重点色与分行）＋ 提示词口径 ＋ 一层薄标签表**，Blast Radius **L1**
- **不改**：表格渲染与配色 / 用户自己的气泡 / 后端与接口 / 数据模型 / 既有 9 条提示词规则。
- **不做**：给模型一套颜色标记（那正是用户说的"乱搞"，还要常年付 token）；给表格单元格上色；新增块类型（引用块 / 结论卡）；给 `ReadAction` 补展示栏。

## ④ Behavior Contract

- 问「SO2026… 这单怎么样」⇒ 回答按「标签：值」一行一个字段、金额单独一行；不再是一整段话。
- 状态 / 危险 / 钱的短片段自动带对应语义色；一条回答最多两种颜色、最多 12 处，超出部分保持无色。
- 「无异常」是绿色（正常），不是红色。
- 表格仍然是中性白卡，单元格没有颜色；加粗还是模型写的那个加粗。
- 用户自己发的那条消息（蓝底白字）颜色不变。
- 同一条回答在任何时候重新渲染（历史消息、切角色、暗色主题）颜色一致。

## ⑤ Data Contract

- 不新增字段、不改类型、不落库、不动接口、不做迁移。
- 客户端新增纯函数与默认值：
  `AnswerTone`（公开枚举，四档）＋ `AiAnswerTone.toneOf(text)` / `AiAnswerTone.apply(blocks)`；
  `AiMarkdown.Span` 多两个字段（`bold: Boolean = false`、`tone: AnswerTone? = null` —— 默认值保证既有构造点行为与参数表不变）；
  `AiRichText(..., toned: Boolean = true, ...)`；`AiFieldLabels.of(key)` / `AiFieldLabels.apply(row)`。
