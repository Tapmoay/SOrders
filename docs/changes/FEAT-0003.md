## ① 六问

① **解决什么问题？** 用户原话：「在下单选择地点的时候…再加一个按钮，就是**我就在这**，直接定位」。
现在要点「地图选点 → 使用当前位置」**两步**才拿到自己所在的位置。

② **当前用户 / 业务流程是什么？** 货主 / 派单员下单 → 点「地址库」→ 在
线路 / 我的地点 / 共享地点 三个 tab 里翻。三个都不合适时，只能先去「地图选点」。

③ **哪个现有事实或能力会发生变化？** 下单页「地址库」抽屉多一个入口；
取点结果照样只是**一次表单填充**。

④ **哪些明确不能变化？** 见 ② 节。

⑤ **属于 Core、Extension 还是 Infrastructure？** **PRESENTATION**（多一个按钮）。
底层定位能力（`core/AmapLocationManager`）**已存在**，本事项只调用它。

⑥ **什么证据能够证明它完成？** 真机：点一下按钮 → 收货地址被填成当前位置的地址文字 + 坐标。

---

## ② Must Change / Must Not Change

```text
Must Change:
- 下单页「地址库」抽屉（线路 / 我的地点 / 共享地点）顶部加一个按钮，文案表达"我就在这里"
- 点它 → 取当前定位（GCJ-02 + 逆地理地址）→ 填进下单页的收货地址（含坐标）
- 货主端与派单员端都要有（用户点名了这两端）

Must Not Change:
- ⛔ 不动 AmapLocationManager 与 AmapPicker 的既有行为
  （「地图选点」里那个「使用当前位置」照旧）
- ⛔ 不许退到系统定位 DeviceLocation（WGS84，国内差几百米）
- ⛔ 拿不到定位时如实说一句中文、不弹一张写着假地址的卡、不写库
- ⛔ 不自动提交订单、不自动存进地点库（存不存由用户点既有按钮决定）
```

## ④ Behavior Contract

```text
Input          点一下按钮
Output         下单页的「收货地址」被填成当前定位的地址文字，同时记下 GCJ-02 坐标
Success        拿到点 → 填入；抽屉关闭
Failure        拿不到（没权限 / 高德失败 / (0,0)）→ 抽屉里一句中文，表单一个字不改
Boundary Cases 用户已经填过地址 → 覆盖（他点的就是"我就要用当前位置"）
               (0,0) 这类假值 → 必须过滤（复用全仓唯一那份 SunLocation.isPlausible）
Side Effects   只改表单；⛔ 不写库、⛔ 不提交
Authorization  沿用下单页既有权限
Compatibility  Compatible：纯新增入口
```
