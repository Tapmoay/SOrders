## ① 六问

```text
① 我要解决什么问题？
② 当前用户 / 业务流程是什么？
③ 哪个现有事实或能力会发生变化？
④ 哪些东西明确不能变化？
⑤ 这个变化属于 Core、Extension 还是 Infrastructure？
⑥ 什么证据能够证明它完成？
```

① **AI 设置页最上面那一格被一段话占了大半屏**。那一格是「隐私与费用」＋「能力说明」两句话拼的：第一句 `API Key 加密存在本机、不上传；费用你自己承担。` 只有一行，第二句是 `AiRolePrompt.settingsSummary(...)` 生成的能力声明 —— 真机上是 `能查：` 一行（39 项，域与域之间用「、」）＋ `能改：` 一行（23 项），折行折成十几行。用户 2026-10-09 第三次点名（`m01649`，语音转写逐字）：「**顺便把这个做一个折叠和隐藏啊，他那些详情的解释啊，不然太长了很占位子。**」他发的截图圈的就是这一格（412×404 的截图里，这一段几乎占满）。

② 派单员打开「AI 助手设置」→ 最上面那一格告诉他"AI 能查什么、能改什么"。这段字**必须**在那里：它是用户对 AI 能力的唯一交代，而且**和 system prompt 同源**（`AiRolePrompt.brief()` 读的是同一处），历史上写窄过一次就出过事故（v3.7 那句「它不能下单、派单、改价或删数据」，模型跟着一起否认自己的能力，见 §19.6）。所以本轮**不删字**，只把它折起来：默认一行，点一下看全。

③ 只有**这两件事**：① 那一段默认不画（`if (capacityExpanded)`），折叠时那一行写 `能查 39 项 · 能改 23 项（点开看清单）`；② 为了"这个数字是哪来的"可断言，新增纯函数 `capabilitySummaryCounts` / `capabilitySummaryLabel`（`ai/AiCapabilitySummary.kt`）—— 数字**从那段话本身数出来**（按「、」数），不手写第二份清单。

④ **那段话本身一个字都不许动**（它同时是模型的 system prompt，改窄了模型会跟着否认自己的能力）；`settingsSummary` 仍是唯一来源、仍带 `actor` 与 `readModules`；隐私与费用那句（CHG-0031 用户点名要常显）**仍在折叠之外**；AI 操作流水入口、只读开关清单、模型/Key/思考档那些卡片、`AiReads` / `AiWrites` 的角色裁剪、后端 / 端点 / 权限 / 数据库 / 历史 —— **一行不改**。

⑤ **Presentation（展示层）** ＋ 一小块 **EXTENSION IMPL**（`ai/AiCapabilitySummary.kt` 两个纯函数，不 import android.\*）。它只决定「那一段画不画、折起来那行写什么」，不定义任何核心事实；删掉之后 Core 照样成立（能力裁剪、提示词、权限一个字节都不变，只是那一格又变回一大段）。

⑥ ① 判据脚本 `python _tools/qa/_check_ai_settings_fold.py` **51/51 全绿**（退出码 0）；② 反验 `python _tools/qa/_reverse_verify_ai_settings_fold.py` **20/20 逐条注入报红**、被碰过的 5 个文件逐字节还原；③ 单测 `AiCapabilitySummaryTest` 7 档 BUILD SUCCESSFUL，全量单测 101 个类 tests=1436 failures=0；④ 真机（`emulator-5554`）两张截图：`shots/74_ai设置_能力说明_折叠.png` / `shots/75_ai设置_能力说明_展开.png`，折叠态只剩两行（隐私一句 ＋ `能查 39 项 · 能改 23 项（点开看清单）`），点一下能展开、标题变「收起清单」；⑤ 卡片下沿 **y=1430 → y=656 px**（省 774 px ≈ **281.5 dp**）。

## ③ Boundary（Core / Extension / Infrastructure / Presentation）

- **结论**：**PRESENTATION**（`ui/ai/AiSettingsScreen.kt` 那一格画不画那段字）＋ **EXTENSION IMPL**（`ai/AiCapabilitySummary.kt` 新增 `capabilitySummaryCounts` / `capabilitySummaryLabel` 两个纯函数，不 import android.\*）。
- **为什么不是 Core**：Core 是订单/账本/钱的规则与权限裁剪。这里改的是"设置页那一格画几行字"，删掉它，`AiReads.forRole`、`AiWrites.forModel`、system prompt、后端 403 的每一条**一个字节都不变**。
- **为什么不是 Infrastructure**：没碰数据库、端点、权限点、KeyStore、网络。
- **为什么不是"数据契约"**：`settingsSummary` 的返回类型仍是 `String`，`AiReads` / `AiWrites` 的清单没动；本轮只是**多了一个读那段字的函数**，没有任何形状变化。
- **为什么新建纯函数而不是就地改布局**：用户点名的就是"太长了很占位子"。留在 Composable 里，判据只能靠正则去源码里找字符串；抽成纯函数之后，`AiCapabilitySummaryTest` 能直接断言「派单员这档的项数 = 那段话里「、」的条数」「认不出角色时不许报 0 项」「兜底话不算一项」—— 这才是"下次有人把数字改成手写"能立刻报红的那种判据。

## ④ Behavior Contract

```text
Input:
  - summary: String                    AiRolePrompt.settingsSummary(...) 的**原样输出**
  - counts: AiCapabilitySummary        从上面那段话数出来的三件事
  - expanded: Boolean                  折叠状态（默认 false）
  - actor / readModules                照旧来自那一格的入参（签名未变）

Output:
  - capabilitySummaryCounts(summary) -> AiCapabilitySummary(canRead, canWrite, canWriteKnown)
  - capabilitySummaryLabel(counts, expanded) -> 一行字，四档之一

Success:
  - 折叠态：那一行写「能查 39 项 · 能改 23 项（点开看清单）」，正文不画
  - 展开态：那一行写「收起清单」，正文原样画出来（一个字不缺）

Failure:
  - 认不出角色（summary 是兜底那句）：canWriteKnown = false，标题写「能做什么（点开看清单）」
    —— 不许报「能查 0 项 · 能改 0 项」（那是把人吓一跳的假结论）

Boundary:
  - 只读开关全关掉时那句话是「能查：暂时没有（…）」⇒ 那一项**不算**清单里的一项（读 0）
  - 一项能改的都没有 ⇒ 只报能查（⛔ 不许出现"能改 0 项"）
  - 四个档互斥，写在前面那档先赢（顺序即判据：展开 > 认不出 > 全 0 > 报数）

Side Effect:
  - 无。两个纯函数不碰文件、不发网络、不写盘

Authorization:
  - 不适用：不改任何权限判定（能力裁剪仍由 AiReads / AiWrites 说了算，本轮只是把它算出来的字换个画法）

Compatibility:
  - settingsSummary 的返回值逐字未变；老设置页状态（有没有展开过）不落盘，全部走 Composition 的 saveable
```

internal data class AiCapabilitySummary(val canRead: Int, val canWrite: Int, val canWriteKnown: Boolean)

internal fun capabilitySummaryCounts(summary: String): AiCapabilitySummary { ... }   // 按「、」数

internal fun capabilitySummaryLabel(counts: AiCapabilitySummary, expanded: Boolean): String = when {
    expanded -> "收起清单"

    else -> "能查 ${counts.canRead} 项 · 能改 ${counts.canWrite} 项（点开看清单）"
}
