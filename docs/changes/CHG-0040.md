   ①-1 第二件的隐藏半边是**这条链路本来是静默失效的**：商品行的三个写端点（`POST/PATCH/DELETE /order-products`）连 `outbox` 都没 import；改地址那条虽然发 `orders.edited`，但下游 `push_events.push_order_edited_to_driver` 只发一个实时信号、**不落站内信**，而 Android `RealtimeHub.kt` 的 `when (e.type)` 里**根本没有 `order.updated` 这一支** ⇒ 派单员改完，司机那边列表不刷新、不响、消息中心也没有一条，**而没有任何东西会红**。
② 当前流程：派单员打开派单池 → 切到「已完成派单」（CHG-0039 加的那一档，按司机分组）→ 每张卡只有左侧一颗「退回池子」；要改单只能回「待派单池」那档找这张单（而它已经不在了）或重新下一单；改商品行对司机完全无感。
③ 会变的事实：
   - 这一档顶栏多一颗「选司机」→ **左侧抽屉**（左栏车型档位 / 右栏名单，可搜名字与手机号），**默认「全部司机」**，选中某位后只列他的单；
   - 每张单**右侧**多一颗「编辑」→ 就地在档内改**收货信息**（地址 / 收货人 / 下单人 / 备注）与**货物明细**（改数量单价 / 删行 / 加货，加货按**这一单货主**的专属价报价）；
   - 后端三个明细写端点统一在 `db.commit()` 之前发 `orders.edited`；`message_center` 新增 `publish_order_edited_driver` **落站内信**（标题「订单信息有修改」）；`push_events` 改走站内信 + 实时信号；
   - Android `PushTrust.ORDER_TYPES` 认识 `order.edited`、`RealtimeHub` 补 `order.updated` 分支。
④ 明确不能变：**谁在什么时候动了这一单，货主端一个字都不提醒**（与 CHG-0039「静默退回派单池」同一口径，用户明确要求）；`orders` 表结构一列不加（改单一律走既有端点 `PATCH /orders/{id}` 与 `order-products` 三个端点）；订单状态机、派单弹窗（`AssignDriverDialog(` 仍只出现一次）、「退回池子」动作、行金额算法（后端 `resolve_line_total`）一个字节不改。
⑤ **Extension + Presentation**：后端是「给已有写路径补一条事件」（不改核心不变量、不新增字段、不新增权限点），客户端是展示层（已有端点的第二个入口 + 一个筛选器）。
⑥ 见 ⑦ 测试表与 ⑧ 证据：真实库探针（改 3 次商品行 → 发件箱 3 行、站内信 3 条收件人**只有司机**）+ 真机（模拟器 5554 改备注 → outbox 861 + notifications 1989）+ 契约静检 + 全量静检 + 反验。

## ⑥ CHG 专章

### Before

- 「已完成派单」档只能看：卡片上只有「退回池子」，**没有任何改单入口**；司机一多、单子一多只能人工上下翻。
- 改商品行**对司机完全无感**：三个写端点不发任何事件（这个文件连 `outbox` 都没 import）。
- 改地址/联系人/备注虽然发 `orders.edited`，但 `push_events.push_order_edited_to_driver` 只 emit 一个实时信号 `order.updated`，而 **Android 全仓零命中这个取值**（`RealtimeHub.kt` 的 `when` 里没有这一支）⇒ 信号到了也没人认；且**不落站内信**，断线重连也补不回。
- ⇒ 用户那句「改完司机会收到消息」在今天**等于没做**，而且没有任何检查会红。

### After

- 这一档顶栏一颗「选司机」→ 左栏（车型档位）+ 右栏（名单，可搜名字与手机号），默认「全部司机」。
- 每张单右侧一颗「编辑」→ 就地改收货信息与货物明细（复用 `ProductPickerSheet`，按**这一单货主**的专属价报价）。
- 后端：三个明细写端点在 `db.commit()` 之前统一 `_notify_driver_lines_changed`；`publish_order_edited_driver` 落站内信 + 实时信号；幂等键带发件箱行号。
- Android：`PushTrust.ORDER_TYPES` 认 `order.edited`；`RealtimeHub` 认 `order.updated`（只刷新、不播报）。
- 真机实测（模拟器 5554 派单员）：详情页改「备注」保存 → `outbox_events` id 861 + `notifications` id 1989（收件人＝司机 39，标题「订单信息有修改」）。

### Must Preserve

- 「退回池子」的静默口径（CHG-0039）
- 只有派单员能改（权限点不动、`AssignDriverDialog(` 仍只出现一次）
- 行金额一律后端重算；加货按这一单货主的专属价
- 发件箱事务性：改单没成，司机就不该收到「地址变了」

### Blast Radius（L0～L3）

**L1** —— 跨后端与 Android 两侧、触及**发件箱与通知链路**（`orders.edited` 的消费与落库），但不动表结构、不动状态机、不动权限点。
- 受影响：`order_products.py` 三个写端点、`message_center.py`、`push_events.py`、`main.py`、`PushTrust.kt`、`RealtimeHub.kt`、`DispatcherPool{S keleton,ViewModel}.kt`（原文见 ② 清单）
- 不受影响：订单状态机、派单流程、结算与报表、货主端与司机端可见字段
