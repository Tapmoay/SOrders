## ① 六问

① **解决什么问题？** 它原来是 `AlertDialog`，而**同一页**其它三个选择器（地址库 / 联系人 / 选商品）
   都是底部抽屉 —— 同一页两种选择容器，本身就不一致；用户看到的是"丑"。
② **当前用户 / 业务流程是什么？** 见 ⑥ 的 Before。
③ **哪个现有事实或能力会发生变化？** 见 ⑥ 的 After。
④ **哪些明确不能变化？** 见 ②。
⑤ **属于 Core / Extension / Infrastructure？** **PRESENTATION**，不碰 Core。
⑥ **什么证据能证明完成？** 见 ⑧。

## ② Must Change / Must Not Change

```text
Must Change:
- 「为谁下单」改成底部抽屉（`ModalBottomSheet`），并抽成公共件 `ui/common/ShipperPickerSheet.kt`
- 抽屉里：临时货主（未注册）输入框 + 已注册货主搜索框 + 名册（选中打勾）

Must Not Change:
- ⛔ 选中已注册货主 = `vm.setShipper(id, null)`；填临时货主 = `vm.setShipper(null, name)`
  （两者的互斥关系与原来**逐字相同**）
- ⛔ 搜索规则走唯一实现 `core/UserSearch`（姓名 / 手机号 / 后 4 位）
- ⛔ 名册截断必须说出来（静默截断会被读成"名册里没有这个人"，然后去填临时货主 → 同一个人两本账）
- ⛔ 后端一个字节不动
```

## ③ Boundary（Core / Extension / Infrastructure / Presentation）

**PRESENTATION**，**L0**。五问：①否 ②否 ③否 ④否 ⑤**是** ⇒ 不涉及 Core。

## ④ Behavior Contract

```text
Input          点「为谁下单」那一张卡（代理下单页最上面）
Output         底部抽屉：临时货主 / 已注册货主（可搜）
Success        选一位已注册货主 → 记下 id、清掉临时货主名字、关抽屉
               填临时货主名字 → 记下名字、清掉 id（**不关抽屉**，可能还要改字）
Failure        名册为空 → 如实写「暂无货主」；搜不到 → 「没有匹配「X」的货主」
Boundary Cases 名册 >100 位时截断并写明"还有 N 位没显示"
Side Effects   无（只改页面上的草稿）
Authorization  只有代理下单页有这一块（`proxyMode`）
Compatibility  Compatible：不改接口、不改数据
```
