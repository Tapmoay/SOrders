### R4-BOUNDARY-JUSTIFICATION：为什么边界解决不了这件事

这条缺陷的形状是**三张表之间少了一个连接者**：读目录里有中文名（`AiReadCatalog.kt:138` 的 `ReadAction("ledger.list_entries", "订单账流水（手动记账 + 订单产生的收支）", …)`），
工具表里也有中文名（`AiTools.TITLES`），**数据一直在**；缺的是界面这一列"去问谁"那一行代码。
边界（网络 / RBAC / 数据库 / 契约）都碰不到"一行字该怎么显示"：它不产生任何新数据，也不违反任何契约 ——
`String → String` 的纯函数，类型系统看不见它认没认全，编译器也看不见"少问了一张表"。
唯一拦得住它的办法是**把三张表的形状与顺序写成判据**（第 7 节），再用反验逐条把这份保证弄坏一次。

## ⑥ CHG 专章

### 病灶：动作名那一列只问了一张表

改前（`ui/ai/AiOperationRows.kt`）：

```kotlin
fun actionLabel(row: AiOperationDto): String {
    val id = row.action?.takeIf { it.isNotBlank() } ?: return "未标动作（只读查询）"
    val title = AiWrites.titleOf(id)          // ← 只问写动作表
    return if (title == id) id else title + "（" + id + "）"
}
```

CHG-0089 之前，读动作根本不带 `action`，这条路没有问题；CHG-0089 让读动作也带 id 之后，
它们统统落到"认不出"那一支上 —— 页面上就是一行英文 id。真机上抓到的两行（改前，`shots/63_ai_log_read_rows.png`）：

```text
inventory_alerts             GET /api/v1/inventory/summary
invoices.list_invoices       GET /api/v1/invoices
恢复发票（invoices.restore）  POST /api/v1/invoices/9/restore     ← 同一页里的写动作（有中文名）
```

### 这次怎么做的

1. **三张表依次认**（`knownTitle`）：写动作最具体先认；读目录第二（它的 id 是带点的规范名，工具表里不会有）；工具表最后兜底。
   都认不出就返回入参本身，调用方靠"返回值 == 入参"判断没认出来 —— ⛔ 不在这里编中文名。
2. **读目录那条只取表名**（`readTitle`）：读目录的 `cn` 是整句说明（"订单账流水（手动记账 + 订单产生的收支）"），
   直接印到流水行上会挤成一片 ⇒ 取第一个「（」之前的表名；没有括号 / 剥空了都退回整句。
3. **⛔ 不改读目录产物**：`AiReadCatalog.kt` 是 `_tools/ai/_gen_ai_read_catalog.py` 生成的，
   短名在这里现场推导，产物一个字节都不用动（这也是台账 L-58 里"修法可选"里的第二种：不动数据源，改消费端）。
4. **判据与单测各钉一遍**：判据读 `code_only` 之后的源码（注释掉不算数），钉住三张表的顺序、短名规则、兜底语义，
   并加一条 absent 检查"⛔ 不许在流水页另抄一份读动作中文名表"；单测从 9 档补到 14 档，中文名**一律从表里取**，
   ⛔ 不许在用例里抄一个中文名（那样表改了测试还是绿的）。

### 判据与反验（这一单的红线，坏一处就必须红）

- 判据 `_tools/qa/_check_ai_operation_log.py`：第 7 节钉 `knownTitle` 的三张表顺序 ＋ `readTitle` 的短名规则与退路 ＋
  两条兜底语义 ＋ "工具表里每个工具都有中文名"；第 9 节钉文书与登记（九节齐全、登记簿行、工作声明行、反验脚本在）。
- 反验 `_tools/qa/_reverse_verify_ai_operation_log.py`：逐条注入（认表顺序换掉 / 短名规则换回整句 / 兜底改成编中文名 /
  文书缺一节 / 登记簿与工作声明改成别的单号 …）—— 每条都必须让判据变红，跑完逐字节还原。
