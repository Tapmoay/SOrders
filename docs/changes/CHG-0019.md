# CHG-0019 · 账号管理页按设计规范重做（第 2 批：卡片动作 —— 裸铅笔与三个文字键换成圈底图标动作）

> 司机管理 / 货主管理 / 批发商管理这三池共用**同一张账号卡片**。上一批（CHG-0018）把「新增 / 编辑账号」搬进抽屉之后，
> 卡片上还剩两处规范里不该有的东西：卡头一个**裸 18dp 铅笔** `IconButton`（用户点名「这个不行」的那一种），
> 卡底三个 `TextButton` 平铺（`设为批发商 / 转货主 / 停用`）。规范 §4.2c :226-268 要求卡片动作一律是
> 「12% 语义色圆底 + 同色图标」（`ui/common/Components.kt::CardActionIcon`），且**危险 / 异常放最左、编辑放最右**
> （用户原话「编辑一定在右边，因为我们的**惯用手是右手**」）。本批就是照这条把这张卡片的动作区重画。

① 三个动作（停用 / 转池 / 设批发商）在这张卡片上**都有用、都经常用**，问题是它们的"画法"和"位置"两样都不对：

1. **编辑是一个裸的 18dp 铅笔**。`IconButton(onClick = onEdit) { Icon(Icons.Default.Edit, …, Modifier.size(18.dp)) }`
   —— 这正是规范 §4.2c 与用户原话一起否掉的那种画法（「他就是一个**笔**啊，**这个不行**啊，他要一个图标啊，**稍微圈一下**」）。
   18dp 的图标在 40dp 的卡头里既不好看见也不好按，而且它和"点整张卡也能编辑"这件事没有任何视觉关联。
2. **三个动作是平铺的文字键，而且危险的那个位置不对**。`设为批发商 / 转货主 / 停用` 三个 `TextButton` 并排，
   键与键之间只隔 8dp（CHG-0018 之前「停用」紧挨着「转货主」，那一批把危险键挪到了最右）。规范 §4.2c 的口径是
   **异常 / 危险在最左、编辑在最右**：右手拇指扫到的是"编辑"，最左边那个才是要躲开的。
3. **同一个动作在这一页和车辆页长得不一样**。车辆卡的 `解绑 / 停用 / 编辑` 早就是圈底图标动作（`VehicleManageScreen.kt:508-546`），
   地址页六个动作也是；只有账号卡还留着文字键 + 裸图标两种老画法。同一种"拿这个人/这辆车能做什么"的语义，
   在三个页面里长成三样，正是需求方说的「认知的成本」。

② 派单员进「工作台 → 司机管理 / 货主管理 / 批发商管理」→ 滚动或搜索找到某个人 → 在**卡片上**直接做一件事：
停用 / 启用他、把他设为（或取消）批发商、在司机与货主之间转池，或者进编辑抽屉改资料。
这四件事里前三件是"就地一按"，没有任何确认弹窗（只有停用带一次确认？——**没有**，见「Must Not Change」：本批不加确认层），
所以按钮本身必须自带语义：**按错一个人的代价是不对称的**（停用会让他登不上、转池会换掉他的报价口径）。

③ 只变**这一屏的画法与位置**：动作的形态（`TextButton` / 裸 `IconButton` → `CardActionIcon` 圈底图标）、
动作的位置（编辑从"卡头"挪到"卡底那一行的最右"、危险动作从最右挪到最左）、动作的配色（不再用 `colorScheme.error`，
改成规范 §2 的语义色常量）。这些人、这些角色、这些动作**本身**一个都不变。

④ 见「Must Not Change」：四个动作的回调与语义、批发商池卡头的「定价」入口、司机池的车辆行、搜索、三个池的分池规则、
「只停用不删除」的口径、任何请求字段，都不能动。

⑤ **PRESENTATION**（详见 ③ Boundary）：本批改的全是"这一屏怎么画"，不产生任何新的事实，也不改任何写路径。

⑥ 新判据 `_tools/qa/_check_users_ui.py` + 它的反向验证 `_tools/qa/_reverse_verify_users_ui.py`
+ `python _tools/qa/_check_all.py` + `python backend/scripts/check_reachability.py` + 构建 + 模拟器 5554 实机截图（三个池）。
