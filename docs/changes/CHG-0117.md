① 用户 2026-10-11 逐字：「还有一个就是线路，他不是要选择联系人吗？**收货联系人**——这个联系人**可以选择派单员本人**啊。」——派单员给自己下的单（顺路带一车货回去），收货人就是他自己，而全 App 唯一那份挑人弹层里**只有联系人名册**：他只能把姓名与号码手打一遍。
② 现在：下单页 / 「地址与联系人」的线路与地点表单 / 订单详情的「补联系信息」，三处都挂同一份 `ui/common/ContactPickerSheet.kt`；弹层列的是调用方传进来的名册（按登录人隔离），挑中哪一条就把那一条的姓名 + 电话**整对回填**给调用方。
③ 「弹层里能挑到谁」这条事实多了一种来源：名册之外多了一行**内存里的**「我自己」（当前登录人的姓名 + 手机号，负数哨兵 id）。名册本身、后端数据、搜索规则都不变。
④ 不能变：⛔ 不写任何后端数据（不新建联系人）；⛔ 拿不到姓名或电话就不显示这一项（不出现空行）；⛔ 搜索语义不变（仍走唯一一份 `core/UserSearch`，那一行也按姓名/号码参与匹配）；⛔ 名册顺序一行不动；⛔ 三个调用方一个都不能漏。
⑤ PRESENTATION（App 展示层）：改的是"弹层里显示哪几行"，没有新的核心事实、没有新的不变量、没有新的接口。
⑥ 判据 `_tools/qa/_check_contact_picker_self.py` 九层全过 + 反向验证 6 条注入全被抓 + 单测 10 例 + 编译通过 + 线路表单真机截图（用户点名场景）。

## ⑥ CHG 专章

### Before

派单员给自己下单（或给自己名下的一条线路配收货人）时打开「选择收货联系人」：弹层里只有联系人名册。他自己不在名册里（名册是他给别人建的人），于是他要把自己的姓名与手机号**手打一遍**；打错了也没人拦（号码那一栏只做格式校验）。

### After

同一个弹层：名册之前多一行**他自己**（姓名 + 手机号），后面带一枚「本人」小标签，固定排在最前。点它 → 姓名与电话整对回填到收货人那一组，与点一条已存联系人**没有任何区别**。搜索框里输入他自己的姓名或号码（含后 4 位）也能筛出这一行；输入别人的关键字时它会正常消失（不常驻、不开后门）。拿不到姓名或电话（例如某些没有号码的测试号、取数失败）时，这一行**根本不出现**。

### Must Preserve

```text
- 历史订单 / 历史金额 / 已冻结的 Pricing Fact
- 历史 Provenance / Audit / Ledger
- 权限
- API compatibility
- 本事项特有：联系人名册的顺序与内容；core/UserSearch 是唯一的按人搜索实现；
  「挑人记下的 id 只用来在名册里找同一条」这条老口径（合成的 -1 查不到 → 什么都不做）
```

### Blast Radius（L0～L3）

L1 —— 只动 App 展示层的一个新零件、一个共用弹层与三个调用方；没有新接口、没有新字段、没有迁移，其它会话正在改的文件一个都没碰。真出问题的表现是"挑到一行空的收货人"或"某个入口没有这一项"，都能靠回滚那两笔提交立刻回到今天的样子。
