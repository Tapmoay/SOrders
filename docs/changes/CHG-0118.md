① 用户定了规定：**所有账号的初始密码默认是 123321**（逐字见下）。而现在的代码要求**必填**：
   后端 `UserCreate.password = Field(...)`、AI 动作 `users.create` 的密码字段 `required = true`、
   提示词还写着「你不知道的事就去问」（例子里的"新密码是什么"会被模型套到建号上）。
   后果：用户说「建一个账号」，AI 会先反问"密码设成什么"——**这正是规定要消灭的那一步**。
   用户原话（2026-10-11，逐字）：「我们的**所有账号初始密码默认是 123321**，这是**规定死的**。
   **AI 也要知道** —— 比如说我叫它创建一个账号，它**直接帮我创建好、不要问我密码是什么**；
   当然也可以，它也可以问我"初始密码要按默认的走吗"。这个有个要改一下，把它改一下。」

② 当前流程：派单员在「账户管理 → 新增账户」或「用户/司机管理」里手填手机号、姓名、**初始密码**（必填）、
   角色；AI 侧走 `users.create`（HIGH 风险确认卡），密码也是必填参数，模型只能问用户要。
   两条路都**没有默认值** —— 于是"规定"只存在于人脑里，代码里一个字都没有。

③ 会变的既有事实（**只有这三条**）：
   - 建号时**没给密码**：原来 422 / 被拒绝；现在按 `DEFAULT_INITIAL_PASSWORD`（123321）建出来。
   - AI 卡片：原来只写「密码：已设置，不显示」；现在**没给密码时写明用的是默认初始密码 123321（你可以改）**。
   - 两个建号表单：密码框原来空着；现在**预填 123321**（仍然可以改）。
   ⛔ **没有变**的：账号的密码存储方式（仍然 bcrypt 哈希）、`PATCH /users/{id}` 的改密码语义
   （仍然必填、留空=不改）、审计与出参口径（都不含密码）、任何历史账号的既有密码。

④ 明确不能变（Must Not Change，逐条都留了锚点）：
   - **密码不进审计**：`operation_logs.change_content` 连哈希都不许有（既有注释写死）。
   - **密码不回显**：`UserOut` 没有这个字段；AI 卡片只写"已设置/用的是默认值"，**绝不插入密码值**。
   - **"改密码"仍然是必填、仍然必须由用户明确给出**（没有"默认的新密码"这种东西）。
   - **编辑账号时密码框必须是空的**（空串 = 不改密码；预填会把别人的密码静默重置）。
   - **`min_length = 6`**：默认值是下限内的取值，不是放宽校验的理由。
   - `_tools/qa/_check_secrets.py` 的判据**不许放宽**（见 ⑦ 的那条说明）。

⑤ **Extension / Presentation**：规定本身落在既有的"常量 + 字段默认值"这一层（`core/security.py`
   是口令域既有文件，不在 `_tools/qa/_core_files.txt` 里）；AI 侧改的是**动作规格与提示词文案**，
   不动写闸门 `AiWriteService.kt`（核心区）。**零迁移、零结构变更、零回填**。

⑥ 证据：见 ⑧ —— 关键是三条独立入口：后端 pytest（不给密码也能建号并登录）、
   判据 `_tools/qa/_check_default_password.py`（含跨语言对账）、反向验证 11 条注入全红。

## ⑤ Data Contract

- **新增/改动哪些字段**：**零表结构改动**。改的是 `UserCreate.password` 的**默认值**
  （从"必填"变成"缺省 = DEFAULT_INITIAL_PASSWORD"）。`users.password_hash` 的写入方式不变。
- **Owner 是谁**：口令域 —— `backend/app/core/security.py`（值的唯一一处）；
  schema 只引用它；App 侧同源副本 `core/AccountRules.kt`（由判据对账）。
- **什么时候写 / 什么时候不写**：只在**建号**时写（且总是写：给了就用给的、没给就用默认）。
  `PATCH /users/{id}` 不带 `password` 时**不动**这一格（既有语义）。
- **是否允许 NULL**：不允许（`password_hash` 非空，既有）。
- **历史数据怎么办**：**不动**。已有账号的密码一个都不改；本单没有回填、没有迁移
  —— 规定只对"这一次之后新建的账号"生效，且这是用户的口径（他要的是"以后建号别问密码"）。
- **迁移怎么做 / Rollback 怎么办**：无迁移。回滚 = 把 `DEFAULT_INITIAL_PASSWORD` 的引用撤回成必填
  （`Field(...)`）＋ 删掉 AI 那段提示词与卡片分支（见 ⑨ Rollback）。
- **删除本功能后历史数据还能不能解释**：能 —— 每个账号的 `password_hash` 都还在，
  "他是用默认密码还是自己设的"本来就没有记录（⛔ 也不该有：那等于把凭据口径写进审计）。

## ⑥ CHG 专章

### Before

- 派单员在「账户管理 → 新增账户」里填手机号/姓名/**初始密码（必填）**，不填就保存不了
  （红字「请设置密码（至少 6 位）」）；「用户/司机管理」那条链路同理（「初始密码至少 6 位」）。
- AI：用户说「帮我建一个货主账号，手机号 139…」时，模型会**先反问密码**（动作说明里写着"必填。
  必须由用户明确给出"，提示词里还写着"你不知道的事就去问"）。
- "所有账号初始密码默认 123321"这条规定，**代码里一个字都没有** —— 只有人记得。

### After

- 两个表单的密码框**预填 123321**（占位也写明「默认 123321，可改」），派单员可以直接保存，
  也可以改成一个别的密码；**编辑**账号时仍然是空的（= 不改密码）。
- AI：`users.create` 的密码参数是**可选**。用户没提密码时，卡片上会写着
  「密码：将使用默认初始密码 123321（你可以改）」；点确认后**真的**用 123321 建号。
  用户明确说"密码设成 abc123"时，用他给的（卡片回到「密码：已设置，不显示」）。
- 提示词里多了一条**例外**：「所有账号的初始密码默认就是 123321：用户说『建一个账号』时
  **不要追问密码**，直接按默认建……⛔ 但改一个已有账号的密码不适用这条：那里仍然必须问他。」
- 规定写进了 `docs/ACCOUNT_RULES.md`（第一节：用户原话 + 唯一落点表 + 改密码不适用 + 别与开发库口令混淆），
  并从 `docs/PROJECT_MAP/INDEX.md` 与 `docs/PROJECT_MAP/03_BACKEND_DETAILS.md` 可达
  —— 下一个人（或下一个 AI 会话）不用问就知道默认是 123321。

- 历史 Provenance / Audit / Ledger                    （审计口径不变：payload 里仍然没有密码）
- 权限                                                （require_permission(USER_MANAGE) 不变）
- API compatibility                                   （老客户端传 password 照旧；不传 = 用默认）
- 本事项特有的：① 改密码仍然必填 ② 编辑账号留空 = 不改 ③ 密码永不回显/永不进审计
`@

### Blast Radius（L0～L3）

**L1** —— 改的是"建号时的默认值 + 文案 + 提示词"，影响面限于建号这一条链；
不碰钱 / 账本 / 订单生命周期 / 权限模型 / 迁移 / 历史事实（L3 的那些一项都没有），
也没有 L2 的契约破坏（字段类型、端点形状都没变，只是默认值从"必填"变成"有默认"）。
虽然是 L1，仍然配了完整判据与反向验证 —— 因为**它坏掉时是静默的**：
卡片上写着 123321、实际发的是别的密码，没有一行日志会说不一致。
