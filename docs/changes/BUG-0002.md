① 三件事：⑴ 名册卡 / 账户卡把软删账号的**内部号码**（`13923111638_del62` 这种带 `_del<id>` 后缀的值）原样画给用户看；⑵ 账户管理页只有「分类」一层过滤，停用与已删除的账号混在同一个列表里；⑶ 车辆管理的「绑司机」候选里还能选中**已停用 / 已删除**的账号。
② 现在的样子：删号 = 软删 + 把手机号**释放给新账号**，所以库里那行的 `phone` 必须变成 `号码_del<id>`（号码不能凭空消失，否则新账号建号会撞号）；但 `UserOut` 只下发 `phone` 一格，Android `UserDto` 也只有一格 —— 界面既不知道该不该显示它，也没有第二处信息能判断「这个账号是不是在回收站」。账户列表的过滤只有 `shownInRail`（分类）一层；绑车候选 = `vm.drivers` 直接按关键字过滤，没看 `is_active`。
③ 变化：`users.phone` 的**列内值一个都不动**，只在**读出口**多给两格派生信息 —— `phone_display`（可拨号的展示号码；号码已让给别人时为 None）与 `is_deleted`（回收站判据）；Android 端把「显示号码 / 状态筛选 / 绑车候选」三处从「自己猜后缀」改成「读后端口径」。
④ 不能变：`users.phone` 的落库值（表单回显 `draftPhone`、搜索、AI 别名都读原值）；删号 / 恢复 / 启用三个端点的既有语义与 400 文案；搜索口径 `val shown: List<UserDto> get() = hits ?: users`（判据脚本钉着）；`ui/dispatcher/UsersManageScreen.kt` 卡片里那块 `Surface(color = Color(0xFFFFF1C6))` 的「已停用」外观；历史订单 / 账本 / 权限。
⑤ 结论：以 **Presentation** 为主 —— 三处都是「同一份既有事实怎么被看见」，后端只增加**只读派生字段**（不定义新事实、不改不变量、不加表、不加迁移）。
⑥ 证据：后端 4 条新用例 `backend/tests/test_user_roster_phone_and_bin.py` + `_tools/qa/_check_user_account_status.py` 静态判据 + `_tools/qa/_reverse_verify_user_account_status.py` 注入全红 + 全量 pytest 无新增红 + 模拟器 5554 真机三处复测。

## ⑤ Data Contract

- **新增/改动哪些字段**：只加**出参**两格 —— `UserOut.phone_display: str | None = None`、`UserOut.is_deleted: bool = False`。`users` 表结构与写入值一个字不改（无新列、无迁移、无回填）。
- **Owner 是谁**：`users` 表与账号事实的 Owner 仍是账号域（`app/models/user.py` + `app/api/v1/users.py`）；号码的软删口径唯一处 = `app/services/soft_delete.py::dialable_phone`；回收站判据 = `app/api/v1/users.py::_in_recycle_bin`。
- **什么时候写 / 什么时候不写**：这两个字段**从不落库**，每次读时在 `_to_out()` 里现算（`out.phone_display = dialable_phone(u)`、`out.is_deleted = _in_recycle_bin(u)`）；账号不存在 / 没登录时按既有 401 / 404 处理，不产生半成品字段。
- **是否允许 NULL**：`phone_display` 允许 None，语义 = 「这个账号现在没有可拨的号（号码已经让给新账号了）」，⛔ **不是**「没填手机号」；`is_deleted` 是非空布尔。
- **历史数据怎么办**：**什么都不做**。后缀本来就在历史行的 `phone` 里（那是软删当时就写下的事实），`dialable_phone` 现场去后缀 —— 历史账号**自动**显示正确，不需要任何回填。
  ⛔ 反过来，若按「把历史行的后缀洗掉」来修，就必须回填历史、并且会破坏「删号后号码能重新建号」这条既有能力（新账号会撞号）。
- **迁移怎么做 / Rollback 怎么办**：**无迁移**（无 schema 变化）。Rollback = 把 `_to_out()` 那两行与 Android 三处改回去，历史数据不受影响。
- **删除本功能后历史数据还能不能解释**：能 —— 后缀仍在 `phone` 里，删掉派生口径只是回到「把内部值画给用户看」，账号身份、号码占用与账目都不受影响。

## ⑥ CHG 专章（FEAT / GOV 不适用时写「不适用：<理由>」）

### Before

在 5554 打开「账户管理」：卡片上直接画着 `13923111638_del62` 这种号码，没有第二行说明，用户只会以为号码坏了；一屏里停用、已删除、在用的账号混在一起，只有左栏的「分类」能筛，想找「还剩几个能用」得自己一格格翻；回收站里的账号卡片上「删除」还在（点下去后端回 400「这个账号已经删过了」）。
车辆管理 → 「绑司机」抽屉里，已停用（甚至已删除）的账号照常出现在候选里，选中后绑定成功 —— 之后派单才会一连串地不对。

### After

同样的动作：电话行画的是**能拨的号码**；号码已经让给新账号的账号，画灰字「号码已让给新账号」（不留白、不染成青绿，⛔ 也不把内部值露出来）。账户管理页顶部多了状态档 `全部 / 在用 / 已停用 / 已删除`，默认停在「在用」，档位筛空时说一句「这一档下没有账号 —— 上面换一档看看」。回收站账号的卡片只给「恢复」（绿），不再出现按不动的「删除 / 停用」；恢复撞号时后端只把 `is_active` 置回、号码仍归新账号，界面照灰字显示。
「绑司机」抽屉里只剩在用且未被删的账号，底部多一行「另有 N 个匹配的司机是已停用/已删除的账号，不在这里 —— 先把人在「账户管理」里启用。」

### Blast Radius（L0～L3）

**L1** —— 影响一组展示面（账户管理页、司机 / 货主 / 批发商名册卡、车辆绑司机抽屉）＋ 后端一个出参模型；不动写入路径、不动表、不动钱、不动权限。
之所以不是 L0：`UserOut` 是账号域对外的出口，多两格会跟着所有读账号的接口走（`/users`、`/users/{id}`、名册接口）。
