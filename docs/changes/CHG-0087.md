## ③ Boundary（边界：为什么这件事不该在代码边界以外解决）

结论：**这条线的落点只能是 AI 的能力面**，不能推给「让用户去页面点」或「后端再开一个专用端点」。

五问依据：

1. **用户侧**：派单员已经在用 AI 干同一批活儿（改单、发票台账、下游价），定价与让价是他当场判断出来的数；缺的只是「AI 说不说得出来」。
2. **代码侧**：四条端点在 `data/repo/AppRepository.kt` 与 `data/remote/api/Apis.kt` 齐备（`repo.priceFreight` / `repo.applyOrderDiscount` / `repo.clearOrderDiscount` / `repo.editArrearsUnit`）—— 数据层一行不用改，本单只写 `ai/` 这一层。
3. **重复侧**：手工页面与 AI 走的是**同一套端点**，不存在两套业务逻辑；卡片上的话由 `AiWriteAction` 的 blurb/details 承担说明责任（这一层就是「说明书的唯一出处」）。
4. **风险侧**：四条都动钱（司机运费 / 客户该付多少 / 一个单位还能赊多少）—— 所以定价给 MEDIUM（送达前随时能再定一次），其余三条给 HIGH ＋ 确认卡；两条**没有撤回按钮**的动作必须把理由写进撤回表（`AiRevert.kt` 的两条 `UNDO_NONE`）。
5. **能力侧**：让价的「按名字找行」必须落到**这一单真实存在的行**上（找不到就列出这一单的商品名让他挑），不靠模型猜行号；额度必须落到**确定的单位编号**上（名册按名字严格解析 → 命中唯一一个才允许动）。

**核心改动声明**：`android/app/src/main/java/com/tapmoay/sorders/ai/AiWriteService.kt` —— 为什么必须动核心：数据源接口（4 个方法）与处理器注册表都在这个文件里；钱相关四条按既有域的形状接进去，不另起一层框架（`AiWriteMoney.kt` 只提供规格与处理器，接线点全在核心文件里）。**没有动 README 之外的任何 Core 文件**：`data/`、`backend/`、数据库、权限点都零改动（前后对比见 ⑧ 证据表）。

## ④ Behavior Contract

```text
Input:
  - 定价：order（必填）＋ freight（必填，元，可填 0 ＝ 这一单不收运费）＋ category（可选：分类名；说「不适用」＝清空；不说＝沿用现在的分类）。
  - 让价：order（必填）＋ kind（抹零 / 减百分比，必填）＋ value（必填）＋ lines（商品名，一个或多个，用「、」分开；不说＝整单）＋ reason（可选）。
  - 取消让价：order（必填）。
  - 额度：unit（挂账单位名，必填）＋ limit（元，必填；说「不限额」＝清空）。
Output:
  - 一张确认卡（NeedConfirm）：卡上逐行写着这次要写什么（额度那张写「原来 → 改成」），以及这次做完会发生什么。
  - 确认之后：Done（带 undoToken 与 undoLabel）或 Done（undoToken = null，撤不回来的两条）。
Success:
  - 端点返回 2xx：定价 / 让价 / 取消让价 / 设额度都无返回体（幂等键由框架带上）。
Failure:
  - 参数缺失/格式错 → Rejected（如「让价方式只认两种：抹零（减一个金额）或减百分比（减几个点）」）；
  - 定价门 → Rejected：已撤销（「这一单已经撤销了，不用再定价。请如实告诉用户，不要换一张单去操作。」）、已送达且定过价（锁死那句 ＋ 为什么）、其余状态（如实说定不了）；
  - 让价找不到行 → Rejected ＋ 列出这一单的商品名让他挑；超过 200 行 → Rejected（如实说收到几行）；
  - 取消让价本来就没有 → Rejected（按后台原话「这一单本来就没有折扣。」拦下，不弹注定失败的卡）；
  - 额度：名册读不到 / 单条读不到（可能刚被删）→ Rejected ＋ 说清不许改去设别的单位；原来就是这个数 → 如实说不用改，一条都不写；
  - 后端非 2xx → 由框架转成给用户看的话（不吞错）。
Boundary Cases:
  - 定价 0 元是合法取值（＝这一单不收运费），不许当成「没填」；
  - 分类：后端 category_id 默认值就是 None ⇒「键不在」与「发 null」在后端是同一个结果（都是清空）∴「沿用」必须把**当前分类的编号**显式发回去；
  - 让价值四种坏法（空 / 非数 / 零 / 百分比到 100）一律在弹卡之前拦下；
  - 让价范围：整单是空集退路（不是「所有行编号」）；同名多行全都选上；
  - 额度 null（不限额）与 0（一分钱都不许赊）是两件事，payload 里用 JsonNull 与 "0.00" 分别表示。
Side Effects:
  - 定价写这一单的司机运费（与运费分类，若给了）；让价改写每一行的金额（退货按折后实付退）；取消让价按快照把每一行还原；额度写挂账单位的额度并留一条审计流水（谁改的、改前改后各是多少）；
  - 两条撤不回来的动作（定价 / 让价）**不留撤回路径**，卡片上直说、并在撤回表里写清理由与指路。
Authorization:
  - 四条全部只给派单员（AiRole.DISPATCHER）；不进 SHIPPER_ACTIONS；
  - 权限点仍由后端把关（定价 order:dispatch；让价与取消让价 order:edit；额度 ledger:edit）—— 越权会在后端被拒，AI 侧不另做一套授权。
Compatibility:
  - 动作总数上界 171 → 175；说明书整份 27807 → 28758 字符（整份上限 29000 不动）；带进上下文的参数约束 2471 → 2579（约束上限 2500 → 2600）；
  - 既有 171 个动作的 id / 参数 / 卡片文案一个字不改；货主清单 44 条不变。
```
