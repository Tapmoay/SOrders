## ① 六问

### 问 1：用户看到的是什么？期望是什么？

用户把「提示」开关**关掉**（默认就是这么来的：首次登录那一轮开、之后冷启动自动关）之后，屏幕上少掉的
不只是"教你怎么用"的句子，还包括这些：

- 我的账本页：「同一批货的两头，两边各记各的账，不会重复收钱。」「这里只有你欠公司的这一边：你自己卖货收回来的钱不经过本系统。」
- 派单员付款确认框：「钱真的出去了：账本「收支」里会写一行资金流水。」
- 退货确认框：「退回来的货会补回库存、账上按行红冲」「按这张申请实际退货：库存和账本在这一刻才变」。
- AI 助手设置页：「API Key 加密存在本机、不上传；费用你自己承担。」（整页唯一一句"数据去哪了"）
- AI 对话页编辑横幅：「正在编辑这条消息：发送后会重新回答，这条之后的对话会被撤掉」。

用户要的是：**只有「不重要的 / 繁琐的」才隐藏或简化**。上面这些一句都不属于那一类 ——
删掉它们，用户会在"钱怎么算、按下去会发生什么、数据去哪了、这一页现在是什么状态"这四件事上选错。

### 问 2：为什么现在不对？

两件事叠在一起：

1. **判据只会逐句记**：2026-10-03 E2E 走查 P25 那次，把货主账本页被点名的那一句改成了常显，并在
   `_hint_inventory.OVERRIDE` 里写了一条"这一句必须一直看得见"。**紧挨着它的同族句子照样挂在 `Hint` 上**，
   谁也不红 —— 逐句记录只能保住被点过名的那一句。
2. **分类器只认"像不像解释"**：`_hint_inventory.classify()` 的判据是长度（≥16 字，或 ≥12 字且带"会/可以/自动/之后"这类标记词）；
   一句话只要够长、够像解释，就判成 `EXPLAIN`（= 可以藏在开关后面）。**它从来不问这句话删掉会不会让人做错决定。**

### 问 3：谁受影响？

三个端所有**关掉过提示开关**的用户（默认第二轮冷启动就会关），其中：

- 货主 / 批发商：账本口径那几句（钱到底算谁的、会不会重复收）；
- 派单员：退货与付款那几句（按下去库存回补、账上红冲、钱真的出去了）；
- 用 AI 助手的任何人：Key 存在哪、上不上传、费用谁承担、编辑这条消息会撤掉什么。

### 问 4：不改会怎样？

「关掉提示」会顺手关掉用户的**判断依据**：他看不到"这两个数为什么一样大"，就会以为系统算错账；
看不到"钱真的出去了"，就会以为点一下只是存个草稿；看不到"这条之后的对话会被撤掉"，就会把上下文弄丢。
而用户从没要求过"把这些也关掉" —— 他要关的是**不重要的 / 繁琐的**那一类。

### 问 5：改哪一层？

Android 展示层（15 处文案挂法）＋ 工具链（分类器的分类规则与红线）。
**不碰后端、不碰请求/响应、不碰库表、不碰设置键、不碰开关机制。**

### 问 6：怎么证明改对了？

- 新判据 `_tools/qa/_check_hint_key_explain.py`：逐条钉住"四族词表在、分类器认四族、21 条关键解释句一条都不许挂在 `Hint` 上、规范写了四族与拆句、文档三件齐"；
- 新反验 `_tools/qa/_reverse_verify_hint_key_explain.py`：**17 条注入**（摘词表、废 `key_family`、拆分类器那一支、把四处关键句改回 `Hint`、删规范里的族名/拆句、删文档三件），逐条证明上面那些检查真的会红；
- 既有红线 `_tools/qa/_check_hints.py`：**31 项**（新增第 2b 组两组判词）；
- Android 单测 `testEmuDebugUnitTest`：**1160 项 0 失败**（文案改动不许碰编译）；
- 真机（模拟器 5556 货主 / 5558 司机）把「提示」开关**关掉**，逐屏看那几句话还在不在。

## ④ Behavior Contract

1. 一句话只要**属于四族**（钱的口径 / 不可逆的后果 / 隐私与费用 / 当前状态的含义），它出现的那次调用就**不许**是 `Hint(`。
2. 同一次调用里既有教法句又有关键句 ⇒ **拆句**：教法句留 `Hint(`，关键句单独写一条 `Text(`（整条改 `Text` 会让 §1 报红，因为它把教法句变成"裸露的解释句"）。
3. `key_family(text)` 是**唯一**的判定入口：返回族名 ⇒ 这一句属于该族；`None` ⇒ 不属于任何一族（照旧由 `classify()` 按长度/标记词定）。
4. `classify()` 对四族的返回值**永远不是** `EXPLAIN`（乙族 → `WARN`，其余三族 → `DATA`）。
5. 关掉「提示」开关之后，**21 条关键解释句一条都不消失**（判据里逐条点名）。
6. 教法句照旧随开关消失 —— 开关依然是"有效"的：它管的是"不重要的 / 繁琐的"那一类。
7. `_check_hints.py` 第 2b 组的两条判词同时成立：认出的条数 ≥ 下限 15，且挂到开关上的 = 0。
