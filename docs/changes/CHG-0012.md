删除在左编辑在右）。点击热区、回调、业务行为一字不变。

④ `AddressScreen.kt` 的取数、三段列表结构、搜索、抽屉表单、判据锚点（`ContactPickerSheet(`、
`vm.contacts.filter {`、`ContactCategoryPane(` 的左栏结构、`FormGroup(…"起点（可选，从这出发）"…)`）一律不动。

⑤ **Presentation**（纯呈现层）。

⑥ ① 三张卡里 `IconButton(` 出现 0 次、`CardActionIcon(` 各 ≥1 次；② 联系人 / 地点卡里「删除」排在「编辑」之前；

## ⑥ CHG 专章

### Before

打开「地址与联系人」页 → 三张卡的右侧是**裸图标按钮**：
`AddressCard` 竖排「删除（红）/ 编辑」两个 18dp 裸图标；`ContactCard` 与 `LocationCard` 是
「**编辑在左、删除在最右**」两个 18dp 裸图标。删除最右＝正好落在右手最容易点到的地方，而它是最危险的那个。

### After

同样的位置、同样的点击区域，变成**圈底图标**（`CardActionIcon`：12% 语义色圆底 + 同色图标，与卡上
`TintedIcon` 说明性图标同一套语言）：`ContactCard` / `LocationCard` 变成「**左＝删除、右＝编辑**」；
`AddressCard` 仍是竖排，但两个动作都换成圈底（删除在上、编辑在下 —— 位置由 §5.0 的竖排豁免管）。

### Must Preserve

```text
- 历史订单 / 历史金额 / 已冻结的 Pricing Fact
- 历史 Provenance / Audit / Ledger
- 权限
- API compatibility
- 本事项特有的：AddressCard 的竖排顺序（删除在上、编辑在下，用户点名两遍）；
  三张卡的 onClick 回调与签名；本页所有判据锚点（含 _check_form_panel_style / _check_contact_binding /
  _check_contact_categories / _check_user_search / _check_hints 钉住的字符串）
```

### Blast Radius（L0～L3）

**L0** —— 只改一个 Compose 文件里三个私有 composable 的**动作外观与顺序**：没有字段、没有端点、没有迁移、
没有权限、没有审计；页面其余部分与所有既有判据的锚点均不变。
