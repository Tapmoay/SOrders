① 用户 2026-10-11 逐字：「我批发商管理他那个分类啊，他那个分类是**跟账号管理不一样**的，**他现在串在一起了**。他那个分类是**可以新建的、另外建的**。只不过我们**账号管理拉取他们的分类的时候是搞 2 级分类**；当然，我们这些**子分类是不会拉取主分类**的。也就如**司机管理**，还有其他的**批发商管理**，**他们是有自己的分类的**，他们的分类基本上就是 **1 级**、不会有 2 级的。然后我们的**账号管理**，他的那个分类他是**有 2 级的**，他是**主动拉取**的，而且我们分类**已经固定好了**的。」
—— 一句话：**分类名册原本只有一份（账号管理那份，谁都在用、谁都能加），现在要拆成两份**：账号管理自己那份**一级固定六类、只读**；批发商 / 货主 / 司机各自一份**可新建、只有一级**；账号管理把模块名册**拉取**成对应一级下面的**二级**。

② 现状（改之前，全部带 `文件:行号`，见 ② 末「现状调查」）：派单员在「批发商管理 / 货主管理 / 司机管理」左栏看到的分类、以及「账户管理」左栏看到的分类，**是同一张表 `user_categories` 的同一批行**；三池页新建一个分类 = 往账号名册里加一行一级分类。

③ 「分类」这个事实从「一份」变成「按模块各一份 + 账号侧一份」，并且账号侧多了「拉取」这件事（读别人的名册当自己的二级）。模块名册的**写权**归各模块页，账号名册的**一级写权**收回（AI 与人都不能新建）。

④ 不能变：账号分类的**六个一级名字与顺序**（CHG-0112 / CHG-0121 的契约）；「账号那一格存的是叶子名」这条老规矩（`users.category` 里的值一个字不改）；两级深度（不准出现三级）；名册的**改名级联 / 占用中拒删 / 建号顺带补分类**三条老规矩；车辆分类（`vehicle_categories`）一个字不动；软删 + 撤销这条用户硬规矩。

⑤ **EXTENSION IMPL + PRESENTATION**：新版块/接口落在既有分类扩展点旁边（不动 Core）；账号册出参只加字段（兼容）。

⑥ 判据 `_tools/qa/_check_category_rosters_split.py` 全绿 + 反验 `_reverse_verify_category_rosters_split.py` 13/13 注入全被抓 + 后端新单测 `backend/tests/test_module_categories_split.py` 15 例 + CHG-0112 老单测 10 例仍绿（新 15 + 老 10 合跑 25 passed）+ Android 单测 1708 例全绿。

## ④ Behavior Contract

```text
Input          模块页：GET/POST/PATCH/DELETE/POST:reorder/POST:restore /api/v1/module-categories（module = members | shippers | drivers）
               账号页：GET /api/v1/user-categories（出参多三格：fixed / pulled / module）
Output         模块页：ModuleCategoryOut（id / module / name / sort_order / user_count），平表、没有 parent_id
               账号页：UserCategoryOut 列表 = 库里那些行（一级 fixed=true）++ 拉取行（id 为负、pulled=true、module=…）
Success        模块册新建/改名/排序/软删各写一行审计并返回最新行；账号册 GET 把模块册活行按 kind 挂到对应一级下面
Failure        400 账号册不能新建一级 / 不能给模块的一级挂子类 / 拉取行不能改删排序；409 模块册重名；
               400 占用的模块分类删不掉；404/400 恢复一个没被删掉的名字
               （失败时不发生什么：不产生半行、不改 users.category、不悄悄把分类搬到别的一级下面）
Boundary Cases ①「派单员」没有模块页 ⇒ 账号册里它下面仍可写（老数据不悬空）
               ② 司机一份名册喂三个一级（小车 / 大车 / 挂车），三个格子的编号互不相同
               ③ 模块一级在账号册里被改名或缺失时：少拉一格，绝不凭空造一级
               ④ 同名分类在两个模块册里各有一行，互不影响
               ⑤ 老库里挂在模块一级下面的历史子分类：迁移搬进模块册，账号册里不再有这一行
Side Effects   写审计（MODULE_CATEGORY_UPSERT / DELETE / REORDER / RESTORE）；登录建号时会照旧补账号册
Authorization  模块册写操作 = Permission.USER_MANAGE（与账号 / 车辆名册同一个权限点，⛔ 不新建体系）
Compatibility  Compatible：账号册 GET 只加字段、老字段与顺序照旧；新增端点不替换任何既有端点
```

## ⑤ Data Contract

- **新增/改动哪些字段**：
  - 新表 `module_categories`：`id` / `module`（`String(16)`，members | shippers | drivers）/ `name`（`String(32)`）/ `sort_order` / 软删列（`is_deleted` / `deleted_at`，来自 `SoftDeleteMixin`）。
  - 账号册出参 `UserCategoryOut` **只加**三格：`fixed: bool = False`、`pulled: bool = False`、`module: str | None = None`（均为默认值，老客户端看不懂也不影响）。
  - `users.category` / `user_categories.parent_id` **一个字段都没加没减**。
- **Owner 是谁**：模块名册的 owner 是**模块页自己**（批发商 / 货主 / 司机三页各写自己 `module` 那一段）；账号侧的「拉取」是**只读投影**，owner 不是账号册。
- **什么时候写 / 什么时候不写**：只在模块页的新建 / 改名 / 排序 / 软删 / 恢复时写 `module_categories`；账号册的三个写端点**永远不写**模块名册（⛔ 也不写自己的一级）。
- **是否允许 NULL**：`deleted_at` 允许（未删时为 NULL）；`module` / `name` / `sort_order` 不允许。
- **历史数据怎么办**：迁移 035 把「挂在批发商 / 货主 / 小车司机 / 大车司机 / 挂车司机这五个一级下面的子分类」逐行搬进对应模块名册（`MOVE` 映射，`{module: members|shippers|drivers}`），**同名活行已在模块册里就不重复插**（`if not already`），**无论如何都撤掉账号册里那一行**（搬不是删：内容相同、只是换了 owner）；「派单员」下面的子分类**不搬**（没有派单员管理页，账号册里仍是可写的那一格）。
  ⛔ 过去没有 provenance 的一律按 `NULL / unknown` 处理 —— 本事项不动历史事实：`users.category` 里的值原样保留。
- **迁移怎么做 / Rollback 怎么办**：`backend/app/migrations/035_module_categories.py`（`VERSION = 35`，由 `_runner.discover` 自动发现，不需要登记）；`upgrade` 幂等（跑两遍结果一致，单测覆盖），源码表不存在就 return。Rollback：把 `module_categories` 整表删掉、把账号册里那些行按同名重新插回（`name` / `sort_order` / `parent_id` 都能从 `module` + `MODULE_LEVEL_ONES` 推回来），`users.category` 从头到尾没被改过 ⇒ 回滚后老界面立刻恢复原样。
- **删除本功能后历史数据还能不能解释**：能。`users.category` 一直是叶子名，与分类名册存在与否无关；模块名册只是「有哪些可选分类」的一份清单。

## ⑥ CHG 专章

### Before

派单员打开「批发商管理」左栏 → 看到的是**账号管理那份名册**（`ui/dispatcher/UsersManageScreen.kt:119` 的 `UserCategoriesViewModel`）；点「管理分类」新建一个「食堂客户」→ **写进 `user_categories` 的一级行** ⇒ 「账户管理」左栏立刻多出一个一级分类「食堂客户」，而它跟「批发商 / 货主」这些身份分类平起平坐。反过来，在账户管理里把「批发商」改名，批发商管理左栏也跟着变（同表同接口）。

### After

同一个动作：批发商管理左栏读的是**它自己那份名册**（`module_categories` 里 `module='members'`）；新建「食堂客户」只写这一份 ⇒ **账户管理左栏一级仍然是固定的六类**，而「食堂客户」作为**二级**出现在「批发商」下面（拉取）。在账户管理里想加一级、或想给「批发商」挂子分类 → 400 并指路：「请到批发商管理那一页的「管理分类」里建 —— 建好之后这里会自动拉取成二级。」拉取行在账号册里**只读**（界面画「只读」+ 一句「要去哪儿改」，连端点都会拦）。

### Must Preserve

```text
- 历史订单 / 历史金额 / 已冻结的 Pricing Fact
- 历史 Provenance / Audit / Ledger
- 权限
- API compatibility
- 六个一级分类的名字与顺序（CHG-0112 / CHG-0121）
- users.category 存的叶子名（改名级联照旧）
- 车辆分类名册与它的页
```

### Blast Radius（L0～L3）

**L2**：新增一张表 + 一个迁移 + 6 个端点，账号册出参加字段；不改钱、不改订单生命周期、不改权限、不改历史事实。App 侧只有名册页与三池页左栏（L1 局部行为）；「账户管理」左栏的两级与筛选**复用**既有 CHG-0112 机制（拉取行带 `parent_id` ⇒ 自动成二级），一行没重写。
