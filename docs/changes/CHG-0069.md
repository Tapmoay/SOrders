① **挂完账之后，订单详情底部还是「现场支付 / 挂账」两颗按钮** —— 用户原话（ref **m01874**，逐字）：「挂完账之后仍然还有挂账按钮在那里呃这个不应该这样子的，它仍然的按钮分别是现场支付和挂账…如果挂完账之后，它这些按钮要变成什么要变成核销啊，是这样子的要核销账啊，是这样子的，而不是可以又可以挂账啊。」而这两颗按钮在**已挂账**这一档上点了都是坏的：再点挂账＝把欠款**静默改挂到另一家**（`backend/app/api/v1/orders_payment.py:257-297`，`charge_order` 里唯一的门 `:271 _reject_if_already_collected` 只挡「已收款」）；点「现场支付」＝**欠款静默蒸发、账上一笔流水都没有**（同文件 `:212-226` 的 docstring 自己写着这条路不写收款单、不写现金流水，`:239-242` 把 `arrears_unit_id` 清空）。
② 派单员在订单详情底部「收款与挂账」一区里操作（`android/app/src/main/java/com/tapmoay/sorders/ui/order/OrderDetailScreen.kt:1411-1479`，仅派单员可见）：未收款未挂账时是「现场支付 ＋ 挂账」；挂账（`POST /orders/{id}/charge`，`payment_method = "arrears"`）之后 `paid` 仍是 False、`settledAmount` 仍是 0 ⇒ 判据 `OrderStatusModel.canChargeToArrears` 仍为真 ⇒ **两颗按钮原样都在**（用户报的正是这一档）。核销能力今天已经在「账本」页：`ui/dispatcher/LedgerPersonScreen.kt:384 SettleOrderDialog` ＋ `POST /ledger/receipts`，只是订单详情这一页没有入口。
③ 订单详情底部按钮区的**分档依据多一档**：已挂账（`payment_method == "arrears"` 且未收款、未核销）不再是「未收款」那一档 —— 主按钮变「核销」（一点＝**整单**核销）、次按钮变「改挂账单位」（挂错单位是真实场景，留一条纠错路）；已收款那一档不再显示两颗禁用按钮，改成「**已收清**」。另外，核销前若这单**没有客户档案**（临时货主），弹窗里能**就地建 / 关联客户档案**。
④ 后端账务语义一行不改：`charge_order` / `pay_order` 的行为与 docstring、`create_receipt` 的算法与三条拒（`backend/app/services/accounting_service.py:355-469`）、收款单/流水/挂账单位的表结构（`arrears_units` 仍与 `customers` 没有直连）、账本页那套核销（整单 / 按商品）全部原样 —— 本次只是把「已挂账」这一档画出来，并把**既有的**核销端点接上这一页。

- **什么时候写 / 什么时候不写**：只有用户**真的点了**「核销」且后端接了才写（收款单 ＋ 流水 ＋ `orders.paid`）；点开弹窗、改一半取消、只看看不点，都不写。
- **是否允许 NULL**：核销请求里 `orderProductIds` 为空数组（口径：整单核销，与账本页「一行不勾＝整单」同一条规则）；`note` 留空存空串，不是 `NULL`。
- **历史数据怎么办**：历史订单、历史收款单与流水一个字不动。本次只是给「已挂账」这一档**画**出核销入口 —— 它不会回头去改任何一条已经存在的账。

- **迁移怎么做 / Rollback 怎么办**：**没有** schema 变更，不需要迁移。回滚 = `git revert` 这一个提交：按钮区回到今天那两颗、两个共用件与 AI 判据一起消失，后端不用动。
- **删除本功能后历史数据还能不能解释**：能。核销走的是**原有的**收款单与流水（与账本页核销出来的那一条结构上不可区分），删掉这一档不影响任何一条已存在的账。

## ⑥ CHG 专章（FEAT / GOV 不适用时写「不适用：<理由>」）

### Before

派单员把一张已送达的单挂账（`payment_method = "arrears"`，`paid = False`、`settledAmount = 0`），回到订单详情底部：**「现场支付 ＋ 挂账」两颗按钮原样都在**（判据只挡「已收款」）。
- 再点一次「挂账」：`charge_order` 唯一的门只挡「已收款」，于是这单被**静默改挂到另一家**（旧单位名下那笔欠款消失、新单位名下出现，既不拒绝也不提示）。
- 点「现场支付」：`pay_order` 把 `paid = True`、`arrears_unit_id` 清空，**不写收款单、不写资金流水** —— 欠款静默蒸发，账上没有任何痕迹。
- 已收款的单：底部显示「已收款（禁用）＋ 挂账（禁用）」两颗灰按钮。

### After

同样这一页，按这一单的档位画：
- **已挂账**：主按钮「**核销**」（一点＝整单核销，金额取 `order.arrearsAmount`）＋ 次按钮「**改挂账单位**」（复用既有挂账弹层，挂错单位有纠错路）。「现场支付」在这档**收掉不画**（它点下去就是上面那条静默蒸发）。
- **已收款**：显示「**已收清**」，两颗禁用按钮一并收掉。
- **未收款未挂账**：与今天逐字一样（「现场支付 ＋ 挂账」）。
- 核销时若这单**没有客户档案**（临时货主）：不许发注定失败的请求，弹窗给一句引导 ＋ 就地**建 / 关联**一份客户档案（与 CHG-0068「就地新建供应商」同一族）；有档案的直接弹出「核销 ¥X」确认。
- AI 侧：已挂账的单上再让 AI 挂账，`ChargeOrderHandler` 在 `prepare` 就拦住并如实说明（不再弹一张注定失败的确认卡）。
