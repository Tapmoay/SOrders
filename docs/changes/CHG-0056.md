## ① 六问

```text
① 改的是什么？
   a) 「通知权限开着没有」这个读法**收口到唯一一份**：新建 `core/NotifyPermission.kt`
      （`enabled(context)` / `shouldPrompt(enabled, promptedThisLaunch)` / `markPrompted()` /
      `openSettings(context)` ＋ 从设置页搬来、升级成共用的 `startFirstResolvable(context, preferred, fallback)`）；
   b) 首页进门的**硬提示**：进页面判一次，没开就弹一张带图标的弹层
      （「手机上还没允许发通知」＋「去开启」跳系统设置页 ＋「以后再说」出口）；
   c) 「这一轮拦过了」只记在**进程内**（`NotifyPermission.promptedThisLaunch`，⛔ 不落盘）；
   d) 设置页（「我的 → 消息提醒」）那份私有的读法与跳转删掉、转发到共用那一份；
      两张卡不再顶同一个图标（通知卡显式传 `Icons.Default.NotificationsOff`，默认值仍是电池）。

② 为什么要改？
   用户 2026-10-06 的裁定（m01132 第⑤条）：「这个一定要有的这个权限，我们**如果权限不足的话，
   我们就给他开**」；动机是同一次说的**账会乱掉**。而现状是**静默降级**：权限关掉之后 App
   照发（系统不弹），人不会去翻通知栏 —— 用户也永远不会自己想到去系统设置里找这一项。
   尤其司机端：派单来了不响也不弹，现场那层提醒等于没有。

③ 谁受影响？
   三个角色的首页（`ui/home/RoleHomeScreen.kt` 是三端共用的进门页）、「我的 → 消息提醒」那张卡、
   以及盯提醒链路的既有红线（`_tools/ai/_check_notify_guardrails.py` 与 `_check_alert_background_all_roles.py`）。

④ 不改会怎样？
   「权限不足就给他开」这条**用户已经明确要求过**（m01132 第⑤条），而现状是只有一条路：
   权限申请那一刻的系统弹窗 —— API 32 及以下、或者已经被永久拒绝的人，连那条回调都走不到，
   App 一声不响地降级，而通知是提醒三层里唯一的现场通道。

⑤ 有没有更小的改法？
   有，三条都被否了：
   · 只在**权限申请回调**里判一次 → API 32 及以下 / 已被永久拒绝的人走不到那条回调，等于没改；
   · 每次都弹 → 用户点过「以后再说」之后每次进首页都弹，是骚扰（而且会被当成卡死）；
   · 把「拦过」**落盘**（一辈子只弹一次）→ 用户后来自己把权限关了，就再也不提醒了，
     与「权限不足就给他开」正相反。
   ⛔ 也不做**拦路页**：提示只叠在页面上，页面照常进出（否则点不开 App 的人都得先答这一题）。
```

## ③ Boundary

- **结论**：**UI（一个共用件的读法与提示）**，Blast Radius **L1**
- 逐问依据：
  · **数据 Owner 变了吗**？没有。没有新字段、没有新键 —— 本刀**一行落盘都没有**。
  · **有没有新的写入**？没有（唯一那份状态是进程内的静态变量）。这正是判据要钉的一条。
  · **算法动了吗**？新增一个**纯判定** `shouldPrompt(enabled, promptedThisLaunch)`（两入一出，四组合有单测）；
    既有的播报 / 去重 / 渠道判定一个没改。
  · **权限动了吗**？**申请清单没有变化**（`POST_NOTIFICATIONS` 早就在 `AndroidManifest.xml` 里、早就在申请）；
    本刀只改「没开的时候怎么办」。
  · **状态机动了吗**？没有。
- **核心改动声明**：这一刀只改「**没开通知权限时，进首页会不会看到一张让他去开的提示**」，
  不改「什么时候申请权限、什么时候发通知、谁能收到」。

## ④ Behavior Contract

- **Input**：`Context`（首页 / 设置页）＋ 当前系统里 SOrders 的通知开关（`areNotificationsEnabled()`）＋ 进程内的 `promptedThisLaunch`。
- **Output**：至多一张 `CardAlertDialog`；点「去开启」时一次 `startActivity`（系统设置页）。
- **Success**：进首页时权限没开且本轮还没拦过 → 弹一次；「去开启」真的到系统设置页；「以后再说」关掉、页面照常。
- **Failure**：读不到开关 / 打不开系统设置页 → 静默降级（`startFirstResolvable` 兜底到应用详情页）——
  最多少一次提示，⛔ 不许让首页崩、也不许卡住进门。
- **Boundary Cases**：
  · 权限开着 → 一声不响（不弹）；
  · 刚点完系统弹窗的「允许」→ 那一下的授予结果**当开着看**（`grantedNow` 为真即视为开），不再补一张提示；
  · API 32 及以下 / 权限已被永久拒绝（没有可申请的权限）→ 走**同一道判定**（`guideNotifyPermission(false)`），
    只要开关是关的照样弹；
  · 同一次启动里进首页 → 只弹一次；进程被杀再启动 → 允许再拦一次（这不是「落盘记住」）；
  · 用户点「以后再说」→ 同一轮不再弹（`markPrompted()` 已经记过）；
  · 「我的 → 消息提醒」那张卡与首页弹层**同一句话逐字相同**（两处入口口径不漂）。
- **Side Effects**：一次 `areNotificationsEnabled()` 读；点「去开启」时一次 `startActivity`。没有网络、没有后台任务、没有落盘。
- **Authorization**：无变化（仍只看本机开关）。
- **Compatibility**：老版本没有这个文件；升上来行为就是「没开就拦一次」，⛔ 不写任何盘上痕迹。

## ⑤ Data Contract

- **改动哪些字段**：无。后端零字段；客户端本刀**没有新增任何持久化键**。
- **唯一那份「状态」**：`NotifyPermission.promptedThisLaunch`（`var`，`private set`，进程内） —— App 一退就没了，
  这正是口径（⛔ 不落盘：用户后来自己关了权限，再进首页还能被拦一次）。
- **什么时候写**：`markPrompted()`（弹之前记一次）。
- **是否允许 NULL**：不适用（布尔，默认 false）。
- **历史数据 / 迁移 / Rollback**：无迁移；回滚 = 撤掉这一提交，不留任何盘上残渣。
- **删除后能否解释**：删掉标记只意味着「同一次启动里可能多弹一次」。

```kotlin
// core/NotifyPermission.kt:39  读法 / 判定 / 跳转三件事的唯一一份
object NotifyPermission {
    fun enabled(context: Context): Boolean =
        NotificationManagerCompat.from(context.applicationContext).areNotificationsEnabled()

    /** 这一轮启动拦过没有（⛔ 不落盘：用户后来关了权限，再进首页还得拦一次）。 */
    var promptedThisLaunch: Boolean = false
        private set

    fun markPrompted() { promptedThisLaunch = true }

    fun shouldPrompt(enabled: Boolean, promptedThisLaunch: Boolean): Boolean =
        !enabled && !promptedThisLaunch

    fun openSettings(context: Context) { /* ACTION_APP_NOTIFICATION_SETTINGS，兜底应用详情页 */ }
}

// ui/home/RoleHomeScreen.kt:75  进首页判一次（申请回调末尾与「没有可申请的权限」那一支都走它）
fun guideNotifyPermission(grantedNow: Boolean) {
    val ok = grantedNow || NotifyPermission.enabled(permContext)
    if (NotifyPermission.shouldPrompt(ok, NotifyPermission.promptedThisLaunch)) {
        NotifyPermission.markPrompted()
        showNotifyGuide = true
    }
}

// ui/home/RoleHomeScreen.kt:320  提示只叠在页面上（不是拦路页）
if (showNotifyGuide) {
    CardAlertDialog(

        dismissButton = { TextButton(onClick = { showNotifyGuide = false }) { Text("以后再说") } },
    )
}
```
