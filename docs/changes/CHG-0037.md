# CHG-0037 · 报表中心金额配色改口径：**带负号的金额一律红**

> 用户 2026-10-05 看过 CHG-0036 的效果之后（报表中心首页：营业利润 `−¥12053.69` 是**橙**的、「别人欠我」`¥72664.4` 是**红**的），原话：
> 「**哦我说的是如果是负的钱的话，就是欠钱，只要是带负号的都是用红色的，其他的用其他颜色或者黑色都没关系。**」

① 金额的颜色**不是按「这个数是不是负的」定的**，而是按「这一格属于哪个主题」定的，于是出现两种自相矛盾的画法：
**(a)** 亏损/净流出的营业利润 `−¥12053.69` 画**琥珀**（当成"警告"而不是"负钱"）；
**(b)** 反过来，`¥72664.4` 的「别人欠我」（**正数**）画**红**；老报表页里商品毛利为负时仍然画**绿**（`ReportCenter.kt:321` / `:425` / `:1296`）。
用户要的是一条更简单、也能自己一眼查的规则：**数字自己带负号 ⇒ 红**；别的金额用什么色「都没关系」。

② 派单员在报表中心（v2 首页五张表卡 + 11 个下钻节点，以及抽屉里那 11 个老页面）看"这一段赚没赚、钱够不够、欠了多少"。他要能在**数字本身**上看出正负 —— 而不是先记住"这格的主题色是什么"。

③ 变的是**颜色判据**这一件事，落点六处：
- `ui/dispatcher/report/ReportV2Model.kt` 的 `amountTone(v)`：`if (v < 0) Tone.WARN` → `Tone.BAD`（连带 `Palette` 与 `amountTone` 的文档注释）；
- `ui/dispatcher/report/ReportV2Nodes.kt` 四处**可为负却按别的条件上色**的点：税账「这一段应纳增值税」（负数是留抵，原画蓝）、客户「还能欠多少」（负数是超额，原按 `overLimit` 判）、客户欠款串（原 `> 0` 才红）、司机待结运费串（原 `> 0` 才红）；
- `ui/dispatcher/ReportCenter.kt`（老页面）三处**商品毛利**：`营业纵览` / `商品经营` / `经营利润`，恒画绿 → 改成按正负；
- `ui/dispatcher/ReportCenter.kt`（老页面）两处**留抵**（「该交的增值税」为负 = 进项比销项多）：`:1324` 经营利润页那张增值税卡、`:1672` 税账页大数，原本画**绿**（把留抵当"好事"）→ 改成按正负（负 ⇒ 红 `#FF0013`，正数仍是本页的橙 `#FF6B2C`）。

④ 明确不动：
- **数字与口径**：一个数都不变（同一个「上周」窗口的每个值都要逐项对得上）；
- **接口 / DTO / 路由 / 权限**：零改动（纯渲染层）；
- **文案与布局**：CHG-0036 刚定的「金额列固定列宽内左对齐」「提示总开关」原样保留；
- **老页面已经按正负上色的两处**：资金收支「净流入」（`ReportCenter.kt:720`）、经营利润「营业利润 / = 营业利润」（`ReportCenter.kt:1281/1304`）——它们本来就是对的，改成同一套写法即可，颜色不变；
- **利润表里的"结构减号行"**（`− 商品成本` / `− 司机运费` / `− 期间费用` / `− 车辆折旧` / `− 算不出成本的收入`）：它们是**公式的运算符**，值本身是正数，保持中性（黑/灰）—— 用户给的自由度就是「其他的用其他颜色或者黑色都没关系」。

⑤ Core / Extension / Infrastructure **都不是** —— 这是纯 Presentation：只决定一个已经算好的数字**画什么颜色**。要动 Core 的三问（数据模型要不要改？接口契约要不要改？别的模块会不会受影响？）答案全是否，所以不触发核心改动声明。

⑥ 一条判据（`_tools/qa/_check_report_money_color.py`，会被 `_check_all.py` 自动收进去）+ 它的反向验证（注入"把负数画回橙色""把结构减号行也染红""商品毛利恒绿"等，判据必须当场红）+ 模拟器 5554 截图（负数红、正数不是红、结构减号行仍是黑）。

## ④ Behavior Contract

```text
Input     某个金额（数值或已经格式化成 "¥..." 的字符串）在某个渲染点被画出来
Output    该金额的文字颜色
Success   数值 < 0 ⇒ 红（v2 = Palette.bad #FF4D4F；老页面 = 本页既有的 #FF0013）
          数值 ≥ 0 ⇒ 该格原有的语义色（绿 / 蓝 / 琥珀 / 灰 / 黑都允许，用户明确说"都没关系"）
Failure   纯渲染没有运行期失败；数值解析不出来（null / 空串 / "—"）按 0 处理 ⇒ 绝不画红

          「—」（算不出成本的保本营业额等）⇒ 不适用本条；
          结构减号行（− 商品成本 …）⇒ 值本身是正数，保持中性色；
          同一个负数在 v2 与老页面必须**都是红**（红的具体色号两页各沿各的，本轮只统一语义）。
Side Effects  无（不发请求、不写库、不改文案、不改布局）
Authorization 无变化（还是报表中心原有的角色权限）
Compatibility 纯客户端渲染：老版本 App 不受影响；后端零改动 ⇒ 不存在"新老客户端口径不一致"
```
