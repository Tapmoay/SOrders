# CHG-0129 · 派单时按订单路线自动带出货主运费（默认值 · 手改优先 · 说清选了谁）

> 变更单（CHG）：把「运费模板**早就绑了路线**」这件事接到派单动作上 —— 派单抽屉打开（以及换司机）时，
> 按**这一单的地点路线**挑一条最贴近的价目，把钱填进运费框当**默认值**，并显示「取了哪一条、凭什么」。
> 不改数据库结构、不加端点、不加权限点、**一个字节都不写库**。
> 由来：用户 2026-10-15 口述 —— 「运费模板已经绑定了路线，派单时路线匹配就直接带出钱。」
> 口径（用户授权父会话定下，本单逐条兑现）：
> ① **自动填默认值 ＋ 手改优先**：自动带出的钱只是默认值，用户改过就以人为准（⛔ 不许在他改完之后又覆盖回去）；
> ② 同一条路线命中多条时取**最贴近**的一条（同路线 → 分类 → 车型 → 最近改过），并把**选了哪一个**在界面上显示出来；
> ③ 匹配不上就**什么也不填**（⛔ 不猜一个价填进去），界面维持原样；
> ④ ⛔ 不碰「钱只算一处」的既有口径：`backend/app/services/driver_pay.py` 仍是唯一算司机应得的地方 —— 运费模板的钱是**货主运费**，两者不许混。

## ⑥ CHG 专章（FEAT / GOV 不适用时写「不适用：<理由>」）

### Before

派单员在池页点「派单」→ 抽屉里选司机 → 手动滚到「运费模板」下拉，从一长串价目里**自己认出**哪一条是这条线的（同一条路线可能有三条：价格一 / 价格二 / 价格三），或者干脆自己敲一个金额。
界面上没有任何东西告诉他「这一单走的是哪条线」—— 价目绑了路线这件事只存在后端，派单这一步每次都要人来翻译一遍。

### After

同一个动作：抽屉打开的瞬间（以及**每一次换司机**）自动按这一单的地点路线去问一次，匹配上就把钱填进「一车运费」框，并在框下写一行：
「已按路线自动带出「<价目名>」—— 可改，改过之后不再自动覆盖；这条路线上一共 N 条价目，取的是…（为什么比另一条更贴近）」。
派单员可以直接用，也可以改：**手一落笔就记为「人填的」**，之后换司机回来的在途结果不再回填；手选模板走的是同一条路。匹配不上时框**保持原样（空）**，只写一句「… —— 运费留空，自己填」。
