# CHG-0121 账号分类改为**按身份自动推导**（不再由人挑）

- **ID**：`CHG-0121`　**类型**：CHG　**状态**：已关闭　**Owner**：DSH `session-bd8fe093-…`
- **Blast Radius**：**L1**（写路径行为 + 一次数据回填；不动钱的算法、不动订单/账本）

## ① 六问

```text
① 解决什么问题？  用户原话（逐字要点）：「批发账号管理……其实已经分好了、已经挂上了不同的身份，既然挂上了
                  不同的身份，我们就**自动分类**啊，不用我们再手动分类了。像我现在如果选『批发商』，他分的
                  类居然是个『东城水果批发』，但**我们的身份显示的居然是货主**，这肯定是错的 —— 他应该分到
                  **货主**那里去，不是批发商。**自动分类是要有的**。」
② 当前流程是什么？ `users.category` 原来由**人挑**：建号 `users.py:184` 直接写 `body.category`，
                  更新 `users.py:423-427` 也允许派单员改 ⇒ 分类可以与身份**不一致**（这正是那个账号的由来：
                  分类=批发商、role=SHIPPER、is_member=0），而四个名册页左侧那一列是**按分类**分组的，
                  所以一筛就把身份是货主的人筛进了批发商。
③ 哪个现有事实会变？`users.category` 的**来源**：从"人填的字符串"变成"身份的投影"；
                  `PATCH /users` 的 `category` 字段从此**不再写库**（忽略，不报错）。
④ 哪些明确不能变？ ① 六个分类**名字与顺序**（派单员/货主/批发商/小车司机/大车司机/挂车司机，`user_categories`
                  名册与 CHG-0112 的两级结构都不动）；② 司机的车型代码 `small/large/trailer` 与其"认不出当大车"
                  的老口径；③ 钱/订单/账本的一切算法；④ `is_member` 的语义（身份，不是分类）。
⑤ 属于哪一层？    业务规则（L1 局部行为）＋ 一次历史数据纠正。
⑥ 什么证据能证明完成？ 单测 8 例 + 判据 `_check_auto_user_category.py` 5 项 + 生产库回填后的逐行输出
                  （分类与身份一致）+ 建号/改身份后分类自动跟着变。
```

## ② Must Change / Must Not Change

```text
Must Change:      新增 backend/app/services/user_category.py（auto_category 唯一实现）；
                  users.py 建号与更新两处改走它；新增 _tools/ops/_fix_user_categories.py 回填；
                  生产库按同规则一次性纠正。
Must Not Change:  六个分类名与名册顺序、user_categories 两级结构（CHG-0112）、车型代码口径、
                  金额与订单/账本算法、is_member 的语义。
```

## ③ Boundary

分类 = 身份的投影：`role` + `is_member` + `vehicle_type` ⇒ 六个固定分类之一（唯一实现）。

## ④ Behavior Contract

| 身份 | 分类 |
|---|---|
| `DISPATCHER` | 派单员 |
| `SHIPPER` 且非高级货主 | 货主 |
| `SHIPPER` 且 `is_member=True` | 批发商 |
| `DRIVER` + `small` / `large` / `trailer` | 小车司机 / 大车司机 / 挂车司机 |
| 认不出的角色 | 货主（老口径）｜认不出的车型 ⇒ 大车司机（老口径） |

改身份（角色/会员/车型）之后，分类**下一次写库时自动跟着变**；`PATCH /users` 里带 `category` 不再生效。

## ⑤ Data Contract

`users.category` 仍是 `VARCHAR(32)`（不改结构）；回填**只改值**，规则与 `auto_category` 一字不差。

## ⑥ CHG 专章

### Before：分类可被手填 ⇒ 与身份不一致（用户看到的"批发商里混进货主"）。
### After：分类由身份推出 ⇒ 两者不可能不一致；四个名册页左侧那一列分组因此永远与身份一致。
### Must Preserve：六个分类名与顺序、两级结构、车型口径、钱的一切算法。
### Blast Radius：**L1**（写路径 + 一次数据回填）。
