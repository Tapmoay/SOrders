# FEAT-0011 · 经营利润表：把已经算得出来的四块钱汇成一张「这月赚了多少」

> **本事项回答的是老板五问里的第 1 问**：「这月赚了多少（营业额 − 成本 = 利润）」。
> 它**只汇合、不新增事实**：四块钱（营业额 / 商品成本 / 司机应得 / 开销）各自都已经有唯一实现，
> 本事项把它们按**同一个时间窗口**放进同一张表，并如实标出「哪一块今天是 0、为什么是 0」。

① **「这月赚了多少」今天没有一个地方答得出来。** 系统能算「商品毛利」（`/reports/turnover`）、「司机应得」（`/freight-settlement`、`/reports/turnover` 的 total_freight）、「开销」（`expenses`＋收支页的分类小计），但**从来没有一处把它们按同一个窗口相减**。
   本机实测（2026-10-04，`backend/sorders.db`）：把三页数字手工拼起来是 商品毛利 16,707.70 − 司机应得 13,537.00 − 开销 36,001.00 = **−32,830.30**（≈ 营业额的 −43%），而**没有任何一页承认这个数是"利润"**，也没人知道它算得对不对。
② **用户是老板 / 派单员**：报表中心六页（营业纵览 / 商品经营 / 司机绩效 / 客户经营 / 资金收支 / 异常与审计，入口 `android/.../ui/dispatcher/ReportHome.kt:30-35`）逐页看，每页各自成立；要判断"这个月到底挣没挣钱"，得自己抄三个数、还要记住三页的时间口径是不是同一段。
③ **没有事实会变**：`ledgers` / `cash_flows` / `expenses` / `driver_bills` / `orders` **一行都不写、不改**。变化的是**一处新的只读口径**（营业利润）与它的三个对外面：新端点 `GET /api/v1/reports/profit`、报表中心第 7 页「经营利润」、导出第 7 个 kind `profit`。
④ **不能变化**：既有的四个金额口径一个字节都不许动 —— 营业额 = `order_money.receivable`（`services/order_money.py`）、商品成本 = `cost_basis`（入库加权平均进货价，三级兜底）、司机应得 = `driver_pay.pay_for_order`、开销 = `expenses` 按 `exp_date` 落窗口；既有六页报表的数字与字段、既有导出的六个 kind 与文件名、既有权限点，全部不变（见 ② 的 Must Not Change 与 ⑥ 的 Must Preserve）。
⑤ **EXTENSION IMPL（只读查询）+ PRESENTATION（Android 页）**：新文件落在 `backend/app/services/reports/profit_query.py` —— `services/reports/**` 由 `_tools/qa/_check_report_boundary.py` 按 glob 自动收，**AST 层面禁止落库写法与写服务依赖**；Core 侧（`order_money.py` / `cost_basis.py` / `driver_pay.py` / `money_contract.py`）**只被 import，一个字符都不改**。

## ④ Behavior Contract

```text
Input          GET /api/v1/reports/profit?mode=day|week|month&date=YYYY-MM-DD[&date_from=&date_to=]
               —— 窗口语义与 /reports/turnover 完全同源：`_span(mode, anchor, date_from, date_to)`（reports_service 转出）
Output         ProfitReportOut：
               收入侧  revenue_total（营业额 = 应收）/ revenue_covered（参与毛利的收入）/ revenue_uncovered（没成本数据、因此不进毛利的那部分收入）
               成本侧  cost_total（只含参与毛利行的成本）+ 覆盖率四项 total_lines / covered_lines / cost_avg_lines / cost_snapshot_lines
               利润六级 revenue_total → cost_total → gross_profit → delivery_cost → operating_expense_total → tax_total → operating_profit
               费用明细 operating_expenses[{category, amount}]（按分类降序）
               资金侧  collected / arrears_total / cancelled_orders / damage_qty / damage_amount
               说明    notes[]：逐字写清"哪些数今天是 0、为什么是 0"（税、折旧）与"未覆盖收入不进毛利"
Success        恒等式在本表内**精确成立**（判据与 pytest 都钉）：
               ① revenue_total == turnover.total_amount（同一 span，两处必须逐分相同）
               ② revenue_covered + revenue_uncovered == revenue_total
               ③ gross_profit == revenue_covered − cost_total
               ④ operating_profit == gross_profit − delivery_cost − operating_expense_total − tax_total
               ⑤ delivery_cost == turnover.total_freight（司机应得，同一 span）
               ⑥ Σ operating_expenses[].amount == 区间内 expenses 合计
Failure        窗口参数非法（只给一头 / 顺序颠倒 / mode 不在枚举内）→ 400，且**不产生任何半成品**（只读端点没有副作用）；
               权限不足 → 403；无数据 → 全 0 与空列表，⛔ 不报 500、不拿"上一段"的数顶替
Boundary Cases 空窗口（区间内没有已送达单）；有单但一行成本都没有（覆盖率 0%，毛利 0）；有开销无订单（利润为负）；
               整月/跨月标签；区间跨月跨年；货损既有 expense 行又有 damage_amount（⛔ 不许重复扣）
Side Effects   无（只读：不写库、不发通知、不产出导出任务）
Authorization  沿用 Permission.ORDER_DISPATCH（与 /reports/turnover、/reports/export 同一权限点，⛔ 不新建）
Compatibility  Compatible —— 纯新增端点/响应模型/页面/导出 kind；既有调用方一行不用改
```

## ⑤ Data Contract

- **新增/改动哪些字段**：**不新增任何库表或库列**。新增的是对外响应模型 `ProfitReportOut`（`backend/app/schemas/reports.py`）与它的组成项 `ProfitExpenseItem`。
- **Owner 是谁**：本事项**不拥有任何事实**（无写入）。它读的每一格都归既有 Owner：营业额归 `services/order_money.py`、成本归 `services/cost_basis.py`、司机应得归 `services/driver_pay.py`、开销归 `models/expense.py`（写入口是开销单接口）。
- **什么时候写 / 什么时候不写**：**任何时刻都不写** —— `services/reports/**` 由 `_check_report_boundary.py` 在 AST 层面禁止落库与写服务依赖（新增文件自动被这个 glob 收）。
- **是否允许 NULL**：不适用（响应里的金额一律 `Decimal`，缺数据就是 `0`，并在 `notes[]` 里说明为什么是 0）。
- **历史数据怎么办**：**不回溯、不重算、不迁移**。利润表按窗口现算，历史窗口重算出来的数就是那个窗口按当时事实应有的数；⛔ 不许给历史补任何"推算出来的成本或税"。
  ⛔ 过去没有 provenance 就写 `NULL / unknown`，**不许**按现在的规则猜过去 —— 本表对"没有成本数据的收入"正是这么做的：单列 `revenue_uncovered` 并说明它**不进毛利**，而不是按 0 成本或按平均成本替它猜一个。
- **迁移怎么做 / Rollback 怎么办**：无迁移（无 schema 变更）。Rollback = 回滚这一笔提交：端点、页面、导出 kind、AI 目录条目一起消失，库里任何一个字节都不用还原。
- **删除本功能后历史数据还能不能解释**：能 —— 本功能不产生任何历史事实，删掉之后账本/结算/库存/派单的解释链条与今天完全一致。
