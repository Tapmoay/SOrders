① 这一页现在是「一件商品一张卡 + 卡里展开一大片编辑器」：默认价和每个人的价都藏在**卡内展开区**里。用户只想改一个默认价，也得先点开、改完再收起；人一多整页被撑得很长，「默认」和「这个人」要靠读小字分辨。用户看样张时挑的甲，就是把这件事摊平：**默认价在卡片上直接改，单人价进抽屉、一人一行**。

② 批发商（货主）自己用：打开「下游定价」→ 看得见自己能定价的商品 → 给全部下游一个默认价，或给某个人单独一个价 → 保存。改的是"**以后**下的单按哪个价算"：后端按 `order_products.shipper_unit_price` 快照，改价删价都**不追改已下的单**。入口：`ui/nav/Modules.kt:278` 的 ModuleEntry("下游定价") → `Routes.SHIPPER_PRICES`（`ui/nav/NavGraph.kt:285`），双闸门 = 批发商 + `downstream_ledger_enabled`（`ui/nav/ModuleVisibility.kt:52`）。

③ 只有表现：默认价的输入框从"卡内展开区"搬到"卡片上直接改"；单人定价从"同一片展开区里一长串"搬进底部抽屉（一人一行，行序 = 联系人表顺序）；抽屉顶上多两档「在用 / 回收站」；按人行上逐字写「删除这条价」。数据 / 接口 / 权限一个字不动：还是 `/api/v1/shipper-prices` 那一套（`/api/v1/shipper-prices/products` 取可定价商品，POST 建/改，DELETE 软删），还是 `include_deleted=true` 才看得到回收站。

④ 不能变的六条：① 写的人永远是登录人自己（请求体里没有 `shipper_id`）；② 改价删价**不追改历史订单**；③ 删是**软删**，回收站里能恢复；④ 后端错误文案原样透传（不自己编号）；⑤ 这一页跟派单员那条 `price_rules`（批发商专属价 `special_unit_price`）**是两回事**，本单一个字节都不碰 `price_rules.*`；⑥ 两条既有静检红只能"改绿"，**不许放宽判据**（本单只追加新判据 + 一条写明理由的窄例外，见 ⑧）。

⑤ Presentation 为主（`ui/shipper/ShipperPricesScreen.kt` + 新纯逻辑文件 `ui/shipper/DownstreamPriceCards.kt`），Extension 只有 ViewModel 里的接线（草稿键按"商品 + 人"算，同一件商品上每个人的草稿互不串）。Core 不碰。

⑥ 五条证据：① 判据 `_tools/qa/_check_downstream_price_cards.py` 全绿（清单全部现算，不手写文件表）；② 反向验证 `_tools/qa/_reverse_verify_downstream_price_cards.py` 8/8 被抓住；③ 单测 `DownstreamPriceCardsTest` 跟着 `:app:testEmuDebugUnitTest` 一起绿；④ 顺手修的两条旧红变绿（`_check_input_rules.py` / `_check_sheet_form_pages.py`）；⑤ 主会话真机回归。

## ④ Behavior Contract

```text
Input          用户在这一页上的三种动作：① 在商品卡上改「全部下游的默认价」并保存；② 点「定价」进抽屉，
               给某一个人单独定价并保存；③ 在抽屉里删掉某一条价（含二次确认）或从回收站恢复一条。
Output         保存后：卡上大字价与那行人的价都会跟着刷新（refreshAfterWrite 重新拉这一件商品的价）；
               删/恢复后：抽屉那一行改挂"已删除"或"未设"，卡上「按人定价 · N 人」跟着变。
Success        保存成功 → 底部一条 actionResult 提示，逐字带商品名 + 是给谁的 + 金额；草稿格子清空。
Failure        ① 空输入 → 「先填一个单价」；② 金额 <= 0 → 「单价要大于 0 元」；③ 后端拒绝 →
               后端原话原样显示（toApiException(e).message），一个字都不改写。
Boundary Cases 联系人表为空；这个人从没单独定过价（price = null，显示「未设」，他实际按默认价算）；
               人价与默认价都没设（卡上显示「未设」）；软删那条（在用那一档不挂在人身上、回收站那一档挂回去）；
               后端还回了"联系人表里已经没有的那个人"的价（无主价排在最后，不显示成无主，也不许悄悄消失）；
               联系人名字与电话都空 → 「联系人 N」兜底名。
Side Effects   只写后端这一处：POST/DELETE /api/v1/shipper-prices（含 include_deleted 读）。本地只改内存里的
               状态（products / prices / 草稿表），不落盘、不发通知、不动订单。
Authorization  仍旧双闸门：登录人是批发商 + downstream_ledger_enabled；非批发商看到的是 PriceGateCard（文案逐字
               抄后端 403），一个输入框都不给。这一页**没有**任何"替别人改价"的入口：请求体里没有 shipper_id。
Compatibility  老版本 App 与后端接口完全兼容（没有新字段、没有新端点）；同一账号换设备看到的排法一致，
               因为排法只依赖后端回的价与联系人表。
```

## ⑥ CHG 专章（FEAT / GOV 不适用时写「不适用：<理由>」）

（本节按 CHG 类型填；FEAT / GOV 的专属章节见各自小节说明。）

### Before

- 一份卡的展开区里同时塞着**默认价**与**所有人的价**（`PriceEditor`）：标题「给不同的人不同的价」，下面第一行是
  「全部下游的默认价」，之后是联系人表里每一个人一行，底部还有「显示已删除的价（回收站）」这类切换；
  人一多，用户要在一长条里找"哪一行是默认、哪一行是我要改的人"。
- 卡上那颗按钮写「定价 / 收起」，语义是"展开 / 收起"，不是"给谁定价"。
- 删除按钮写「删除」，用眼睛分不出删的是这一件商品的默认价还是某个人的价。
- 同文件外，成本价弹层里那个「口径名称」框被判成金额框（举例文案里带「成本」两个字）、
  抽屉体缺 `fillMaxHeight(`，两条静检红一直挂着。

### After

- 商品列表页：一件商品一张卡 `DownstreamPriceCard` —— 卡上**直接**一行「全部下游的默认价」+ 输入框 + 保存
  （`DownstreamPriceInput`，输入框 `SoTextField` 52dp、保存键 `Modifier.height(52.dp)` 焦糖底色）；
  卡上那颗按钮改成「定价」，点它才开底部抽屉 `DownstreamPersonSheet`。
- 抽屉里：顶上两档 `SegmentedPicker`「在用 · N 人」/「回收站 · M 条」；下面**一人一行**
  `PersonPriceRow`（行序 = 联系人表顺序，保存完行不跳走）：姓名 + 电话 + 他现在的价 / 「未设」+
  输入框 + 保存；右边逐字「删除这条价」（软删那条在这一档里显示金额 + 「恢复」）。
- 数额一律走 `formatMoney` 漏斗；钱的颜色统一 `MoneyOrange`；卡与抽屉走 `SectionCard`（圆角 16dp，全 App 一处说了算）。
- 顺手：`ProductCostPriceSheet.kt` 抽屉体补 `fillMaxHeight(`（旧红转绿）；该弹层「口径名称」框在旧判据里
  记一条**写明理由**的窄例外（自由文本名字框，套金额过滤会把中文名字在输入层吃掉；同弹层真正的金额框
  仍走 `InputRules.priceInput`，没有放开任何金额门）。

### Must Preserve

- 接口 / 端点 / 请求体 / 权限（批发商 + 开关双闸门、无 shipper_id）。
- 「一个人只认一条价」「软删不算价」「历史订单不追改」三条不变量。
