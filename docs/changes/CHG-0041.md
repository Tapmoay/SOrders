## ⑥ CHG 专章

### Before

派单员在订单详情页看到收货信息卡与商品明细卡：**全是只读文本**，没有「改」字、点行没有任何反应。要改这张单只能：回派单池 → 切到「已完成派单」→ 找到这张单 → 打开池里的改单抽屉（CHG-0040 那一档）。另外这一页**没有 SnackbarHost / 横幅**，所以 `vm.actionResult` 之前设了也没人显示（历史上任何在本页触发的动作结果都是"静默"的）。

### After

同一页：
- 收货地址行、收货人行、下单人行、备注行各自行尾一颗「改」；点进去**原地**变成输入框（地址/备注多行），下面一行「取消 / 保存收货信息」。
- 商品明细标题下多一句「点某一行可以改数量与单价」；点某一行 → 该行原地变成「数量 / 单价（元）」两个输入框 + 左「删掉这件货」右「取消 / 保存」；列表末尾一颗「加一件货」（弹既有 `ProductPickerSheet`，按这单货主的专属价报价）。
- 保存成功后页面顶部出现一条绿色横幅「已经改好，司机那边会收到一条消息」（4 秒后自动消失）。
- 货主/司机（非派单员）或终态订单：**一个「改」都不画**，页面与改动前完全一致。

### Must Preserve

```text
- 历史订单 / 历史金额 / 已冻结的 Pricing Fact
- 历史 Provenance / Audit / Ledger
- 权限（只有派单员能改；后端仍兜底）
- API compatibility（端点、请求体、响应字段一字不改）
- 司机端金额判据（_tools/qa/_check_driver_money.py）与货主可见状态口径（CHG-0039 shipper_status_hold）
- 改单只通知司机、货主端静默（CHG-0040 口径）
```

### Blast Radius（L0～L3）

**L1（局部行为）**：改的是"订单详情页这一屏的交互"，写库走既有端点；没有结构变更（无迁移）、没有新端点、没有权限变化，因此不是 L2/L3。之所以不是 L0：它确实让用户能**改写订单事实**（六个字段与商品行数量/单价），只是这条路以前也有、只是不在这一屏。
