① 派单员（以及货主 / 批发商）手上常常只有**一个名字、没有电话**的联系人（工地上的人、只报名的收货人）。
「新建联系人」这个入口有**两扇门**：人工的弹层 / 抽屉，和 AI 动作「记一个联系人」(`contact.upsert`)。
CHG-0010 已经按需求方口径把**人工那扇门**放开了（手机号选填、姓名与手机号至少填一个、没填存 NULL），
**AI 这扇门还写着必填** —— 字段规格 `required = true`、提示词也写着「按手机号记一个联系人」。
模型手上只有名字时因此只有两条路：拒绝执行，或者**编一个假号**。假号是假事实：既污染档案，
又会顶掉 `(shipper_id, phone)` 唯一约束 —— 正是 CHG-0010 要治的那个病。

② 现在的链路：AI 面板 → 模型按动作目录里的字段规格收集参数（规格里的 `required` 决定「卡片提交前必须有值」）
→ `AiWriteService.preview` 出确认卡（标题 / 明细）→ 用户点确认 → `AiWriteDataSource.createContact(fields)`
→ `POST /shipper/contacts` → 后端 upsert。改动前：规格要号 ⇒ 模型被推着要号；
落点用 `fields.req("phone")` ⇒ 就算卡片那条路被绕过，只给姓名也会在 `req` 上当场抛错。

③ 三件事变：
  · **入参规格**：`phone` 由必填改选填；`name` 仍必填 ⇒ 天然满足「姓名与手机号至少填一个」，
    同时保住 crud 的「空卡不许提交」守卫（`AiWriteCrudHandlers.kt:71-75`）；
  · **提示词与卡片**：blurb 明说「手机号可以不填，只填姓名也能记」；标题不再留空尾巴，
    明细里不再出现光秃秃的一行「手机号：」；
  · **落点取参**：`fields.str("phone").orEmpty()`，不再 `req("phone")`。

④ 不能变：
  · 后端 upsert 的口径（CHG-0010 已实现：至少填一个才 400、空号写 NULL 不写空串、按「同名且也没号」认人）；
  · DTO 形状 `ContactCreateRequest(phone, display_name, category)`；
  · 姓名必填（放开它 = 允许一张什么都不填的空卡）；
  · 「同一个手机号已经有了就更新他的名字」这句同号即同人的语义；
  · 人工那两扇门（下单页弹层 + 地址与联系人抽屉）的一切现状（判据第 12 节钉着）。

⑤ **Presentation**：改的是 AI 动作目录里的字段规格、卡片文案与客户端落点的取参方式，
没有引入任何新事实、新契约或新存储；后端与库一个字没动。

## ⑥ CHG 专章

### Before

- 对 AI 说「记一个联系人，叫工地老李」→ 卡片上「手机号」是必填那一格，模型会回头追问号码，或者自己编一个。
- 提示词写着「按手机号记一个联系人。同一个手机号已经有了就更新他的名字，不会重复。」—— 通篇只谈号码。
- 落点 `phone = fields.req("phone")`：只说了名字的那条路会在 `req` 上抛错。

### After

- 字段规格：`textField("phone", "手机号", "选填；填了就按号认人（同一个号会更新他原来的名字）", maxChars = 20)`
  （**没有** `required = true`）；姓名那一栏仍是 `required = true` ⇒ 天然满足「至少填一个」，
  同时保住 crud 的空卡守卫。
- 提示词：「记一个联系人。**同一个手机号已经有了就更新他的名字**；手机号可以不填，只填姓名也能记。」
- 卡片：标题 `"记联系人：" + listOf(display_name, phone).filter { !it.isNullOrBlank() }.joinToString(" ")` ⇒
  没号时是「记联系人：工地老李」，不留空尾巴；明细用 `c.str("phone")?.takeIf { it.isNotBlank() }?.let { "手机号：$it" }`
  ⇒ 没号时那一行整条不出现（⛔ 不许用 `c.line("phone", …)`，它只判「键在不在」，空串会渲染出光秃秃的「手机号：」）。
- 落点：`phone = fields.str("phone").orEmpty()` ⇒ 只报名字也能走通，空号交给后端写 NULL。
- 两处各留一句防回归注释（`AiWriteBasicData.kt:129-132`、`AiWriteDataSource.kt:1090-1091`）。

### Must Preserve

```text
- 后端 upsert 口径与会话历史（订单 / 金额 / 账本 / 审计一个字没动）
- 权限与审计动作码
- API compatibility（ContactCreateRequest 形状不变）
- 同号唯一与同号即同人
- 人工两扇门的一切现状（判据第 12 节 12a-12e）
- 历史联系人数据（不回填、不猜测、不改内容）
```
