① 第 4 轮测试（方向 B · 金额口径连锁普查，台账 **TB-14**）实测：客户用**滚动收款**（不绑订单）付了 124 —— `/cash-flows/summary` 的收入从 323 变 199、撤销又回到 323，钱确实进账了；但**欠款表一分不冲**：`totals.balance` 与那一行的 `balance` 一动不动、`prepaid` 恒 0。后果是**催收名单上还是全款**，客户明明付过钱会被再催一次（设计文档 `docs/ACCOUNTING_V2_DESIGN.md` 那句「rolling（可选）：冲抵该客户应收余额」与枚举 `CashFlowBizType.RECEIPT_PREPAID`（`backend/app/models/enums.py:396`）本来就是为这件事准备的，但全仓没有写入点）。
② 用户动作：账本 → 客户收款 → 选「滚动收款」（不勾订单）→ 收钱；之后去「报表 → 客户欠款/催收」看这个客户还欠多少。
③ 只变**一个读数**：客户欠款表里那一行的 `balance` 与 `prepaid` 两个数（欠款减少、预收增加），以及 `totals` 的对应合计。
④ 不变量：① 每一张**订单**的应收/已收/欠款（`order_money`）一个字节不改；② 现金流水、收款记录、营业额 `collected`、挂账汇总（按单）都不改；③ 恒等式 `balance == Σ buckets − prepaid` 必须继续成立（账龄桶仍是"欠久了多少"，不拿预收去抵桶）；④ 不动表结构、不加列、不改接口字段（`prepaid` 本来就在出参里）；⑤ 撤销过的收款不许再冲（软删要认）。
⑤ Extension（报表读数的一处口径修正），但它落在"钱"上 ⇒ 按 L2 走正式变更审查：判据 + 反验 + 两个单测 + 红证。
⑥ 判据 `_tools/finance/_check_rolling_receipt_prepaid.py` 18 项全过、且在**改前源码**（`_tmp/wt_final`）上跑 6 条不成立；反向验证 `_tools/finance/_reverse_verify_rolling_receipt_prepaid.py` 7/7 全红且逐字节还原；单测 `backend/tests/test_rolling_receipt_prepaid.py` 2 passed（收 124 → 欠款少 124、预收多 124；撤销 → 原样回去；别的债务人的行不动）。

**最后一个问题**（规范 §三十五 / §三十六）：这条缺陷活下来的原因，是**钱有两条入口**（绑单的逐单核销 / 不绑单的滚动收款），而"应收"只认其中一条。
判据现在钉住的是「凡是从客户手里收进来的钱，都要在"这个客户还欠多少"这个数上留痕」——以后再加收款方式，先问它进不进这个读数。
