# 消息卡片设计规范（消息中心 / FEAT-0019）

> **这份文档解决什么问题**：消息中心的消息类型会一直加（订单、库存、钱、发票、账号、车辆……）。
> 每加一类，都要回答同样四个问题：**竖条用什么颜色、风险算哪一档、哪几个字该上色、点进去到哪。**
> 这份规范把四个问题一次说清 —— 照它做，界面自然统一；不照它做，判据会红（`_tools/qa/_check_message_card_grading.py`）。
>
> 用户 2026-10-11 拍板的原话（两条口径的来源）：
> 「**我们的信息要按不同的类型做颜色的区别**……方案 A 就可以了（最左边一条比较粗的竖杠）」
> 「**文字不能全部用颜色去搞**……真正的重心是『库存不足』和还剩多少的个数……其他的文字你用正常的黑色。
> 你要记住一点：**全是重点就是没有重点**。」

---

## 一、两条**正交**的规则（别混在一起）

| | 管什么 | 用什么定 | 作用范围 |
|---|---|---|---|
| **① 类型色** | 这是**哪一类**消息 | 消息类型 → 工作台对应那一格的模块色 | 卡片**最左边 6px 方角竖条** + 同色小标签 |
| **② 风险色** | 这条消息**有多要紧** | `severity`：`danger` / `warn` / `info` | 正文里**被点名的**关键词与数字的**字色**（其余正常黑） |

⛔ 两个维度互不替代：库存预警可以"类型=库存色、风险=危险"；也可以是"类型=库存色、风险=提醒"。
⛔ **风险色只落在被点名的片段上**，不许整行/整段上色 —— 这是用户明确否掉过的做法。

## 二、类型 → 竖条色（取工作台那一格）

颜色的**唯一来源**是工作台模块色（定义在 `android/app/src/main/java/com/tapmoay/sorders/ui/nav/Modules.kt` 的
`ModuleEntry(..., color = 0x…)`）。规则：**这条消息属于哪个功能，就借哪一格的色** —— 用户认的就是那套对应关系。

| 消息类型 | 借哪一格 | 色值 |
|---|---|---|
| 订单：新单 / 已接单 / 改单 | 派单作业·订单 | `#1E6FFF` |
| 订单：已送达 | 送达（绿） | `#00B578` |
| 订单：被撤销 / 被删除 | 订单管理 | `#917A16` |
| 库存：不足 / 偏低 | 库存管理 | `#008EAB` |
| 钱：客户收款 / 欠款 | 客户收款 | `#9C88E0` |
| 钱：供应商应付 | 供应商/应付 | `#E05288` |
| 发票 | 发票台账 | `#E08034` |
| 价格调整 | 商品管理 / 下游定价 | `#B65DC4` |
| 车辆（年检 / 保险） | 车辆管理 | `#00AAAE` |
| 账号（登录 / 停用 / 解冻） | 账户管理 | `#AC7217` |
| 系统公告、其它 | 消息中心 | `#E07B80` |

⛔ **不要自己调新颜色**（同一类消息在不同页面颜色不一致，用户会以为是两件事）；
⛔ 新类型若确实找不到对应模块 ⇒ 用消息中心的 `#E07B80`，并在变更单里写清为什么。

## 三、风险档怎么定（`severity`）

| 档 | 什么时候用 | 字色 | 例子 |
|---|---|---|---|
| `danger` | **已经出事或马上出事**，不改会亏钱/停业 | `#D93025`（红） | 库存不足（低于报警阈值）、挂账超额度、应付**已逾期**、账号在新设备登录 |
| `warn` | **还没出事，但需要你处理** | `#E07B00`（橙） | 库存偏低、应付**将到期**、订单被撤销、车辆**年检提醒** |
| `info` | 只是**告知**，不需要动作 | 不上色（正常深色） | 已接单、已送达、收款到账、发票已开具、系统公告 |

⛔ 判据只认这三档；**新增档位要先改这份文档与判据**（不许随手写 `critical` 之类）。
⛔ 同一类消息的风险档应当**由数据判**（低于阈值=danger、低于建议水位=warn），不是由文案判。

## 四、哪几个字上色（`payload.emphasis`）

**由发消息那一侧点名**（后端在通知的 `payload` 里给出），客户端**只负责上色、不猜**：

```json
{ "severity": "danger", "emphasis": ["库存不足", "8"] }
```

点名规则（用一句话记：**点"结论词"和"数字"**）：

| 该点 | 不该点 |
|---|---|
| 结论词：库存不足 / 已超额度 / 已逾期 / 新设备登录 | 整句话、整段正文 |
| 关键数字：数量（8 筐）、金额（12,800.00）、天数（3 天）、单号 | 日期时间的"年月日"、助词、单位 |
| 一条最多 **2 个词 + 2 个数字** | 超过 4 个片段（那等于整行） |

- `emphasis` 里的片段**必须在正文里原样出现**（含空格与全角）；找不到就不标，⛔ **不许退化成整行上色**；
- 没有重点词的消息（公告、到账通知）⇒ `emphasis: []`，正文保持正常色；
- **已读**：竖条、彩标、高亮**全部去掉**，整条灰调 —— 与未读一眼分开。

## 五、点进去到哪（深链）

能查的消息要给入口（用户原话：「像是个入口一样」）。目标**从 `payload` 取**，权威是
`backend/app/services/message_center.py` 里各 `type` 分支写了什么键：

| 消息 | payload 里放什么 | 点进去 |
|---|---|---|
| 订单类 | `order_id` / `order_no` | 订单详情（撤销原因、送达信息都在那） |
| 库存类 | `product_id` | 库存管理，并**定位到那个商品**、显示当前库存 |
| 收款 | `receipt_id` / `customer_id` | 账本 · 客户收款（那一笔） |
| 应付 | `payable_id` / `supplier_id` | 供应商应付款 |
| 发票 | `invoice_id` | 发票台账（那张票） |
| 账号 / 设备 | `user_id` | 账户管理（看绑定设备、解冻） |
| 纯公告、提醒 | 无 | **不给入口**（⛔ 不要给一个点了没用的箭头） |

⛔ `payload` 里没有对应键时**不许瞎跳**（宁可不给入口）；判据会钉这条。

## 六、加一类新消息：照这个清单走

```text
1. 定类型名：`<域>.<动作>`（如 inventory.low、payable.overdue），写进发消息那一处；
2. 选竖条色：按 §二 借工作台那一格的色（找不到就用消息中心色并写理由）；
3. 定风险档：按 §三 问一句"不改会不会出事" —— 会=danger、要做但没出事=warn、只是告知=info；
4. 点重点词：按 §四 在 payload 里写 emphasis（结论词 + 数字，最多 2+2）；
5. 给深链：按 §五 在 payload 里放目标 id（没有就不给入口）；
6. 补证据：单测（类型→色、severity→色、payload→路由）+ 判据（`_check_message_card_grading.py`）能覆盖到；
7. 真机看一眼：`python _tools/qa/_install_all.py --only 5554`（或真机 `adb install -r`）后打开消息中心，
   确认三件事 —— 竖条颜色对、只有点名的字上色、点进去落到正确页面。
```

## 七、反面例子（都真的发生过）

| ❌ 做法 | 后果 |
|---|---|
| 整行/整段上色 | 用户原话：「**全是重点就是没有重点**」——眼睛没有落点 |
| 同一类消息在两处用不同颜色 | 用户以为是两件事 |
| 已读还带颜色/高亮 | 未读与已读分不开，未读数就失去意义 |
| 没有 payload 也画一个箭头 | 点了没反应，比没有入口更糟 |
| 客户端自己"猜"哪几个字重要 | 文案一改就标错，且两端口径会漂 |

## 八、实现落点（改代码时看这里）

| 事 | 在哪 |
|---|---|
| 发消息（类型 / 风险 / payload.emphasis） | `backend/app/services/message_center.py`（**判定只有这一处**） |
| 出参带 `severity` | `backend/app/schemas/…` 的 `NotificationOut` |
| 卡片渲染（竖条 / 类型色 / 上色） | `android/app/src/main/java/com/tapmoay/sorders/ui/messages/` |
| 类型 → 颜色映射 | 同上目录下（**唯一一处**，判据钉"只有一处"） |
| payload → 路由 | 同上目录（缺键返回 null，不跳） |
| 判据 / 反验 | `_tools/qa/_check_message_card_grading.py` + `_reverse_verify_message_card_grading.py`（后端侧另有 `_check_notification_severity.py`） |
| 可视化样本（改样式前先在这里给用户看） | `_tmp/palette_demo/messages_all.html`（各类总表）、`messages.html`（单类细节） |
